# 言葉のルール

画面の言葉・子ども向けの言い換え・コードの名前を1つの表にそろえます。人も AI も、新しい画面やコードを書くときはこの表に従います。表にない言葉が必要になったら、先にこの表に足します（AI 向けの短い版は `.claude/rules/domain.md`）。

## 1-2. 段の呼び名と、画面の決まった言葉

画面の作り直し（いまやることは1画面に1つ・やわらかい話し言葉・子どもと一緒に使える）で、画面に出るようになった言葉です。決まった言葉は `config/suiri.php` の `ui` と、各画面のかたまりに置きます（部品の見本は `ui-kit.md`）。

| 画面の言葉 | 子ども向け | 意味 | コードの名前（config／部品） |
|---|---|---|---|
| なぞ → 見たこと → どうして？ → もしそうなら → 答え合わせ | 同じ | 事件の段の呼び名（進み具合の丸・一覧の小さな印）。見たこと＝手がかり、どうして？＝見立て、もしそうなら＝予想。設計書の言葉は初めて出る所で一言説明する（「見立て＝『どうしてだろう？』の答えの案」） | `case_list.steps`／`<x-ui.progress>` |
| いまやること | 同じ | その画面でいちばんすべきこと。問い・例・入力欄・主なボタンを1枚のカードにまとめて出す | `<x-ui.step-card>` |
| ステップ 2 / 5・いまここ・済み | 同じ | 事件の段の進み具合（いま何段目か） | `ui.step`・`ui.now`・`ui.done`／`<x-ui.progress>` |
| あとでできること | 同じ | まだ先のこと。いまやることのカードの下に小さく1行 | `ui.later`／`step-card` の `later` |
| これでOK | 同じ | 1問ごとに書いたものを保存するボタン。押したら「保存したよ」と返す | 各画面のかたまりの `save`（`case_partner.write.save` など） |
| 確かめた（はんこ） | 同じ | 答え合わせが済んだ印。丸いはんこの中に結果（当たり・外れ・どちらとも言えない・前提が崩れた。子ども向けは あたり・はずれ・わからない・そもそもちがった） | `ui.stamp_top`／`<x-ui.stamp>` |
| 事件 No.12 | 同じ | 事件の番号（URL の番号と同じ）。一覧の1件・上の帯・答え合わせの「もどる」に出す | `case_board.page_title`・`case_list.case_no`・`resolve.back`／`case_files.id` |
| No.3（荷札） | 同じ | 手がかりの札の番号（その事件の中の順番） | `ui.tag_no`／`<x-ui.evidence-tag>` |
| 提案のチップ（書き出し・ほかの説明の型・候補） | 同じ | 押すと入力欄に書き出しが入るボタン（上の「提案・書き出し」。保存は本人） | `suggest.captions`／`<x-case.suggest-chips>` |
| 今日・明日・いつか（1行で書く欄のボタン） | 同じ | きょうの画面でやることを1行で書いて、押すとその日で作るボタン（今日の日付・明日の日付・日にちなし）。日にちや時間も決めたいときは「くわしく」 | `tasks.quick`／`<x-task.quick-add>` |
| 前からのやり残し | 同じ | 期日を過ぎた、まだ済んでいないやること。きょうの予定とやることの上に、赤でもとの期日を付けて出す | `today.agenda.overdue`／`<x-today.agenda>` の `overdue` |
| これから・いつか・済み | 同じ | きょうの画面のたたんだ枠の名前。これから＝明日から先のやること（日付ごと）、いつか＝日にちを決めていないやること、済み＝この7日に済んだこと | `today.later`／`<x-today.later-tasks>`・`<x-today.fold>` |
| 直す・気になる・消す（やることの行） | 同じ | やることの行を押すと、その場で開いて出る操作。消すときは「消すと、もとに戻せないよ。消していい？」と確かめる | `tasks.row`・`today.curious`／`<x-task.item>` |
| ◯◯にスマホを渡してね・受け取った！はじめる | 同じ | 相棒モードで、次に書く人へ1台のスマホを渡す画面（見せ合うまで、相手の見立ては見ない） | `ui.handoff_title`・`ui.handoff_button`／`<x-ui.handoff>` |

## 1-3. ChatGPT・Claude とつなぐ（読むだけの窓口）

アプリの中では AI を使いません。利用者が自分の ChatGPT・Claude から、推理手帳の記録を**読むだけ**の窓口でつなげます（要件定義書の 4-11）。画面では「窓口」「MCP」という言葉は出さず「ChatGPT・Claude とつなぐ」で通します（説明書だけ「MCP（AI とアプリをつなぐ決まり）」と言い換えます）。言葉は `config/ai_connect.php` に置きます。

| 画面の言葉 | 子ども向け | 意味 | コードの名前（config／部品／URL） |
|---|---|---|---|
| ChatGPT・Claude とつなぐ | 同じ | 利用者が自分の ChatGPT・Claude から、推理手帳の記録を読めるようにすること。読むだけで、仕事の場面の事件は見せない | 設定の枠 `<x-settings.ai-panel>`／`ai_connect.panel` |
| 窓口の住所 | 同じ | AI の設定に入れる住所（`https://suiri.agi-japan.com/mcp`）。説明書では「窓口」と呼ぶ | `/mcp`・`App\Mcp\Servers\SuiriServer`／`panel.address_label` |
| つないでいる AI | 同じ | 許可を出した AI のサービス。名前（AI が自分で名乗ったもの）・戻る先の住所・最後につながった日 | `App\Queries\Ai\ConnectedAppsQuery`（Passport の `oauth_access_tokens` を AI ごとにまとめる）／`panel.connected_title` |
| つなぐのをやめる | 同じ | つないでいる AI の通行証をすべて取り消す。すぐに読めなくなる | `App\Actions\Ai\RevokeAiAccess`／`DELETE /settings/ai/{app}`（`settings.ai.revoke`）／`panel.stop` |
| 同意の画面（許可する・やめる） | 同じ | 「◯◯ に、あなたの事件の記録を読ませてよいですか？」と聞く画面。AI の名前・許可したあとに戻る先・読めるもの・読めないもの・記録が渡る会社と国 | `views/oauth/authorize`（値は `App\Support\Ai\ConsentView`）／`/oauth/authorize`（`passport.authorizations.*`）／`ai_connect.consent` |
| 許可したあとに戻る先 | 同じ | 同意の画面で確かめる住所（`chatgpt.com` など）。名前はだれでも名乗れるので、確かな手がかりは住所 | `ConsentView` の `redirectHost`／`consent.host_label` |
| 通行証・更新の札 | 同じ | 許可の証拠として AI が毎回見せる文字列（アクセストークン。1時間で切れる）と、それを取り替える札（リフレッシュトークン。30日）。説明書とポリシーで使う | Passport の `oauth_access_tokens`・`oauth_refresh_tokens`／`ai_connect.tokens` |
| AI に相談する用に写す（写すボタン） | 同じ | 事件のなぞ・手がかり・見立て・予想と頼み方の文（正誤は判定しないで）を、端末に写すボタン。本人が自分の AI に貼る。アプリからは送らない。仕事の場面の事件では出さない | `<x-case.ai-copy>`・`App\Support\Ai\ConsultText`・`resources/js/parts/ai-copy.js`／`ai_connect.copy` |

## 2. 場面ごとの出し分け

仕事（施術）の場面では、次のように表示を変えます。コードの名前は変えません。

| 共通の言葉 | 仕事の場面での表示 |
|---|---|
| 見た | 見た・触れた・測った |
| 聞いた | ご本人の言葉 |
| 見立て | 見立て（診断ではありません） |
| もしそうなら | 次回、確かめること |

## 2-2. 子ども向けの言葉を出す条件

表の「子ども向け」の列（まちがいノート・ぼくの図鑑・「かも」・見に行く日・どのくらい自信がある？ など）は、**ふだんの場面（設定）が「親子」の人に出します**。条件はこの1つにそろえ、コードでは `User::prefersKidWords()` で判断します。

| 画面 | 子ども向けにするもの |
|---|---|
| 事件の一覧 | 状態のつまみ（調べ中・わかった・おあずけ）と場面の札（ふだん・おやこ・しごと）。迷宮入りのつまみは大人にも「おあずけ」と出し、つまみの下に「おあずけ＝迷宮入り。わからないまま置いた事件だよ。」と一言説明する（`case_list.tabs`・`tabs_kid`・`leads.cold`） |
| 事件を作る | 場面の呼び名（ふだん・おやこ・しごと）、手がかりの種類の説明（目でたしかめた・人から聞いた・「ない」を見つけた）、3問目の見立ての呼び名（「かも」） |
| 事件の画面 | 見立ての呼び名（「かも」）と全部ちがったときの問い、別の説明の型の言い方（日や時間が関係ある？ など）と予想の穴埋めの文、確かさの目安、「いつ見に行く？」「この日に見に行く」「◯月◯日に見に行こう」、閉じた事件の「わかった！」と「図鑑にしまう」（`case_board.kid`） |
| 答え合わせ | 4つの結果（あたり・はずれ・わからない・そもそもちがった）と「どこでまちがえた？」、はんこの言葉、見立ての直しのさそい（「かも」を「あたり」にする？） |
| 今日 | 今日の練習の短い説明（`kid_description`。ほかの人には大人向けの説明を2行まで） |
| ふりかえり・ノーベリ帳・屋根裏の棚 | 呼び名（まちがいノート・ぼくの図鑑・わたしの図鑑。3つの画面の切り替えのつまみでは短く「図鑑」）、見落としの言い方、結果の言い方、見出し「自信と結果くらべ」 |
| 手引きの入口 | わざの名前を子ども向けの名前（`kid_name`）で先に出し、大人向けの名前を横に小さく |
| 手引き（技能・演繹・帰納・アブダクション） | 何も選んでいなければ子ども向けの説明。「大人向け・子ども向け」のボタン（`?kid=0`・`?kid=1`）で選んだときは、その向きが先 |
| 練習メニュー | 子ども向けの説明（`kid_description`）を大人向けの説明より先に出す |
| 名推理カード | 表に「まずは声に出して言ってみよう」を出す（ほかの人には「見えていることを、頭の中で並べてみよう」。`guide.front.say_aloud`・`think_first`）。子ども向けのヒントを初めから開いておく |

事件ごとの場面（日常／親子／仕事）では切り替えません。事件の場面が変えるのは、仕事の場面の言葉の出し分け（上の 2.）だけです。

## 3. 使わない言葉

| 使わない | 理由 | 代わりに |
|---|---|---|
| 診断・治療・治る・効く・改善・処方・おすすめの施術 | 医療の判断に見える（医師法・薬機法） | 見立て・変化・確かめること |
| 患者・顧客・カルテ・client・patient・customer | お客さまの記録を持たない設計のため。コードの名前にも使わない（OAuth の決まった名前 `oauth_clients`・`client_id`・`Passport::client()` だけは例外。つないでくる AI のサービスのことで、人ではない） | （作らない）。つないでくる AI は「AI」「app」と呼ぶ |
| 頭が良くなる・思考力が伸びる・脳トレ・認知症予防 | 根拠のない効果の約束 | 観察・仮説・検証の練習 |
| 正解・不正解（日常の事件について） | 日常の出来事に正解はない | 当たり・外れ（予想について） |
| 演繹・帰納・アブダクション（毎日の入力画面で） | 入力の負担を重くする | 手引きの画面でだけ説明する |
| 無知の無知 | オーナーの決まり | 使わない |
| シャーロック・ホームズをアプリ名・ロゴの主役にする | 海外で商標登録されている | 作品の紹介としてだけ使う |
| 連続◯日・ランキング・ポイント | 罰と圧力で続けさせない | 確かめた件数・考えを変えた件数 |

画面の文言は `bin/check` が確かめます。使わない言葉を打ち消す文（「診断ではありません」「病気の診断・治療・予防を目的としていません」「連続記録やポイントはないよ」「連続記録なし」「点数はつけない」）は通ります。「連続5日！」のような表示と、「連続記録がないと続かない」「〜しないと」のように、ほしがらせる・せかす言い方は止まります。

## 4. コードの名前の付け方

- モデルは単数の英語（`CaseFile`・`Clue`・`Hypothesis`・`Prediction`・`AtticNote`・`Task`）。表は複数（`case_files`…）。`case` は PHP の予約語なので「事件」は `CaseFile` にする。
- 列挙（状態や種類）は `app/Enums/` に置き、表示の言葉は `config/suiri.php` の `labels` から引く（場面ごとの出し分けもここ）。
- URL は英語の名詞の複数（`/cases`・`/tasks`）。ルート名は `cases.show` のように URL に合わせる。
