## 1. なぜ作るのか

### 1-1. 目的

シャーロック・ホームズの物語は、観察から筋道を立てて考える手本として、昔から読まれてきました。けれど、本を読んで終わりにすると、日常で使える力にはなりにくいものです。そこで「**毎日の生活の中でホームズの視点を育てられないか**」を出発点に、ホームズの見方を**タスク管理に組み込んだ形**で練習できるアプリを作ります。

思い描いている使う人は、たとえば子どもと一緒に、論理的に考える練習をしている保護者です。細谷功さんの『具体と抽象』のように、具体と抽象を行き来して考える（「つまり？」「たとえば？」）練習とも相性がよいので、その考え方も取り入れます。施術者が自分の見方を振り返る使い方も考えています。作りと説明書は、自分のツールを作りたい人が参考にできるように、分かりやすくします。

### 1-2. 表の要望と、その奥にある必要

| 層 | 中身 |
|---|---|
| 表の要望 | ホームズのものの見方を、日常で練習できるアプリ。タスク管理に組み込まれた形。 |
| 奥の願い | 親子の会話や毎日の判断で「どうしてそう思った？」「何を見れば確かめられる？」を使えるようになりたい。 |
| 気づいていないかもしれない必要 | 見立てが外れても気まずくならずに考え直せる場。正解を当てる訓練より、「見たこと・考えたこと・まだ分からないこと」を分けて、次の観察で見立てを直す習慣。 |
| 参考にしたい形 | 自分でツールを作りたい人が持ち帰れる、分かりやすい作りと説明書。 |

### 1-3. このアプリが言えること・言わないこと

- 言う：**観察 → 仮説 → 予想 → 確かめる → 振り返る、の手順を、自分の生活で練習して記録する手帳**です。
- 言わない：「頭が良くなる」「思考力が伸びる」「脳トレ」「診断力が上がる」。練習の効果がほかの場面にまで広がるかは研究でも確かではないため（調査 R2・R3）。病気の診断・治療・予防にも使わない（調査 R5）。

## 2. 誰が使うのか

| 利用者 | どんな人か | 1日の中でアプリに触れる瞬間 |
|---|---|---|
| 保護者 | 子どもと一緒に、論理的に考える練習をしている。 | 朝：今日の予定と「答え合わせ待ち」を見る。日中：気になった出来事を1つ記録。夜：子どもと1つの出来事を話す。 |
| 子ども（相棒） | 保護者と一緒に練習する。中高生を想定。13歳未満なら自分のアカウントは持たない。 | 保護者の端末で「相棒の見立て」を先に書く。翌日「確かめた？」を一緒に見る。13歳以上なら自分のアカウントでも使える。 |
| 施術者 | 整体・鍼灸などの施術者。自分の見方を振り返りたい。 | 施術のあとに、自分が見たこと・お客さまの言葉・自分の見立てを分けて書き、次回確かめることを残す。**お客さまの記録（カルテ）には使わない。** |

最初の利用者は、子どもと一緒に練習する保護者とその子ども（相棒）、少数の施術者を想定しています。**一般公開**にします（Google アカウントがあれば、だれでも登録できる）。あとから**招待制**（運営者が名簿に入れたメールアドレスの人だけが新しく登録できる）に切り替えられるようにしておきます。切り替えは設定（`.env` の `SUIRI_INVITE_ONLY=true`）だけで、コードは直しません。

## 3. 中心の流れ（コアループ）

### 3-1. 一言でいうと

**予定や出来事から「気になること」を事件にし、手がかりから見立てを立て、「もしそうなら」の予想を確かめる日をカレンダーに入れ、答え合わせで見立てを直す。**

タスク管理は「確かめることを忘れない」ために使います。思考の練習を「毎日やらなければならない追加の宿題」にはしません。

### 3-2. 流れの図

```
 予定・タスク・ふと気づいたこと
        │「気になる」を押す（任意）
        ▼
 ┌────────── 事件（なぞ） ──────────┐
 │ 手がかり：見た／聞いた／なかった    │ ← あとから何度でも足せる
 │ 見立て  ：説明の案（2つ以上を勧める）│ ← 手がかりに ○（合う）×（合わない）を付けて消していく
 │ 予想    ：もしこの見立てが正しいなら │
 │           〜が見えるはず（確かさ％）│
 └──────────────┬────────────────┘
                 │ 確かめる日を決める
                 ▼
     確かめるタスク ──→ Google カレンダー（専用カレンダー）
                 │ その日が来る（カレンダーが知らせる）
                 ▼
     答え合わせ：当たり／外れ／どちらとも言えない／前提が崩れた
                 │
       ┌─────────┴──────────┐
       ▼                     ▼
  外れ → ノーベリ帳         わかったこと → 屋根裏の棚
  （何を見落とした？）       （つまり？＝一般則／たとえば？＝ほかの場面）
```

### 3-3. ホームズの思考の技能との対応

| 流れの段 | ホームズの技能（調査 R1 の S1〜S10） | 原作の場面の例 |
|---|---|---|
| 手がかり（見た） | S1 見るのではなく観察する／S2 ささいなことを拾う | 『ボヘミアの醜聞』の階段17段 |
| 手がかり（聞いた） | S3 事実と推理を分ける | 『四つの署名』1章 ウィグモア街の郵便局 |
| 手がかり（なかった） | S6 起きなかったことに気づく | 『白銀号事件』吠えなかった犬 |
| 見立て | S4 決めつけを遅らせる／S5 別の説明を並べて消す | 『ブラック・ピーター』 |
| ○×で消す | S5 不可能を除いて残ったもの | 『四つの署名』6章 |
| 予想（もしそうなら） | S7 想像して予測し、確かめる（**ここが演繹**） | 『赤毛組合』膝を見に行く |
| 原因をさかのぼる | S8 逆向きに推理する | 『緋色の研究』第2部7章 |
| 屋根裏の棚 | S9 知識の棚をつくる | タバコの灰の研究 |
| ノーベリ帳 | S10 間違いを認めて直す | 『黄色い顔』「ノーベリ」 |

このアプリが大事にする**演繹**は、「この見立てが正しいなら、〜が見えるはず」と予想を導く段と、合わない見立てを消す段に当たります。見立てを立てる段はアブダクション（仮説形成）、屋根裏の棚に一般則をためる段は帰納です。この3つの違いは「手引き」の画面で説明し、毎日の入力画面には難しい言葉を出しません。

## 4. 機能の要件

優先度：**必須**＝最初の公開に入れる／**次**＝公開後に足す。

### 4-1. ログインとアカウント

| ID | 要件 | 優先度 |
|---|---|---|
| A-1 | Google でログインする（名前・メール・アイコン・ID だけを受け取る。スコープは openid / email / profile）。パスワードの登録は作らない。 | 必須 |
| A-2 | 一般公開（Google アカウントがあれば、だれでも登録できる）。設定（`SUIRI_INVITE_ONLY=true`）で招待制に戻せる。招待制のときは、運営者がコマンド（`invite:add`・`invite:list`・`invite:remove`）で管理する名簿にあるメールアドレスの人だけが新しく登録でき、名簿にない人には「招待制です」と表示する。前から使っている人は、どちらのときもそのままログインできる。 | 必須 |
| A-3 | 初回は、利用規約とプライバシーポリシーへの同意と「13歳以上。18歳未満は保護者の同意を得ています」の確認を求める。 | 必須 |
| A-4 | 設定：表示名、相棒の名前（同じ端末で一緒に使う人の呼び名。例「長男」）、ふだんの場面（日常／親子／仕事）、記録のきっかけ（例「夕食のあとに、気になったことを1つ」。いつ・何のあとにやるかを先に決めておくと続きやすい：実行意図の研究）。 | 必須 |
| A-5 | 自分のデータをすべて JSON でダウンロードできる。 | 必須 |
| A-6 | 退会：すべてのデータを消し、Google の連携も取り消す。 | 必須 |
| A-7 | ログアウト。 | 必須 |

### 4-2. タスク

| ID | 要件 | 優先度 |
|---|---|---|
| T-1 | タスクを作る・直す・消す。項目：題名、メモ（短い）、期日、開始時刻と長さ（任意）、種類（ふつう／確かめる）。 | 必須 |
| T-2 | 一覧：今日／これから／いつか（期日なし）／済み。 | 必須 |
| T-3 | 完了・未完了に戻す。 | 必須 |
| T-4 | 「確かめる」タスクは予想から自動で作られ、予想の答え合わせ画面につながる。答え合わせを済ませると完了になる（行の丸を押して済みにしたり戻したりはできない）。 | 必須 |
| T-5 | タスクを完了するとき、任意で「気になることを記録」に進める（そのタスクを出発点にした事件を作る）。 | 必須 |
| T-6 | 期日のあるタスクを Google カレンダーの専用カレンダーに書き出す（4-5）。 | 必須 |
| T-7 | 繰り返しのタスク。 | 次 |
| T-8 | 見積もりの答え合わせ：タスクに「予想時間」と「かかった時間」（どちらも任意）を入れられる。予想時間を入れるとき、題名の似た過去のタスクの実績を見せる。ふりかえりで、予想と実際の差を出す（過去の実績を思い出すと、楽観しすぎる見積もりが減るという研究がある：Buehler ら 1994）。 | 必須 |

### 4-3. 事件（記録の中心）

| ID | 要件 | 優先度 |
|---|---|---|
| C-1 | 事件を作る：なぞ（題名。例「体操着をなぜ忘れる？」）、場面（日常／親子／仕事）、きっかけ（予定・タスク・なし）。 | 必須 |
| C-2 | 手がかりを足す：種類（見た／聞いた／なかった。仕事の場面では「見た・触れた・測った／本人の言葉／なかった」と表示）と本文。あとから何度でも足せる。 | 必須 |
| C-3 | 見立てを足す：本文。2つ目を勧める（「ほかの説明は？」）。たくさんは求めない（別の説明は1〜2個が適量で、多く書かせると逆効果という研究がある）。 | 必須 |
| C-4 | 見立てごとに、手がかりへ ○（合う）×（合わない）を付けられる。× が付いた見立ては「消す」を勧める。 | 必須 |
| C-5 | 見立ての状態：検討中／有力／消えた／当たり。変えた日時を残す（考えを変えた記録）。 | 必須 |
| C-6 | 予想を立てる：見立てを選び、「もしそうなら〜が見えるはず」の文、確かさ（50〜95％）、確かめる日（時刻は任意）。保存すると「確かめる」タスクを作る。**予想の文と確かさは保存後に書き換えられない**（後知恵を防ぐ。考えが変わったら新しい予想を立てる）。取り下げはできる。取り下げると、まだ済んでいない確かめるタスクは消す（もう確かめる必要がないため。済んだものは記録として残す）。 | 必須 |
| C-7 | 答え合わせ：当たり／外れ／どちらとも言えない／前提が崩れた、と一言。最初の予想の文と、書いた日時を必ず見せる。 | 必須 |
| C-8 | 外れたとき：「何を見落とした？」を選ぶ（手がかりが足りなかった／見立てが1つだけだった／思い込みがあった／確かめ方がずれていた／偶然）と一言。ノーベリ帳に載る。 | 必須 |
| C-9 | 事件を閉じる：解決／迷宮入り。閉じるとき「つまり？（この事件からわかった一般則）」「たとえば？（ほかに当てはまる場面）」を任意で書き、屋根裏の棚に入れられる。 | 必須 |
| C-10 | 一番軽い記録：手がかり1つと見立て1つだけで保存できる。 | 必須 |
| C-11 | 相棒の見立て（同じ端末）：相棒モードの事件では、相棒が先に見立てを書き（自分の見立ては隠れる）、次に自分が書き（相棒の見立ては隠れる）、「見せ合う」で並べて表示する。どの手がかりに ○ を付けたかの違いも並べる。 | 必須 |
| C-12 | 一覧：捜査中／解決／迷宮入り。場面で絞れる。 | 必須 |
| C-13 | 相棒が自分のアカウントを持つ場合の共有（招待・同じ事件を2つのアカウントで見る）。 | 次 |

### 4-4. ワトソンのひとこと（決まった規則で出す問いかけ）

AI は使いません。決まった規則で、**一度に1つだけ**、閉じられる問いかけを出します。保存は止めません。

| ID | 出す条件 | 問いかけ（例） | 優先度 |
|---|---|---|---|
| W-1 | 「見た」の手がかりに推測の言葉（と思う・だろう・らしい・みたい・ようだ・たぶん・おそらく・はず・気がする・かもしれない）がある | 「これは見たこと？　それとも考えたこと？」 | 必須 |
| W-2 | 「見た」の手がかりに原因を決める言葉（ので・から・ため・せいで・おかげで・によって）がある | 「原因まで見えた？　それとも考えた？」 | 必須 |
| W-3 | 見立てが1つだけ | 「ほかの説明は？　ホームズはいつも別の可能性を用意した（『ブラック・ピーター』）」 | 必須 |
| W-4 | 仕事の場面で「よくなった・楽になった・改善」と書かれた | 「施術のほかに考えられることは？　自然な経過／生活の変化／ほかの治療／測り方のばらつき／期待」 | 必須 |
| W-5 | 電話番号・メールアドレスの形、「様」「さん」のつく名前らしきものがある | 「ほかの人がわかる情報ではありませんか？　記号（Aさん など）で書いてください」 | 必須 |
| W-6 | 捜査中の事件で、見立て（消えていないもの）はあるのに、答え合わせ待ちの予想が1つもない（予想には確かめる日が必ず付くので、「確かめる日の決まった予想がない」と同じ） | 「いつ確かめる？」 | 必須 |
| W-7 | 捜査中の事件に「なかった」の手がかりが1つもない | 「あるはずなのに、なかったものは？（吠えなかった犬）」 | 次 |

言葉の一覧と表示文は設定ファイル（`config/watson.php`）にまとめ、コードに直書きしません。

### 4-5. Google カレンダー連携

| ID | 要件 | 優先度 |
|---|---|---|
| G-1 | 連携は任意。ログインとは別に「カレンダーとつなぐ」で追加の許可をもらう（段階的な許可）。連携の前に、送る項目（タスクの題名・日時・戻るリンクと、どのタスクの予定かを見分ける番号だけ）と受け取る項目、Google は米国の会社であることを示す。 | 必須 |
| G-2 | つないだら、アプリ専用のカレンダー「推理手帳」を作り、期日のあるタスクをそこに書く（作る・直す・消す）。メインのカレンダーには書かない。送るのはタスクの題名・日時・アプリに戻るリンクと、どのタスクの予定かを見分ける番号（`suiri_task_id`）だけ（番号は予定の利用者に見えない欄に入れる。番号はアプリの中の通し番号で、利用者の記録の中身ではない）。事件の手がかりや見立ての本文は送らない。連携が切れている間に消したタスクの予定は、つなぎ直したときに専用カレンダーから消す。 | 必須 |
| G-3 | 確かめるタスクの予定は「予定なし（時間を塞がない）」にし、予定から答え合わせの画面に戻れるリンクを付ける。確かめるタスクの題名には予想の文が入るので、予定の題名は「推理手帳：答え合わせの日」に固定する（本文を送らないため）。 | 必須 |
| G-4 | 専用カレンダーで日時を動かされた・消されたら、15分ごとの取り込みでタスクの期日を合わせる・カレンダーとのつながりだけ外す（タスクは消さない）。Google 側で新しく作られた予定は取り込まない。 | 必須 |
| G-5 | 今日の画面に、自分のカレンダーの今日の予定を時刻順に表示する（読むだけ）。受け取るのは予定の題名と時刻だけで、5分だけ一時的に覚え、記録としては保存しない。予定から「気になる」で事件を作れる（題名は URL に載せずに送る）。確かめる日の提案（S-4）のために、今日から14日先までの予定の題名と時刻も同じ決まりで読む（1回の問い合わせ・5分だけ覚える・保存しない）。 | 必須 |
| G-6 | 連携の解除：Google のトークンを取り消す。専用カレンダーも消すかを選べる。 | 必須 |
| G-7 | Google の許可が取り消された・切れたら「連携が切れました。つなぎ直してください」と表示する。アプリの保存は Google が止まっていても成功させ、書き出しはあとで再送する。 | 必須 |

スコープ：`calendar.app.created`（専用カレンダーを作って書く）と `calendar.events.owned.readonly`（自分の予定を読む）。同意画面は「本番（未審査）」で運用する。未審査のあいだ、カレンダーとつなげる利用者は通算100人まで（調査 R4）。一般公開なのでこの数に届きうる。近づく前に、審査を受けるか、招待制（A-2）に切り替えて新しい人を絞るかを決める。

### 4-6. 今日の画面

| ID | 要件 | 優先度 |
|---|---|---|
| D-1 | 上から：記録のきっかけの一文 → 答え合わせ待ちの予想（期日が今日まで）→ 今日の予定とタスク（時刻順）→ 今日の練習の提案 → 捜査中の事件（最近の3件）。 | 必須 |
| D-2 | 答え合わせ待ちは、その場で開いて答え合わせできる。 | 必須 |
| D-3 | タスクをすばやく足す欄。 | 必須 |
| D-4 | 予定・タスクの行から「気になる」で事件を作れる。 | 必須 |

### 4-7. 手引き（ホームズの方法を学ぶ）

| ID | 要件 | 優先度 |
|---|---|---|

### 4-10. 提案（AI なし）

白紙を前に手が止まらないよう、**決まった型と、本人のこれまでの記録から**書き出しの候補を出します。AI は使いません（中身を外に送らない・料金がかからない・なぜその提案が出たかを説明できる）。提案は書き出しの手助けで、押すと入力欄に文の書き出しが入るだけです。**保存は本人がします**（自動で保存しない）。言葉は `config/suiri.php` の `suggest` にまとめます。

| ID | 要件 | どこに・何から | 優先度 |
|---|---|---|---|
| S-1 | 手がかりの問いかけ：押すと書き出しが入る小さなボタン（「いつ？」「何回？」「どこで？」「だれが？」「いつもと違ったことは？」「あるはずなのに無かったものは？」）。最後のものは種類を「なかった」に切り替える。仕事の場面では「どこが？」「どのくらい？（数で）」「前回と比べて？」「ご本人はどう言った？」（種類を「ご本人の言葉」に切り替える）と「無かったもの」。 | 手がかりを足す欄の真上／決まった型 | 必須 |
| S-2 | 別の説明の型：時間（時期・曜日・時刻が関係？）／習慣（いつもの手順？）／環境（置き場所・道具・天気？）／人（だれかの影響？）／偶然（たまたま？）／数え方（記録や見間違い？）／逆向き（原因と結果が逆では？）。見立てが0〜1個のときは開いて目立たせ、2個からは1行にたたむ。ふだんの場面が親子の人には子ども向けの言い方。仕事の場面では W-4 と同じ5つ（自然な経過／生活の変化／ほかの治療／測り方のばらつき／期待）。 | 見立てを足す欄の真上／決まった型 | 必須 |
| S-3 | 予想の穴埋め：「もしそうなら」の欄を開くと、文が空なら「もし『（見立ての本文）』が正しいなら、＿＿のときは＿＿のはず」が入る（書いてあれば上書きしない）。JavaScript が動かなくても、欄の下に同じ型を例として出す。「＿＿」が残ったままでは保存できない（予想の文は保存後に直せないため）。 | 「もしそうなら」の文の欄／決まった型と見立ての本文 | 必須 |
| S-4 | 確かめる日の提案：「明日」「3日後」「1週間後」のボタン。カレンダーとつないでいる人には、これから14日の自分の予定のうち、事件のなぞ・手がかり・見立てと言葉が重なる題名の予定を3件まで「次の『◯◯』の日（11/7 金）」として出し、押すと日付と時刻が入る。予定の題名は画面に出すだけで保存しない（G-5 と同じ決まり）。 | 確かめる日の欄の下／本人のカレンダー | 必須 |
| S-5 | 屋根裏の棚からの提案：本人の棚の知識（つまり？）のうち、事件のなぞ・手がかりと言葉が重なるものを3件まで「前にわかったこと：〜」として出す。押すと、見立ての欄には「前にわかった『〜』が当てはまるなら、」が入り、予想の欄では「使う知識」に選ばれる。他人の知識・この事件から生まれた知識は出さない。0件なら何も出さない。 | 見立てを足す欄・予想の「使う知識」／本人の屋根裏の棚 | 必須 |
| S-6 | さっき終わった予定への声かけ：今日の画面の予定とタスクの並びで、終わった時刻を過ぎて3時間以内の今日の予定に「さっき終わった予定：気になったことは？」の印を付け、その行の「気になる」を目立たせる（D-4 の流れを使う）。 | 今日の予定とタスク／本人のカレンダー | 必須 |

**言葉の重なりの決め方（S-4・S-5）**：日本語は単語の区切りがないので、意味を持ちやすい文字（漢字・カタカナ・英数字）のひと続きを取り出し、漢字は2文字ずつ、カタカナと英数字は3文字ずつの「かけら」に分け、同じかけらが1つでもあれば「重なる」とします（多いほど先に出す）。ひらがな（てにをは・送りがな）は見ません。「今日」「時間」「予定」のようにどこにでも出てくるかけらは数えません。たとえば「体操着」と「体育」は「体」の1文字しか同じでないので重なりません（誤検知を控えめにするため）。判定は `App\Support\WordOverlap` の1か所です。

### 4-11. ChatGPT・Claude とつなぐ（読むだけ）

アプリの中では AI を使いません。そのうえで、**利用者が自分の ChatGPT・Claude から、推理手帳の記録を読んで相談できる窓口**（`https://suiri.agi-japan.com/mcp`。MCP＝AI とアプリをつなぐ決まり）を置きます。本人の操作で本人の AI が読みに来る形で、運営者が選んで送ることはしません。AI の役目は**候補を出すこと**（ほかの見立て・見立てを見分ける確かめ方・まだ集めていない手がかり）に限り、正誤は決めさせません。AI の料金は利用者のプランの中で、推理手帳は AI の API を持ちません。つなぐ流れは OAuth 2.1（認可コード＋PKCE）と動的クライアント登録（AI が自分で登録する）で、ログインは今までどおり Google だけです。部品は Laravel 公式の laravel/mcp と Laravel Passport。言葉は `config/ai_connect.php`、決まりは `.claude/rules/ai-connect.md`、しくみとつなぎ方の説明は [12. ChatGPT・Claude とつなぐ](../guide/12-ai-connect.md)。

| ID | 要件 | 優先度 |
|---|---|---|
| M-1 | 利用者は、自分の AI（ChatGPT・Claude など MCP に対応したもの）から窓口（`/mcp`）につなげる。つなぐときは推理手帳の Google ログインと同意の画面を通る。未ログインなら Google のログインへ、規約に同意していなければ同意の画面へ送り、終わったら同意の画面へ戻す。 | 必須 |
| M-2 | 窓口から見えるのは本人の記録のうち、**仕事の場面の事件と、それにつながる予想・屋根裏の棚の知識を除いたもの**（施術の場面には体のことが混ざりうるため）。他人の記録は見えない。見つからない・他人・仕事の場面は同じ文で返し、あるかどうかを漏らさない。 | 必須 |
| M-3 | 読む道具は4つ：事件の一覧（`list_cases`）・事件の中身（`get_case`）・答え合わせ待ちの予想（`list_due_predictions`）・屋根裏の棚（`search_attic`）。相棒モードで見せ合う前の事件は、見立てと予想を隠す。 | 必須 |
| M-4 | **書き込みの道具は置かない**（手がかり・見立て・予想を足す・事件を作る、も置かない）。答え合わせ・取り下げ・○×・見立ての状態・直す・消すの道具も置かない。予想の文と確かさは窓口からも変えられない。 | 必須（置かないことが要件） |
| M-5 | 窓口の説明と道具の説明で、AI に「候補を出すだけで正誤を判定しない」「予想は書いたあと変えられないので、新しい予想の案として出す」「病気や体の状態を見分けない」「ほかの人の名前を書かない」を伝える。 | 必須 |
| M-6 | 同意の画面に、AI の名前（自己申告）・許可したあとに戻る先の住所・読めるもの・読めないもの・記録が渡る会社と国とそのポリシー・「自分で始めたときだけ進める」注意を出す。許可する・やめるを選べる。 | 必須 |
| M-7 | 設定の画面に「ChatGPT・Claude とつなぐ」の枠：できること・窓口の住所（写すボタンつき）・ChatGPT と Claude のつなぎ方（画面の英語の項目名のまま）・つないでいる AI の一覧（名前・戻る先・最後につながった日）と「つなぐのをやめる」（すぐに読めなくなる）。 | 必須 |
| M-8 | 許可した AI のサービスの戻り先は chatgpt.com・claude.ai・claude.com に限る。通行証は1時間、更新の札は30日で切れる。取り消し・期限切れのものは毎日消し、使われなかった自己登録は7日で消す。退会で許可の記録をすべて消し、データの書き出しにつないでいる AI の一覧（名前・戻る先・最後につながった日時。通行証の番号は出さない）を入れる。 | 必須 |
| M-9 | 事件の画面に「AI に相談する用に写す」：なぞ・手がかり・見立て・予想と頼み方の文（正誤は判定しないで・名前などを書かないで）を端末に写すだけ。本人が自分の AI に貼る（窓口を使えないプランでも使える。アプリからは何も送らない）。仕事の場面の事件では出さない。見せ合う前は見立てを写さない。 | 必須 |

- ChatGPT は、プランによってはつなげない・読むだけになることがある（2026-10 の OpenAI のヘルプ）。そのため窓口は読むだけで出し、どのプランでも使える写すボタン（M-9）を並べる。
- 4-10 の提案（AI なし）は別のもので、そのまま残す。

## 5. 作らないもの（と理由）

| 作らないもの | 理由 |
|---|---|
| AI による採点・正誤の判定・思考力の点数、アプリの中の AI による提案、AI の窓口からの書き込み | 日常の出来事には正解のデータがなく、もっともらしい採点は信頼を損なう。答え合わせは現実（確かめる日）に任せる。AI は記録の外の現実を自分で確かめられない、という限界とも合う。書き出しの提案（4-10）は決まった型と本人の記録から出し、AI は使わない（本文を外に送らない・なぜ出たか説明できる）。利用者が自分の ChatGPT・Claude からつなぐ窓口（4-11）は、本人の操作で本人の AI が**読みに来るだけ**のもので、アプリは AI を持たない。AI は候補を出す役に限り、記録を書き換える道具は置かない。 |
| お客さま（他人）ごとの記録、カルテ、顧客の ID | 病歴などの要配慮個人情報を持たないため。漏れたときの報告義務を最初から生まない。 |
| 病名・症状のチェック、施術の効果の判定 | 医師法・薬機法（プログラム医療機器）の線を越えないため。 |
| 連続記録・バッジ・順位 | 罰や圧力で続けさせると、途切れたときにやめてしまう（調査 R3）。成長の物差しは推理の質にする。 |
| メインのカレンダーへの書き込み、自動で予定を動かす機能 | 利用者の予定を勝手に変えないため。権限も最小にする。 |
| 運営者が記録の中身を読める管理画面 | 利用者の記録を守るため。招待制に戻したときの名簿の管理もコマンドで行う。 |
| アクセス解析・広告のタグ | 外部への送信を増やさないため。 |

## 8. 次の版で考えること

- 相棒が自分のアカウントを持つ場合の共有（C-13）
- 繰り返しのタスク（T-7）
- 「なかった」の手がかりの問いかけ（W-7）
- ChatGPT・Claude とつなぐ窓口（4-11）に、書き足す道具（手がかり・見立て・予想を足す。設定の「書き足しを許す」を入れた人だけ）を足すか。足すなら、足す前に AI が利用者の確認を得る決まりと、確かさを利用者に聞く決まりを道具の説明に入れる。ノーベリ帳を読む道具（`list_misses`）も候補。
- AI は判定役ではなく問いかけ役（「別の説明の候補を1つ出す」など）に限る決まりは変えない。
