> 前提：目的は、日常でホームズのものの見方を練習できるアプリ。使う人は、子どもと一緒に考える練習をしている保護者とその子ども、自分の見方を振り返りたい施術者を想定する。

# 1. 使う人が本当に欲しいもの

| 層 | 読み取れること |
|---|---|
| 表の要望 | 保護者と子どもが、ホームズのものの見方を日常で練習できるアプリ。施術者が自分の見方を振り返る使い方にも応用できるとよい。 |
| その奥の願い | 具体と抽象を行き来して考える練習（細谷功『具体と抽象』のような考え方）を、親子の会話や日々の判断で使えるようにしたい。「どうしてそう思った？」「何を見れば確かめられる？」を共有できるようにしたい。 |
| まだ言葉になっていないかもしれない必要 | **見立てが外れた後も、気まずくならずに考え直せる場**。正解を当てる訓練より、「見たこと・考えたこと・まだ分からないこと」を分け、次の観察で見立てを更新する習慣が要る。 |

ホームズの見方は、本で読むだけでなく、**日常に持ち帰って使える形**にする必要がある。したがって、作品の雰囲気だけでなく、日常のどの瞬間にどんな問いを挟むかが、企画の核になる。

# 2. 利用者像ごとの、アプリに触れる瞬間

| 利用者 | 1日の瞬間 | その場ですること |
|---|---|---|
| 保護者 | 朝、今日の予定を見るとき | Googleカレンダーの予定と自分のタスクを確認する。昨夜の「明日確かめること」があれば、予定の下に一行だけ見る。 |
| 保護者と子ども | 夕食後、今日の出来事を話すとき | 保護者のスマホで一つの出来事を選ぶ。まず子ども、次に保護者が「見たこと」と「考えたこと」を話す。互いの違いを一つ見つけ、確かめられそうなら次回の問いにする。約5分。 |
| 子ども | 翌朝、前日の問いが気になったとき | 「確かめられた／違った／まだ分からない」を選ぶ。答えが出なくても終えられる。 |
| 施術者 | 予約前に予定を開くとき | 前回自分が残した「次に聞く・見ること」を一行で確認する。 |
| 施術者 | 対応後、次の仕事に移る前 | 「本人が話したこと」「自分が確認したこと」「自分の見立て」を短く分け、次回の確認事項を一つ残す。最初は個人を特定する情報を入れずに試す。 |

保護者・子ども・施術者を最初から同じ記録画面に押し込まない。共通するのは「一つの出来事から、次に確かめることを残す」操作で、入力例と言葉遣いは場面ごとに変える。

# 3. 中心の循環（コアループ）

| 案 | 循環 | 強み | 弱み |
|---|---|---|---|
| A. 毎日の推理問題 | 出題→回答→解説 | 始めやすく、親子で遊べる | アプリの中だけで上達し、現実の予定や仕事につながりにくい |
| B. 日常観察ノート | 気づきを自由記述→後で読み返す | 題材が本人の生活にある | 毎回「何を書こう」と迷い、読み返す理由も弱い |
| **C. 予定から始まる「次の問い」** | 予定・タスク→気づきを残す→次の予定で確かめる→見立てを更新 | 日常の用事が練習のきっかけと、確かめる機会になる | 問いかけが多いと邪魔になる |

**Cを推す。** タスク管理は「次に確かめることを忘れない」ために使う。思考練習を毎日の追加タスクにはしない。

具体例は「子どもが今週、二度持ち物を忘れた」。保護者が学校の準備というタスクを完了するとき、任意の「一つ気づきを残す」を押す。

1. **記録カード・約60秒**  
   入力欄は「見た・聞いたこと：今週二度、体操着を忘れた」「いまの見立て：前夜の準備を忘れたのかも」「次に確かめること：前夜に準備した日はどうだった？」の三つ。見立てと確認事項は空欄でも保存できる。
2. **次の予定に結ぶ・約10秒**  
   「次に確かめること」を押すと、自分のタスクとして作成される。「次の登校準備」の予定があればそこに表示する。予定がなければ日付を選ぶか、期限なしで置ける。
3. **次回の予定カード・約20秒**  
   予定の下に問いが一行だけ現れる。開いたら「見立てどおり／違った／まだ分からない」を選び、一言追記できる。違っていたら、そこから新しい問いを作れる。
4. **週末の親子会話・約5分、任意**  
   一枚のカードを選び、子どもの見方を先に聞く。「二度とも朝に急いでいた」など、保護者が見ていなかった事実が出たら追記する。最後に「忘れ物の話」から「準備の時間が変わると結果も変わるかもしれない」という共通の形を見つける。これが『具体と抽象』との接点になる。

通常のタスクは思考カードを開かずに完了できる。Googleカレンダーの予定も、すべてを練習対象にしない。利用者が「この出来事は気になる」と選んだときだけ循環が始まる。

# 4. 最小の機能セット（MVP）と、あえて作らないもの

**作るもの**

- 今日の画面：自前のタスクとGoogleカレンダーの予定を時刻順に表示。まずは指定した一つのカレンダーの予定を取り込み、アプリ側での編集は自前タスクに限定する。
- タスクの作成・完了と、予定に紐づく「次に確かめること」。
- 三欄の記録カードと、「見立てどおり／違った／まだ分からない」の更新。
- 保護者の端末一台で使える「二人で見る」表示。子ども用のアカウントや点数は設けず、互いの一言を並べて見る。
- 過去のカード一覧。「何を当てたか」より「何を見て考えを変えたか」を読み返せるようにする。

**作らないもの**

| 機能 | 理由 |
|---|---|
| AIによる正誤判定・思考力スコア | 現実の出来事に正解データがなく、もっともらしい採点が信頼を損なう。 |
| 毎日の出題、連続記録バッジ | 予定のついでに使う設計と衝突し、親子の会話も宿題になりやすい。 |
| 患者記録、診断候補、施術効果の判定 | まず「次に何を確かめるか」という共通の体験を試したい。施術の記録業務まで一度に担うと、用途も入力負担も大きく変わる。 |
| Googleカレンダーとの全面的な双方向編集 | どちらで変更した予定を正とするかが複雑になる。MVPでは予定を取り込み、確認タスクはアプリ内で管理する。 |

# 5. 失敗しそうな点と対策

| 失敗 | 対策 |
|---|---|
| 続かない | 「毎日一件」を求めない。予定を終えたときに任意で一件残せれば十分。何も記録しない日も通常どおり使える。 |
| 入力が面倒 | 一件一分を目安にし、三欄は短文でよい。次回の問いは記録からそのままタスク化し、再入力させない。 |
| 説教くさい | 「根拠不足です」ではなく「ほかに何を見れば分かりそう？」と尋ねる。問いは一度に一つ、閉じられる。 |
| 子どもが飽きる、保護者が先生役になる | 子どもの答えを先に聞き、保護者も自分の見立てを書く。「どちらが正しいか」ではなく「見ていたところの違い」を発見する。扱う題材も本人が選ぶ。 |
| 医療っぽい権威が出る | 施術者向けでも画面上の言葉は「観察・見立て・次の確認」にとどめる。アプリが原因や効果を認定したように表示しない。 |
| 記録を残しただけで、確かめない | 今日の一覧に「前に残した問い」を再表示する。ただし、確認できなければ「まだ分からない」で閉じられる。 |

# 6. ホームズらしさ・面白さ

名前の候補は**「次の手がかり」**。事件を解決した気分より、身近な違和感に目が向く感覚を大切にする。

画面には「見たこと」「見立て」「次の手がかり」を小さな手帳の見出しとして置く。虫眼鏡や紙の質感は控えめに使い、入力の読みやすさを優先する。完了時の言葉も「事件解決！」ではなく、**「見立てを更新しました」**、**「まだ分からない、を残しました」**がよい。後から考えを変えたカードが、静かな達成感になる。

# 7. AIを使うなら、どこに使い、どこに使わないか

MVPは**AIなし**で成立させる。日常の出来事をAIが独立して確認することはできない、という懐疑は設計上の重要な前提になる。

後から試すなら、本人が望んだときだけ、入力した文章を「見たこと」と「見立て」に分ける**下書き補助**、または「次に確かめられることは？」という**問いの候補を一つ出す補助**に限る。候補は本人が修正・採用する。AIが見落としを指摘しなかったことを、記録の正しさの保証として扱わない。

原因の特定、施術の効果判定、子どもの思考力評価には使わない。このアプリが正直に提供できる価値は、**考えを整理し、次の観察につなぎ、後で見直せること**である。

上記の利用場面と機能は、冒頭の前提からの設計提案であり、利用者調査で確認済みの事実ではない。
