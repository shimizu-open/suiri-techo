# 9. 用語集

## この章でわかること

- このアプリの言葉（事件・手がかり・見立て・もしそうなら・答え合わせ・ノーベリ帳・屋根裏の棚 など）の意味と、子ども向けの言い方と、どの画面に出るか
- この解説書に出てくる技術の言葉（MVC・ルート・ミドルウェア・キュー・OAuth・CloudFront・Docker など）の意味を、たとえつきで

**役目：** わからない言葉が出てきたら、ここで引きます。

**たとえると：** 本の巻末の索引と小さな辞書です。

**2つに分けています：**

- **9-1. このアプリの言葉**：画面に出る言葉です。人向けにくわしく書いたもので、元の表は [言葉のルール](../design/words.md)（AI 向けの短い版は `.claude/rules/domain.md`）。アプリの流れの順に並べています。
- **9-2. 技術の言葉**：プログラムの言葉です。アルファベット順、次に五十音順に並べています。

---

## 9-1. このアプリの言葉

**読み方：** 見出しの言葉が画面の言葉です。「子ども向け」は、ふだんの場面を「親子」にした人に出る言い方です（9-1-1 の「子ども向けの言葉」）。「画面」はその言葉が出る主な画面、「コード」はプログラムの中の名前です。

### 9-1-1. 全体の言葉

**推理手帳（すいりてちょう）**
このアプリの名前です。英語の副題は Deduction Notebook。ホームズのものの見方を、毎日の生活で練習して記録する手帳で、**観察 → 仮説 → 予想 → 確かめる → 振り返る** の手順をタスク管理に組み込んでいます。ホームズの名前はアプリ名の主役にしていません（海外で商標登録されているため）。
画面：すべての画面の上の題字・トップ。コード：`config('app.name')`。

**場面（ばめん）**（子ども向け：ばめん）
記録が、日常・親子・仕事のどれの話かです。事件ごとに選び、設定の画面では「ふだんの場面」を決めます。たとえると、手帳の章の見出しです。事件の場面が「仕事」だと、一部の言葉の言い方が変わります（下の「仕事の場面の言い方」）。
画面：事件を作る・事件の一覧の札・設定。コード：`Scene`（`daily`／`family`／`work`）。

**子ども向けの言葉**
ふだんの場面（設定）を「親子」にした人には、言葉を子どもにも読める形にして出します（例：見立て →「かも」、ノーベリ帳 → まちがいノート）。条件はこの1つだけで、事件ごとの場面では切り替えません。手引きの画面では「大人向け・子ども向け」のボタンで選び直せます。
画面：事件の詳細・今日・ふりかえり・ノーベリ帳・屋根裏の棚・手引き・名推理カード。コード：`User::prefersKidWords()`、言葉は `config/suiri.php` の `labels.kid`。

**仕事の場面の言い方**
施術者が仕事（施術）の場面で使うときは、表示だけを変えます。「見た」→「見た・触れた・測った」、「聞いた」→「ご本人の言葉」、「もしそうなら」→「次回、確かめること」。「見立て」には、医療の判断ではないことを示す一言が付きます（言い方は [言葉のルール](../design/words.md) の 2）。プログラムの中の名前は変えません。
画面：仕事の場面の事件の詳細。コード：`config/suiri.php` の `labels.by_scene.work`。

**相棒（あいぼう）**（子ども向け：相棒）
同じ端末で一緒に考える人の呼び名です（例：長男）。設定の画面で名前を入れると、事件を「相棒モード」で作れるようになります。
画面：設定・事件を作る・事件の詳細。コード：`users.partner_name`・`HypothesisAuthor::Partner`。

**相棒モード・見せ合う**（子ども向け：見せ合う）
相棒モードの事件では、まず相棒が見立てを書き（自分の見立ては隠れる）、次に自分が書き（相棒の見立ては隠れる）、最後に「見せ合う」で並べます。どの手がかりに ○ を付けたかの違いも並べて見せます。たとえると、2人で答えを紙に伏せて書き、「せーの」で表に返す遊びです。勝ち負けではなく、どこで見方が分かれたかを話すためのものです。
画面：事件の詳細（並べて見る表）。コード：`case_files.partner_mode`・`case_files.revealed_at`。

**一般公開・招待制**
だれが新しく登録できるかの2つの形です。既定は **一般公開** で、Google アカウントがあれば、だれでも登録できます。設定（`src/.env` の `SUIRI_INVITE_ONLY=true`）で **招待制** に切り替えると、運営者がコマンドで名簿に入れたメールアドレスの Google アカウントだけが、新しく登録できます。招待制のとき、名簿にない人がログインすると「推理手帳はいま招待制です」と出ます。前から使っている人は、どちらのときもそのままログインできます。たとえると、ふだん開けている入口に、必要なときだけ名簿を持った受付を立てるようなものです。
画面：トップ（招待制のときだけ「招待制です」と出る）・利用規約。コード：`config('suiri.invite_only')`・名簿の `invitations` の表・`php artisan invite:add`。

**同意**
初めてログインした人に、利用規約とプライバシーポリシーへの同意と、「13歳以上。18歳未満は保護者の同意を得ています」の確認を求めます。両方にチェックするまで、ほかの画面には進めません。
画面：同意の画面（`/agree`）。コード：`users.agreed_at`・ミドルウェア `agreed`。

**個人情報の注意書き**
入力欄の下にいつも小さく出る一文です。ほかの人の名前・連絡先や、病名・通院のことなど、その人がわかる情報や健康の情報は書かず、「同僚A」のように書いてもらいます。
画面：入力欄のあるすべての画面。コード：`<x-ui.privacy-note>`・`config/suiri.php` の `notes`。

### 9-1-2. 事件の言葉

**事件（じけん）**（子ども向け：事件）
気になる出来事と、その「なぞ」です。記録の単位で、手がかり・見立て・予想は、どれも1つの事件の中に入ります。たとえると、探偵の事件ファイル1冊です。
画面：事件の一覧・事件を作る・事件の詳細。コード：`CaseFile`／`case_files`／`/cases`（`case` は PHP の予約語なので CaseFile）。

**なぞ**（子ども向け：なぞ）
事件の題名です。「〜はなぜ？」の形を勧めます（例「体操着をなぜ忘れる？」）。
画面：事件を作る・事件の詳細のいちばん上・一覧。コード：`case_files.title`。

**きっかけ・気になる**
事件を作ったもとです。予定・タスクの行の「気になる」を押すと、その題名を写して事件を作る画面に進みます（題名は URL に載せずに送ります）。練習メニューから作ったときは、そのメニューの名前がきっかけになります。
画面：今日の予定とタスク・タスクを済みにした直後の枠・事件の詳細の札。コード：`case_files.origin_kind`（`task`／`event`／`practice`）・`origin_label`。

**一番軽い記録**
なぞと、手がかり1つと、見立て1つだけで保存できる形です。1件を1分以内で書けるようにするためです。
画面：事件を作る。

**捜査中・解決・迷宮入り**（子ども向け：調べ中・わかった・おあずけ）
事件の状態です。閉じるときに、解決か迷宮入りを選びます。迷宮入りは「わからないまま置いておく」ことで、あとから開き直せます（解決の事件も開き直せます）。
画面：事件の一覧のタブ・事件の詳細の札。コード：`CaseStatus`（`open`／`solved`／`cold`）。

**手がかり（てがかり）**（子ども向け：手がかり）
事件について確かめた事実です。考え（「〜と思う」）は混ぜず、見たこと・聞いたことだけを書きます。あとから何度でも足せます。
画面：事件の詳細の「手がかり」の段。コード：`Clue`／`clues`。

**見た・聞いた・なかった**（子ども向け：目でたしかめた・人から聞いた・「ない」を見つけた）
手がかりの3つの種類です。「見た」は自分の目・耳・手で確かめた事実、「聞いた」は人が話したこと（本当かどうかは別）、「なかった」は、あるはずなのになかったことです。「なかった」は、ホームズの『白銀号事件』の「夜に犬が吠えなかった」から来ています。
画面：手がかりを足す欄・手がかりの札。コード：`ClueKind`（`seen`／`heard`／`absent`）。

**見立て（みたて）**（子ども向け：「かも」）
「こうではないか」という説明の案（仮説）です。1つで決めつけないよう、2つ以上を勧めます（ただし、たくさんは求めません）。
画面：事件の詳細の「見立て」の段。コード：`Hypothesis`／`hypotheses`。

**検討中・有力・消えた・当たり**（子ども向け：まだわからない・ありそう・ちがった・あたり）
見立ての状態です。変えると、その日時が「考えを変えた記録」に残り、ふりかえりで数えます。
画面：見立てのカードの状態のボタン。コード：`HypothesisStatus`（`considering`／`likely`／`eliminated`／`confirmed`）・`hypothesis_status_logs`。

**合う・合わない（○×）**（子ども向け：○・×）
手がかりが、その見立てに合うかの印です。見立てごとに、手がかりへ ○ か × を付けます。× の付いた見立てには「消す？」を勧めます。たとえると、容疑者の表に、証拠ごとに丸とバツを付けていく作業です。
画面：見立てのカードの中。コード：`Fit`（`fits`／`contradicts`）・`clue_hypothesis`。

**いまの一手**
事件の詳細に1枚だけ大きく出る「いまやることのカード」の元になる、「今いちばんすべきこと」です（手がかりを足す・見立てを足す・予想を立てる・答え合わせ・待つ・閉じる・相棒の番 など）。迷わず次に進めるようにするための案内です。
画面：事件の詳細（いまやることのカード）。コード：`App\Queries\Cases\NextStep`・どのカードを出すかを決める `<x-case-step.desk>`・カードを1枚出す `<x-case-step.now>`。

**ワトソンのひとこと**
決まった規則で出す問いかけです（AI ではありません）。たとえば「見た」の手がかりに「〜と思う」があると「これは見たこと？　それとも考えたこと？」と聞きます。一度に1つだけ出し、閉じるとその事件ではもう出ません。保存を止めることはしません。
画面：事件の詳細。コード：`App\Services\Watson\WatsonNotes`・`config/watson.php`・閉じた記録は `dismissed_hints`。

### 9-1-3. 予想と答え合わせの言葉

**もしそうなら（予想）**（子ども向け：それなら〜のはず）
「この見立てが正しいなら、〜が見えるはず」という予想です。ホームズの思考の中で **演繹** にあたる段で、このアプリの中心です。予想を立てると、確かめるタスクが自動でできます。**予想の文と確かさは、保存したあとは書き換えられません**（あとから都合よく直す「後知恵」を防ぐため）。考えが変わったら、新しい予想を立てます。
画面：見立てのカードの「予想を立てる」欄。コード：`Prediction`／`predictions`。

**確かさ（たしかさ）**（子ども向け：どのくらい自信がある？）
予想が当たると思う度合いです。50〜95％を5刻みで選びます（50 は「五分五分」、95 は「ほぼ間違いない」）。
画面：予想を立てる欄・答え合わせの画面。コード：`predictions.confidence`・`config/suiri.php` の `confidence`。

**確かめる日**（子ども向け：見に行く日）
予想を確かめる日です（時刻は任意）。この日が来ると、今日の画面の「答え合わせ待ち」に出ます。
画面：予想を立てる欄・今日。コード：`predictions.check_on`・`check_at`。

**確かめるタスク**（子ども向け：見に行くこと）
予想から自動で作るタスクです。期日は確かめる日で、Google カレンダーとつないでいれば、専用カレンダーに「推理手帳：答え合わせの日」という題名で入ります（予想の文は送りません）。行の丸を押して済みにはできず、答え合わせを済ませると済みになります。
画面：今日・タスクの一覧（虫めがねの印と「答え合わせ」のボタン）。コード：`TaskKind::Verify`・`Task::answeredByPrediction()`。

**答え合わせ**（子ども向け：答え合わせ）
予想の結果を記録することです。答え合わせの画面では、最初に書いた予想の文・確かさ・書いた日時を必ず見せてから、結果を選んでもらいます。
画面：答え合わせの画面（`/predictions/{id}`）。コード：`predictions.result`。

**答え合わせ待ち**
確かめる日が今日までに来たのに、まだ結果のない予想です。その場で開いて答え合わせできます。
画面：今日の画面のいちばん上・事件の一覧の印。コード：`App\Queries\Today\DuePredictionsQuery`。

**当たり・外れ・どちらとも言えない・前提が崩れた**（子ども向け：あたり・はずれ・わからない・そもそもちがった）
答え合わせの4つの結果です。「前提が崩れた」は、予想のもとにした状況そのものが違っていて、当たり外れを言えないときです。「どちらとも言えない」と「前提が崩れた」は、確かさの答え合わせの当たり外れには数えず、新しい予想を立てることを勧めます。
画面：答え合わせの画面。コード：`PredictionResult`（`hit`／`miss`／`unclear`／`void`）。

**何を見落とした？**（子ども向け：どこでまちがえた？）
外れたときに選ぶ原因です。「手がかりが足りなかった・見立てが1つだけだった・思い込みがあった・確かめ方がずれていた・偶然」の5つ。選んだ外れはノーベリ帳に載ります。
画面：答え合わせの画面（外れを選んだとき）・ノーベリ帳。コード：`MissReason`。

**取り下げ**
予想を確かめるのをやめることです。予想の文と確かさは残し、まだ済んでいない確かめるタスクは消します。取り下げられるのは答え合わせ待ちの予想だけです。
画面：予想のカード。コード：`predictions.withdrawn_at`。

### 9-1-4. ふりかえりの言葉

**ふりかえり**（子ども向け：ふりかえり）
1週間（月曜日から）の振り返りです。記録した事件の数・見立てを2つ以上立てた割合・答え合わせの数と結果・考えを変えた回数・見積もりの答え合わせ・確かさの答え合わせを並べます。休んでも何も減らず、続けた日数や順位は出しません（罰や圧力で続けさせないため）。
画面：ふりかえり（`/review`）。コード：`App\Services\Review\WeeklyStats`。

**週の問い**
ふりかえりの画面で書く3つの問いです。「今週いちばん考えが変わった事件は？」「つまり？」「たとえば？」。「どうだった？」ではなく「なぜそうなった？」と説明する形にしています。
画面：ふりかえり。コード：`weekly_reflections`。

**確かさの答え合わせ**（子ども向け：自信と結果くらべ）
確かさの区間ごとに、予想が当たった割合と件数を出したものです（キャリブレーション）。たとえば「80％と思った予想が、実際に8割当たっているか」がわかります。件数が少ない区間は「まだ判断できない」と出します。
画面：ふりかえり。コード：`App\Services\Review\Calibration`。

**見積もりの答え合わせ（予想時間・かかった時間）**
タスクに「予想時間」と「かかった時間」を入れておくと、ふりかえりで予想と実際のずれを出します。予想時間を入れるときは、題名の似た過去のタスクの実績を近くに見せます（過去の実績を思い出すと、楽観しすぎる見積もりが減るという研究があるため）。
画面：タスクをくわしく作る・直す・タスクを済みにした直後の枠・ふりかえり。コード：`tasks.duration_minutes`・`actual_minutes`・`EstimateCheck`。

**ノーベリ帳（のーべりちょう）**（子ども向け：まちがいノート）
外れた予想と「何を見落とした？」の一覧です。名前はホームズの『黄色い顔』から来ています。推理が外れたあと、ホームズはワトソンに「わたしが自分の力を過信しているように見えたら、耳もとで『ノーベリ』とささやいてくれ」と頼みます。外れを隠さず、次の戒めにする帳面です。
画面：ノーベリ帳（`/norbury`）。

**屋根裏の棚（やねうらのたな）**（子ども向け：ぼくの図鑑・わたしの図鑑）
自分で選んでためる、一般則（つまり？）と具体例（たとえば？）です。名前はホームズの『緋色の研究』から来ています。ホームズは人の頭を小さな屋根裏部屋にたとえ、役に立つものを選んで並べておくべきだと言いました。事件を閉じるときに入れるほか、手で足すこともでき、予想を立てるときに棚の知識を選んで結べます。
画面：屋根裏の棚（`/attic`）・事件を閉じる欄・予想を立てる欄。コード：`AtticNote`／`attic_notes`。

**つまり？・たとえば？**
「つまり？」は、具体的な出来事から一般則を取り出す問い（抽象化）、「たとえば？」は、その一般則をほかの場面に当てはめる問い（具体化）です。
画面：事件を閉じる欄・屋根裏の棚・週の問い。コード：`attic_notes.rule`・`examples`。

### 9-1-5. 手引きの言葉

**手引き（てびき）**
ホームズの方法を学ぶ画面です。技能・名推理カード・練習メニュー・演繹と帰納とアブダクションの説明があります。
画面：手引き（`/guide`）。中身は `src/database/data/guide/*.json`。

**技能（ぎのう）**（子ども向け：わざ）
ホームズの思考の10の技能（S1〜S10）です。「見るのではなく観察する」「起きなかったことに気づく」「間違いを認めて直す」など。1つずつ、説明・原作の英語の短い引用・日常での練習の例・よくある失敗があります。
画面：手引きの技能（`/guide/skills/S1` など）。コード：`skills.json`。

**名推理カード**
原作の場面のカードです（23枚）。表には手がかりだけがあり、自分で推理を書いてから裏返すと、ホームズの推理・どう確かめたか・練習できる技能が出ます。ホームズが外した場面のカードも混ぜてあります。
画面：名推理カード（`/guide/scenes`）。コード：`scenes.json`・自分の推理は `scene_attempts`。

**練習メニュー・今日の練習**
技能ごとの練習です（11種。「17段チャレンジ」「吠えなかった犬」など）。選ぶと、そのメニューの問いかけが入った事件を作る画面に進みます。今日の画面には日替わりで1つ提案しますが、やらなくても何も起きません。
画面：練習メニュー（`/guide/practices`）・今日。コード：`practices.json`・`App\Services\Guide\DailyPractice`。

**演繹・帰納・アブダクション（えんえき・きのう・あぶだくしょん）**
3つの推論のしかたです。アブダクション（仮説形成）は、手がかりから「こうではないか」と見立てを立てること。演繹は「その見立てが正しいなら、〜が見えるはず」と予想を導くこと（アプリの「もしそうなら」と、合わない見立てを消す段）。帰納は、たくさんの例から一般則をまとめること（屋根裏の棚）。入力の負担を重くしないよう、この難しい言葉は手引きの画面にだけ出します。
画面：手引きの「演繹・帰納・アブダクション」（`/guide/reasoning`）。コード：`reasoning.json`。

### 9-1-6. タスクと今日の言葉

**今日（きょう）**
ログインした人の最初の画面です。上から、記録のきっかけ → 答え合わせ待ち → 今日の予定とタスク → 今日の練習 → 捜査中の事件、の順に並びます。
画面：今日（`/today`）。

**記録のきっかけ**
「いつ・何のあとに1つ書くか」を先に決めておく一文です（例「夕食のあとに、気になったことを1つ」）。設定の画面で決め、今日の画面のいちばん上に出ます（いつやるかを先に決めると続きやすい、という研究があるため）。
画面：設定・今日。コード：`users.cue`。

**タスク**（子ども向け：やること）
やることの単位です。題名・メモ・期日・開始時刻・予想時間を持てます。
画面：タスクの一覧・作る・直す・今日。コード：`Task`／`tasks`／`/tasks`。

**ふつう・確かめる**（子ども向け：ふつう・見に行く）
タスクの2つの種類です。自分で作るタスクはいつも「ふつう」で、「確かめる」は予想から自動でできます。
コード：`TaskKind`（`normal`／`verify`）。

**今日・これから・いつか・済み**
タスクの一覧の4つのタブです。今日は期日が今日まで（過ぎたものも）、これからは明日より先、いつかは期日なし、済みは済んだもの。
画面：タスクの一覧。コード：`App\Queries\Tasks\TaskListQuery`。

**すばやく足す欄**
題名と期日だけで、すぐにタスクを足す欄です。「くわしく」を押すと、入れた題名を持ってくわしく作る画面に進みます。
画面：今日・タスクの一覧。コード：`<x-task.quick-add>`。

**予定**（子ども向け：予定）
Google カレンダーの、自分の今日の予定です。読むだけで、題名と時刻だけを受け取り、5分だけ覚えて、記録としては保存しません。今日の画面で、今日のタスクと時刻順に混ぜて並べます。
画面：今日。コード：`App\Contracts\CalendarAgenda`。

### 9-1-7. 設定とカレンダーの言葉

**カレンダーとつなぐ**
Google カレンダーとの連携です（任意）。ログインとは別に、あとから追加の許可をもらいます。つなぐ前に、送る項目（タスクの題名・日時・戻るリンクと、どのタスクの予定かを見分ける番号だけ。番号はアプリの中の通し番号で、記録の中身ではない）・送らない項目・受け取る項目・Google は米国の会社であること、を1画面で見せます。
画面：カレンダーとつなぐ前の説明（`/calendar/connect`）・設定のカレンダーの枠。コード：`CalendarConnection`／`calendar_connections`。

**専用カレンダー「推理手帳」**
つないだときにアプリが Google カレンダーに作る、推理手帳だけのカレンダーです。期日のあるタスクはここにだけ書き、ふだん使うカレンダーには書きません。ここで予定を動かすと、15分ごとの取り込みでタスクの期日も動きます。予定を消すと、タスクとのつながりだけが外れます（タスクは消えません）。
コード：`calendar_connections.app_calendar_id`・`Jobs/PullCalendarChanges`。

**連携が切れました**
Google の許可が取り消された・切れたときに出る言葉です。設定の画面からつなぎ直します。切れている間も、アプリの保存は成功します。
画面：設定のカレンダーの枠。コード：`CalendarStatus::Broken`。

**データのダウンロード・退会**
設定の画面のいちばん下にあります。ダウンロードは、自分のデータをすべて JSON のファイルで保存します（Google の鍵は入りません）。退会は、確認の言葉「退会する」を入れると、その人の記録をすべて消し、Google の連携も取り消します。
画面：設定。コード：`Actions/Account/ExportUserData`・`DeleteAccount`。

## 9-2. 技術の言葉

### A〜Z

**Action（アクション・用事）**
1つの用事（記録を作る・直す・消す）を受け持つクラスです。このアプリの決まりで、1クラスに `handle()` を1つだけ持たせ、名前は「動詞＋名詞」にします（`MakePrediction`・`AddClue`）。たとえると、伝票どおりに1つの作業をする職人さんです。置き場所は `src/app/Actions/{機能}/`。

**ACM（AWS Certificate Manager）**
https に要る証明書（サイトの身分証）を、AWS で無料で作る係です。CloudFront に付ける証明書は、バージニア北部（us-east-1）で作る決まりがあります（[10章](10-deploy-aws.md) のステップ11）。

**API（エーピーアイ）・REST API**
プログラム同士がやりとりするための窓口です。お店の注文カウンターのように、決まった形で頼むと決まった形で返事が来ます。REST API は、住所（URL）と「取る・作る・置き換える・消す」（GET・POST・PUT・DELETE）の組み合わせで頼む形です。このアプリは、Google カレンダーの REST API を直接呼んでいます（`src/app/Services/Google/CalendarApi.php`）。

**artisan（アルチザン）**
Laravel に付いているコマンドの道具です。`php artisan migrate`（表を作る）、`php artisan test`（テスト）、`php artisan invite:add`（招待制のときの名簿に足す）のように使います。このアプリ独自のコマンドは `src/app/Console/Commands/` にあります。

**Blade（ブレード）・Blade コンポーネント**
Blade は、Laravel の画面のひな形の仕組みです。HTML の中に `{{ $case->title }}` のような穴をあけておき、データを流し込んで画面を作ります。ファイルは `src/resources/views/` にあり、名前は `.blade.php` で終わります。Blade コンポーネントは、画面の部品を名前つきで作り置きしたもので、`<x-ui.button>` のように書いて使います（このアプリには88個。[部品説明書](../design/components.md)）。たとえると、ひな形は書類の様式、部品は様式に押すスタンプです。

**cascadeOnDelete（カスケード・オン・デリート）**
親の行を消すと、それにつながる子の行も一緒に消える、表の設定です。たとえると、ファイルを捨てると中の書類も一緒に捨てられることです。このアプリでは、利用者を消す（退会）と、その人の事件・手がかり・予想などがまとめて消えます。

**Cache-Control（キャッシュ・コントロール）**
「この応答を、取り置いてよいか」をブラウザや途中の中継（CloudFront）に伝える札です。このアプリは、ログイン中の人への応答に `private, no-store`（どこにも取り置かない）を付けて、自分の記録が端末や CloudFront に残らないようにしています（`src/app/Http/Middleware/SecurityHeaders.php`）。

**Claude Code（クロード・コード）・CLAUDE.md**
Claude Code は、AI（Claude）がファイルを読み書きしたりコマンドを打ったりして、開発を手伝う道具です。`CLAUDE.md` は、Claude Code がこのフォルダで作業を始めるといつも読む案内です。動いているアプリが AI を呼ぶことはありません（ワトソンのひとことも決まった規則です）。

**CloudFront（クラウドフロント）**
AWS の、世界中に置かれた受付（配信の中継）です。このアプリの本番では、https を受け止めて、奥の EC2 に http で取り次ぎます。たとえると、お店の正面の受付カウンターで、鍵のかかった通信でお客さんを迎え、奥の事務所に用件を渡します。

**Composer（コンポーザー）**
PHP の部品（ライブラリ）を入れる道具です。`composer.json` に一覧を書き、`composer install` で `src/vendor/` に入れます。

**Contract（コントラクト・窓口の約束）**
「この窓口は、こういうメソッドを持つ」という約束（PHP のインターフェース）です。たとえると、電話の受け答えの決まりです。決まりどおりなら、本物の係でも練習相手（テスト用の偽物）でも差し替えられます。このアプリでは、Google カレンダーの窓口 `src/app/Contracts/CalendarApi.php` を、本番は本物・テストは偽物に結びます。

**cron（クーロン）**
「毎日3時に」「15分ごとに」のように、決まった時刻に仕事を動かす書き方です。このアプリでは、`src/routes/console.php` に書いた予定を、worker の箱の `schedule:work` が時刻を見て動かします。本番のバックアップも cron で毎日動かします（[10章](10-deploy-aws.md)）。

**CSRF（シーサーフ）対策**
ほかのサイトから勝手に「事件を消す」などの送信をさせる攻撃（なりすまし）を防ぐ仕組みです。フォームを送るたびに秘密の合言葉（トークン）を付け、合言葉が合わない送信は受け付けません。Blade の `@csrf` がこれにあたります。ページを開いたまま時間がたって合言葉が古くなると、「419 Page Expired」になります。

**CSS（シーエスエス）**
画面の見た目（色・大きさ・配置）を決める書き方です。このアプリでは Tailwind CSS を使い、元の決まりを `src/resources/css/app.css` に書いて、ビルドしたものを `src/public/build/` に置きます。

**Docker（ドッカー）・コンテナ・docker compose**
アプリを動かすのに必要なもの（PHP・nginx・MySQL など）を、箱（コンテナ）に入れて、どのパソコンでも同じように動かす道具です。docker compose は、いくつもの箱をまとめて動かす道具で、設計図は `docker-compose.yml`。このアプリの箱は `app`・`worker`・`web`・`db` の4つです。たとえると、引っ越し先でも中身がそのまま使える、家具つきの小部屋です。

**EC2（イーシーツー）・Elastic IP**
EC2 は、AWS で借りる1台のサーバー（インターネットの上のパソコン）です。このアプリの本番は、東京の EC2 の上で docker compose を動かします。Elastic IP は、そのサーバーの住所（IP アドレス）を固定するもので、サーバーを止めても住所が変わらないようにします。

**Eloquent（エロクアント）・モデル**
Laravel の、データベースの表をプログラムから扱う仕組みです。`$user->caseFiles()->where('status', 'open')->get()` のように書くと、SQL を書かなくても表から記録を取り出せます。表ごとのモデル（`src/app/Models/`）を通して使います。たとえると、帳簿の係で、「この人の捜査中の事件を出して」と頼むと帳簿から探してくれます。

**Enum（イーナム・列挙）**
決まった値だけを取る「種類」や「状態」の型です（例：事件の状態は 捜査中・解決・迷宮入り の3つだけ）。たとえると、書類に押せるハンコの一覧です。このアプリでは `src/app/Enums/` に置き、画面の言葉は `label()` で `config/suiri.php` から引きます。

**.env（ドット・エンブ）・APP_KEY**
秘密の値や、場所ごとに違う設定を書くファイルです。このアプリには、docker compose が読む直下の `.env` と、Laravel が読む `src/.env` の2枚があり、どちらも git に入れません。`APP_KEY` は `src/.env` に入る鍵で、ログインの記録と Google のトークンの暗号化に使います（一度決めたら変えない）。

**Factory（ファクトリー）**
テストで「それらしい記録」を1行で作るための型です（`Task::factory()->create()`）。置き場所は `src/database/factories/`。

**FormRequest（フォームリクエスト・形の検証）**
送られてきた入力の形（必須か・長さ・選べる値か）を、受付に届く前に確かめる Laravel のクラスです。たとえると、窓口の前で書類の書き漏れを見る係です。だめなら受付まで行かずに、エラーの文つきで元の画面に戻します。置き場所は `src/app/Http/Requests/{機能}/`。

**Git（ギット）・GitHub・コミット**
Git は、ファイルの変更の歴史を残す道具です。コミットは「ここまでの変更を1つの区切りとして記録する」ことで、たとえると、書類のコピーに日付を付けて綴じておくことです。GitHub は、その歴史をインターネットに置いておく場所です。本番は GitHub からコードを持ってきます。

**HTTP・HTTPS・HSTS**
HTTP は、ブラウザとサーバーがやりとりする決まりです。HTTPS は、その通信に鍵をかけたもの（途中で盗み見られない）。HSTS は「次からも必ず https で来てください」とブラウザに覚えてもらう札です。このアプリは https で届いたときと本番のときに HSTS を付けます。

**HTTP クライアント**
プログラムから、ほかのサーバーに HTTP で頼みごとを送る道具です。このアプリは、Laravel の HTTP クライアント（`Http::`）で Google のカレンダーとトークンの窓口を直接呼びます（公式の PHP ライブラリは使いません。中身が読める薄い部品のほうが学びやすいため）。テストでは `Http::fake()` で、決まった返事をする偽物に替えます。

**Job（ジョブ・後回しの仕事）**
画面を待たせないよう、後回しにする仕事です。たとえると、窓口で受けた用件を伝票にして箱に入れ、奥の係があとで片づけることです。このアプリでは、Google カレンダーへの書き出し・取り込みが Job です（`src/app/Jobs/`）。Job はキュー（下の「キュー」）に積まれ、worker の箱が順に片づけます。Google が止まっていれば、間を空けて試し直します。

**JSON（ジェイソン）**
`{ "名前": 値 }` や `[ 値, 値 ]` の形でデータを書く決まりです。このアプリでは、手引きの教材（`src/database/data/guide/*.json`）と、データのダウンロードのファイルに使っています。

**Laravel（ララベル）**
PHP でウェブアプリを作るための骨組み（フレームワーク）です。ログイン、データベース、画面の仕組みなど、よく使う部品がそろっています。このアプリは Laravel 13 で作っています。

**MVC（エムブイシー）・太らない MVC**
プログラムを3つの役目に分ける考え方です。M（モデル）はデータ、V（ビュー）は画面、C（コントローラー）は受付です。役目ごとにファイルが分かれているので、どこに何があるかがわかりやすくなります。このアプリはさらに、受付が太らない（長くならない）よう、検証は FormRequest、権限は Policy、用事は Action、外とのやりとりは Service、一覧は Query に分けています（「太らない MVC」。[3章](03-architecture.md)・`.claude/rules/architecture.md`）。

**MySQL（マイエスキューエル）**
データベースのソフトです。利用者・タスク・事件などの記録は、全部ここに保存されます。docker compose の `db` の箱で動いています（8.4）。

**nginx（エンジンエックス）**
ウェブサーバー（ブラウザからの頼みの受付係）です。CSS や JavaScript のファイルは自分で返し、PHP の処理が要る頼みだけを PHP-FPM に回します。`web` の箱で動き、設定は `infra/nginx/default.conf`。

**Node.js（ノード）・npm（エヌピーエム）**
JavaScript をパソコンの上で動かす道具（Node.js）と、その部品を入れる道具（npm）です。このアプリでは、画面の CSS と JavaScript をビルドするためだけに使います（`npm ci`・`npm run build`）。`app` の箱に入っています。

**OAuth（オーオース）**
「パスワードをこのアプリに渡さずに、Google で本人確認をしてもらう」ための決まりです。「Google でログイン」を押すと Google の画面に移り、本人確認がすむと、Google が「この人は○○です」という返事を持たせてアプリに戻してくれます。たとえると、店で会員証を作る代わりに、信頼できる役所の身分証を見せることです。カレンダー連携も同じ決まりで、追加の許可をもらいます。

**Observer（オブザーバー・見張り役）**
モデルが作られた・直された・消されたときに、自動で呼ばれる係です。たとえると、帳簿が書き換わるたびにベルが鳴り、係が動く仕掛けです。このアプリでは `TaskObserver` がタスクを見張り、カレンダーへの書き出しの Job を出します。おかげで、タスクの係は Google のことを知らなくてすみます。

**PHP（ピーエイチピー）・PHP-FPM**
PHP は、サーバーの中で動くプログラムの言葉で、Laravel は PHP で書かれています（このアプリは 8.4）。PHP-FPM は、nginx から回されてきた頼みを受けて PHP を動かす係で、`app` の箱で動いています。

**pint（ピント）**
PHP の書き方（字下げ・空白・並び）を自動でそろえる道具です（整形）。`vendor/bin/pint` で動かします。

**Policy（ポリシー・持ち主の確認）**
「この記録を、この人が見てよいか・直してよいか」を決める Laravel のクラスです。このアプリでは、すべて「持ち主だけ」（記録の `user_id` とログイン中の人が同じとき）です。ルートの `->can('update', 'case')` から呼ばれ、他人の記録なら 403 を返します。事件・手がかり・見立てには「捜査中の事件にだけ書き込める」`write` もあり、閉じた事件への書き込みも 403 にします。たとえると、貸し金庫の鍵の照合です。

**Query（クエリ・一覧の組み立て）**
画面に出す一覧や集計を組み立てて返す係です。書き込みはしません。たとえると、資料室の係で、「答え合わせ待ちを古い順に」と頼むとそろえて持ってきます。置き場所は `src/app/Queries/{機能}/`。

**Route 53（ルートフィフティースリー）**
AWS の住所録（DNS）です。「suiri.agi-japan.com はどこ？」と聞かれたら、CloudFront の場所を答えます。

**Seeder（シーダー）**
表に最初のデータを入れる係です。このアプリの `DemoSeeder` は、手元だけで見本のデータを入れます（[8章](08-operations.md) の 8-3）。

**Service（サービス）**
外（Google）とのやりとりや、画面や表を知らない計算を受け持つ係です。置き場所は `src/app/Services/{相手}/`。たとえると、外へ電話をかける係と、計算の係です。

**Service Provider（サービス・プロバイダー・準備係）**
アプリが起動するときに、係の結びつけや設定をする係です。このアプリでは、`AppServiceProvider`（回数制限・`{case}` の結びつけ・本番の https）と `CalendarServiceProvider`（カレンダーの窓口・見張り役の結びつけ）の2つです。

**Socialite（ソーシャライト）**
Laravel の公式の部品で、Google などでログインする（OAuth の）手順をまとめて引き受けてくれます。このアプリでは `GoogleLoginController` と、カレンダーの許可をもらう `ConnectCalendarController` から使っています。

**sqlite（エスキューライト）**
ファイル1つ（やメモリの中）で動く小さなデータベースです。このアプリのテストは、sqlite のメモリの中で動くので、毎回まっさらな表で始まり、手元の MySQL の記録には触りません。

**SQL（エスキューエル）**
データベースに「この記録を取り出して」「これを保存して」と頼むための言葉です。このアプリでは、ほとんど Eloquent が代わりに書いてくれます。

**SVG（エスブイジー）**
線や図形の座標で描く画像の形式です。拡大してもぼやけません。画面の線画のアイコン・ふりかえりの確かさの図と、この解説書の図に使っています。

**Tailwind CSS（テイルウィンド）**
`class="mt-4 text-lg font-bold"` のように、「上に余白」「文字を大きく」「太字」といった小さな部品の名前を HTML に並べて見た目を作る CSS の道具です（このアプリは v4）。色の名前（`bg-paper`・`text-ink` など）は `src/resources/css/app.css` で決めています。

**throttle（スロットル・回数制限）**
同じ人が短い間に送れる回数の上限です。連打・総当たり・自動化の対策です。このアプリでは種類ごとに名前を付けています：`auth`（ログイン。1分に10回）・`writes`（記録を書く。60回）・`account`（データのダウンロードと退会。5回）・`calendar`（カレンダーとつなぐ・やめる。10回）。

**Vite（ヴィート）・ビルド**
CSS や JavaScript の元のファイルをまとめて、ブラウザ向けのファイルを作る（ビルドする）道具です。設定は `src/vite.config.js`。Blade の `@vite` が、できたファイルを読み込みます。たとえると、原稿を印刷所で本の形に刷ることで、原稿を直したら刷り直し（`npm run build`）が要ります。

**VPC（ブイピーシー）・サブネット・セキュリティグループ**
VPC は、AWS の中に作る自分専用のネットワーク（土地）です。サブネットはその中の区画、セキュリティグループはサーバーの門番（どこからどの番号に入ってよいか）です。このアプリの本番では、80番に入れるのを CloudFront からだけに絞っています（[10章](10-deploy-aws.md)）。

**worker（ワーカー）・queue:work・schedule:work**
worker は、このアプリの4つの箱の1つで、2つの係が一緒に動いています。`schedule:work` は時計を見て、決まった時刻の仕事（15分ごとのカレンダーの取り込み・5分ごとのキャッシュの掃除）を積む係。`queue:work` はキューに積まれた Job を順に片づける係です。worker は起動したときのコードで動き続けるので、コードを変えたら `docker compose restart worker` が要ります。

### あ行

**アクセストークン・リフレッシュトークン**
どちらも Google の鍵（トークン）です。アクセストークンは、Google に頼みごとをするときに見せる短い期限（1時間ほど）の通行証。リフレッシュトークンは、期限が切れたアクセストークンを取り直すための長持ちの引換券です。たとえると、アクセストークンは日帰りの入館証、リフレッシュトークンは入館証を発行してもらうための会員カードです。このアプリは両方を暗号化して保存し（`calendar_connections`）、JSON やログには出しません。期限が近づくと先に取り直します（`GoogleTokens`）。

**暗号化（あんごうか）**
鍵がないと読めない形に変えて保存することです。このアプリでは、Google のトークンを Eloquent の `encrypted`（暗号化して保存する列の型）で保存しています。鍵は `src/.env` の `APP_KEY` です。

**移行（いこう・マイグレーション）**
データベースの表を作る・直す手順を、1ファイル1つずつ書いたものです（`src/database/migrations/`）。`php artisan migrate` で、まだ動かしていないものだけが番号の順に動きます。たとえると、棚の組み立て説明書です。本番で一度動いた移行は二度と動かないので、表を変えるときは今あるファイルを書き換えず、新しい移行を足します。表を消して作り直すコマンドは、記録が全部消えるので使いません。

**インターフェース**
→「Contract」。

### か行

**キャッシュ・作り置き**
一度作った結果を取っておき、次は作らずに使うことです。たとえると、よく聞かれる質問の答えをメモしておくことです。このアプリでは、手引きの教材の読み込みと、今日の予定（5分だけ）をキャッシュします。キャッシュは DB の `cache` の表に置き、期限の過ぎた行は5分ごとに `cache:prune-expired` が消します。また `php artisan optimize` は、設定・住所の表・画面のひな形を作り置きしてアプリを速くします（`src/.env` を直したら作り直しが要ります）。

**キュー**
後回しの仕事（Job）を積んでおく列です。たとえると、伝票を入れておく箱です。このアプリのキューは DB の `jobs` の表で、worker の `queue:work` が順に取り出して片づけます。失敗した仕事は `failed_jobs` に残ります。

**クッキー（Cookie）・セッション**
セッションは、「この人はログインしている」といった、1人ぶんの状態をサーバーが覚えておく仕組みです。クッキーは、ブラウザが持っておく小さな札で、セッションの番号が書いてあります。たとえると、クロークの番号札で、札を見せると預けた荷物（ログインの状態）が出てきます。このアプリのセッションは DB の `sessions` の表です。

**コントローラー（受付）**
画面からの頼みを受け取り、用事（Action）や一覧の組み立て（Query）を呼んで、結果の画面か転送を返す係です（MVC の C）。このアプリでは薄く保ち、検証も DB の組み立てもしません（`bin/check` が止めます）。置き場所は `src/app/Http/Controllers/{機能}/`。

### さ行

**差分の取り込み（sync token）**
前回の取り込みのあとに変わった予定だけを Google から受け取る仕組みです。Google から「前回はここまで」の印（sync token）をもらって保存しておき、次はその印を見せます。印が古くなると、Google が 410 を返すので、全件を読み直します。このアプリの15分ごとの取り込み（`ApplyCalendarChanges`）で使います。

**スコープ**
「このアプリに、Google のどこまでを許すか」の範囲です。たとえると、合鍵を渡すときに「玄関だけ」「物置だけ」と決めることです。このアプリは、ログインでは名前・メール・アイコン・ID だけ（`openid`・`email`・`profile`）、カレンダーでは「アプリが作ったカレンダーに書く」（`calendar.app.created`）と「自分の予定を読む」（`calendar.events.owned.readonly`）だけを求めます。

**セキュリティのヘッダ（守りの札）**
応答に付けて、ブラウザに「この画面をほかのサイトの枠に入れさせない」「ファイルの種類を推測させない」などを伝える札です。このアプリは `SecurityHeaders` がすべての画面に付けます。

### た行

**段階的な許可**
最初は最小限の許可（ログインだけ）をもらい、機能を使うときになってから追加の許可（カレンダー）をもらうやり方です。たとえると、入館のときは受付だけ通し、会議室を使うときに改めて鍵を借りることです。

**テスト（Feature・Unit）**
アプリが決まりどおりに動くかを、機械で確かめるプログラムです。Feature テストは、住所を実際に開いたり送ったりして確かめ、Unit テストは1つの係だけを確かめます。置き場所は `src/tests/`。

**トランザクション**
いくつかの書き込みを「全部成功するか、全部なかったことにするか」のひとまとまりにすることです。たとえると、振り込みで「引き出し」と「入金」を必ずセットで行うことです。このアプリでは、予想と確かめるタスクを一緒に作るときなどに使います（`DB::transaction`）。

**トークン**
→「アクセストークン・リフレッシュトークン」。CSRF の合言葉もトークンと呼びます（→「CSRF 対策」）。

### な行

**偽物（にせもの・fake）**
テストのときに、本物の代わりに使う練習相手です。決まった返事をし、何を頼まれたかを覚えておきます。このアプリのテストは、Google ログインを決まった返事をする偽物（`Socialite::shouldReceive(...)`）、カレンダーを `FakeCalendarApi`、HTTP を `Http::fake()`、キューを `Queue::fake()` に替え、本物の Google には届かないようにしています。

### は行

**バックアップ**
記録の写しを取っておくことです。本番では、毎日1回 DB を丸ごとファイルに書き出し、7日より古いものを消します（プライバシーポリシーの数字と同じ。[10章](10-deploy-aws.md)）。

**番号つきの応答（403・404・419・500 など）**
サーバーが返す応答の番号です。200 はうまくいった、302 は別の住所へ移って、403 は見てはいけない（このアプリでは他人の記録）、404 は見つからない、419 は送信の合言葉が古い（CSRF）、500 はサーバーの中のエラーです。

**フック**
「何かが起きたら、決まった処理を呼ぶ」仕組みです。たとえると、自動ドアのセンサーです。このアプリでは、AI がコマンドを打つ前・ファイルを直した直後・作業を終える前に動く Claude Code のフック（`.claude/settings.json`）と、コミットの前に動く git のフック（`.githooks/pre-commit`）を使い、決まりのチェックを自動で動かします（[8章](08-operations.md) の 8-6）。

### ま行

**ミドルウェア**
受付に届く前（や、画面を返す前）に、すべての頼みに共通の確かめや札付けをする係です。たとえると、建物の入口の関所です。このアプリでは、ログインしているか（`auth`）・同意したか（`agreed`）・回数制限（`throttle`）・守りの札（`SecurityHeaders`）がミドルウェアです。

### ら行

**ルート・ルート名**
「この住所（URL）とこのやり方（GET・POST など）で来たら、どの受付に渡すか」を書いた表の1行です。たとえると、建物の案内板の「〇〇の用は3階の窓口へ」です。ルート名は、その行に付けた名前（`cases.show` など）で、画面の中のリンクは住所を直書きせずにこの名前から作ります。このアプリの住所の表は `src/routes/web/{機能}.php`。住所の `{case}` は、AppServiceProvider で事件（`CaseFile`）に結びつけてあり、受付には事件そのものが渡ります。

**ログ**
アプリや箱が書く、出来事やエラーの記録です。このアプリは、ログに入力の本文（題名・手がかりなど）を書かない決まりです（id・種類・件数・エラーの種類だけ）。見方は [8章](08-operations.md) の 8-9。
