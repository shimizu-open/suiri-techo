11守りの仕組み（他人の記録・回数・ニセの送信・ヘッダ・ログ・退会）

推理手帳を使う人として、自分の記録をほかの人に見られたり、勝手に書き換えられたり、ログに残されたりしたくない。やめるときは全部消してほしい。だから、アプリがどこでどう守っているかを知りたい。

この章で追う道筋：①他人の記録 ->can('write', 'case') → SubstituteBindings（{case} を行に）→ Authorize → Gate → CaseFilePolicy（WritesOpenCase・OwnerOnly）→ 403（閉じた事件も 403） ／ 一覧は $user->tasks() から始める ／ CopiesOwnerFromCase ②回数制限 throttle:writes → ThrottleRequests → cache 表 → 429 ③ニセの送信 @csrf → PreventRequestForgery → 419 ④守りの札 SecurityHeaders ⑤箱の入口（nginx・PHP） ⑥ログに本文を書かない ⑦GET /settings/export → ExportUserData ⑧DELETE /account → DeleteAccountRequest → DeleteAccount（カレンダーの許可の取り消し → sessions・invitations・AI の通行証・users を消す → 子の表もまとめて消える）

  1. サーバー

    守りは何枚も重ねてある（この章の地図）

    推理手帳が持つのは、本人の観察・考え・予想という、外に出したくない記録です。そこで「1か所で守れば安心」ではなく、何枚もの守りを重ねています。どれか1枚がすり抜けられても、次の1枚で止まるようにするためです。

    たとえると銀行の貸金庫です。建物の入口に警備員（箱の入口の守り）、窓口で本人確認（ログイン）、混雑したら整理券（回数制限）、書類の偽造チェック（ニセの送信の確かめ）、金庫の扉は持ち主の鍵でしか開かない（Policy）。帰りの封筒には「中身を見せないで」と書いてあり（守りの札）、警備の日誌には客の書類の中身を書かない（ログ）。解約したら金庫の中身をすべて処分する（退会）。
    守り何を防ぐかどこで
    持ち主だけ（Policy・一覧の絞り込み）他人の記録を見る・直す・消す->can()・app/Policies・app/Queries
    回数制限連打・総当たり・機械での大量の送信throttle:…・AppServiceProvider
    ニセの送信の確かめ（CSRF）ほかのサイトから勝手に送らせる@csrf・PreventRequestForgery
    守りの札（ヘッダ）枠への埋め込み・取り置き・種類の取り違えSecurityHeaders
    箱の入口ファイルを送る形を狙った攻撃・隠しファイルの読み出しinfra/nginx・infra/php
    ログに本文を書かない記録がログから漏れるLog:: の書き方・bin/check
    書き出し・退会自分の記録を持ち出せない・消せないExportUserData・DeleteAccount

    ログインの守り（Google・招待制のときの招待・同意・セッションの作り直し）は 1章、カレンダーの鍵の暗号化と「送るのは題名と日時とリンクと番号だけ」は 9章、予想の文と確かさを書き換えさせない決まりは 6章 で追いました。ChatGPT・Claude の窓口の守り（通行証・読むだけ・仕事の場面と他人の記録を見せない）は 13章 で追います。

  2. サーバー

    住所の表で ->can('write', 'case') と書く

    例として、ほかの人が「自分の事件ではない事件」に手がかりを足そうとした場合を追います。手がかりを足す住所は、こう書いてあります。

    src/routes/web/cases.php
    Route::get('/cases/{case}', [CaseController::class, 'show'])->can('view', 'case')->name('cases.show');
// …（省略）…
// 手がかり（閉じた事件には足せない・直せない・消せない）
Route::post('/cases/{case}/clues', [ClueController::class, 'store'])->can('write', 'case')->name('clues.store');

    ->can('write', 'case') は「住所の穴 {case} の記録に対して、ログイン中の人が write（書き込む）をしてよいか確かめてから通す」という意味です。write は推理手帳が足した能力の名前で、「持ち主で、しかも事件が捜査中か」を確かめます（見る・直す・消すの view・update・delete は持ち主かだけ）。Laravel 本体では、これは can:write,case という見張り役を1つ足すだけの書き方です。

    src/vendor/laravel/framework/src/Illuminate/Routing/Route.php
    public function can($ability, $models = [])
{
    $ability = enum_value($ability);

    return empty($models)
        ? $this->middleware(['can:'.$ability])
        : $this->middleware(['can:'.$ability.','.implode(',', Arr::wrap($models))]);
}

    Laravel に並べ替えさせた、この住所の見張り役の実際の順番は次のとおりです。

    1. EncryptCookies → AddQueuedCookiesToResponse → StartSession → ShareErrorsFromSession
    2. PreventRequestForgery：ニセの送信でないか（このあとのステップ）
    3. Authenticate（auth）：ログインしているか（1章）
    4. ThrottleRequests:writes：回数（このあとのステップ）
    5. SubstituteBindings：{case} を事件の行に替える
    6. EnsureAgreed（agreed）：同意したか（1章）
    7. Authorize:write,case：持ち主で、事件が捜査中か
    ここが大事持ち主の確かめ（Authorize）は、SubstituteBindings よりあとに動きます。穴の中身が「12」という文字のままでは、誰の事件か分からないからです。Laravel の並べ替えの表がこの順番を決めています。

  6. サーバー

    OwnerOnly：記録の user_id とログイン中の人の id を比べる

    src/app/Policies/Concerns/OwnerOnly.php
    /** 直してよいか（持ち主だけ） */
public function update(User $user, Model $record): bool
{
    return $this->owns($user, $record);
}
// …（省略）…
/** 記録の持ち主がこの人かを返す（型をそろえて比べる） */
protected function owns(User $user, Model $record): bool
{
    return (int) $record->getAttribute('user_id') === (int) $user->getKey();
}

    view（見る）・update（直す）・delete（消す）の3つとも、答えは同じ owns です。事件の user_id と、ログイン中の人の id が同じときだけ true（してよい）。(int) で数にそろえてから ===（型まで同じか）で比べるので、「'12' と 12」のような取り違えも起きません。

    運営者だけが通れる裏口のような決まりはありません。運営者のアカウントでも、他人の記録は見られません。

  7. サーバー

    WritesOpenCase：持ち主かを先に見て、次に事件が捜査中かを見る

    src/app/Policies/Concerns/WritesOpenCase.php
    /** 書き込んでよいか（持ち主で、事件が捜査中のときだけ）。閉じた事件なら「開き直してください」の文つきで 403 にする */
public function write(User $user, Model $record): Response
{
    // 持ち主でなければ断る（他人の記録は、閉じているかどうかを知らせずに 403）
    if (! $this->owns($user, $record)) {
        return Response::deny();
    }

    $case = $record instanceof CaseFile ? $record : $record->getAttribute('caseFile');

    // 事件が捜査中なら通し、閉じていれば開き直すよう伝えて断る
    return $case->isOpen() ? Response::allow() : Response::deny(config('suiri.cases.closed_message'));
}

    まず、上の owns で持ち主かを確かめます。他人なら、閉じているかどうかを知らせない、ふつうの 403 にします（ほかの人の事件の様子を漏らさないため）。持ち主なら、手がかりや見立てのときはその事件（caseFile）を取り出し、捜査中（isOpen()）なら通します。閉じた（解決・迷宮入り）事件なら、config/suiri.php の cases.closed_message「この事件は閉じています。書き足すときは、事件を開き直してください。」を付けて断ります。

    閉じた事件の画面には、手がかり・見立て・○×・予想を書く欄やボタンを出していません。それでも受付で断るのは、閉じる前に開いていた古いタブや、手で作った送信が通ってしまわないようにするためです。答え合わせと取り下げは update（持ち主かだけ）のままなので、閉じた事件でも、待っている予想の結果を書いたり取り下げたりできます。

  12. 見張り役

    回数制限：名前ごとに数え方を決める

    回数制限は、記録を書く住所・ログイン・退会・カレンダー・AI の窓口にだけ付けています。数え方は AppServiceProvider に名前つきで4つ、AI の窓口の分は AiConnectServiceProvider に3つあります。

    src/app/Providers/AppServiceProvider.php
    // 回数制限（連打・総当たり・自動化の対策）。種類ごとに別々に数える。ルートでは throttle:auth のように名前で使う
$by = fn (Request $request) => $request->user()?->id ?? $request->ip(); // ログイン中は人ごと、ログイン前は IP ごとに数える
RateLimiter::for('auth', fn (Request $r) => Limit::perMinute(10)->by($r->ip()));       // Google へのログイン・戻り
RateLimiter::for('writes', fn (Request $r) => Limit::perMinute(60)->by($by($r)));      // 記録を書く（作る・直す・消す）
RateLimiter::for('account', fn (Request $r) => Limit::perMinute(5)->by($by($r)));      // データのダウンロード・退会
RateLimiter::for('calendar', fn (Request $r) => Limit::perMinute(10)->by($by($r)));    // カレンダーとつなぐ・やめる
    src/app/Providers/AiConnectServiceProvider.php
    // AI の会社のサーバーの IP は、その会社の利用者みんなで同じなので、IP ごとの数はきつくしすぎない
RateLimiter::for('mcp', fn (Request $r) => Limit::perMinute(120)->by($r->user()?->id ?? $r->ip()));  // 窓口の道具を呼ぶ
RateLimiter::for('oauth', fn (Request $r) => Limit::perMinute(60)->by($r->ip()));                    // 案内・通行証の受け渡し
RateLimiter::for('oauth-register', fn (Request $r) => Limit::perHour(20)->by($r->ip()));             // AI の自己登録
    名前上限誰の回数として数えるか付けている住所
    auth1分に10回IP アドレスGoogle へ送り出す・戻る（1章）
    writes1分に60回ログイン中の人タスク・事件・手がかり・見立て・予想・棚・ふりかえり・設定・同意などの書き込み
    account1分に5回ログイン中の人データのダウンロード・退会
    calendar1分に10回ログイン中の人カレンダーとつなぐ・戻る・やめる（9章）
    mcp1分に120回通行証の持ち主AI の窓口 POST /mcp（13章）
    oauth1分に60回IP アドレス通行証の出し方の案内・自己登録・通行証の受け渡し（13章）
    oauth-register1時間に20回IP アドレスAI の自己登録 POST /oauth/register（13章）

    名前を分けているのは、別の種類の操作が同じ数に混ざらないようにするためです。たとえば手がかりをたくさん足していても、退会の数は増えません。ログイン前の auth は IP で数えるので、本番で本当のアクセス元の IP が分かるよう、bootstrap/app.php の trustProxies(at: '*') で CloudFront の付ける X-Forwarded-For を信じています（EC2 には CloudFront からしか届かない前提）。

    ThrottleRequests：先に数を確かめ、1足してから先へ進める

    src/vendor/laravel/framework/src/Illuminate/Routing/Middleware/ThrottleRequests.php
    protected function handleRequest($request, Closure $next, array $limits)
{
    foreach ($limits as $limit) {
        if ($this->limiter->tooManyAttempts($limit->key, $limit->maxAttempts)) {
            throw $this->buildException($request, $limit->key, $limit->maxAttempts, $limit->responseCallback);
        }
    }

    foreach ($limits as $limit) {
        if (! $limit->afterCallback) {
            $this->limiter->hit($limit->key, $limit->decaySeconds);
        }
    }

    $response = $next($request);
    1. もう上限に届いていれば（tooManyAttempts）、先へ進めずに「429（多すぎる）」を投げます。画面は Laravel の既定の 429 のページです。
    2. 届いていなければ hit で1足して、次の見張り役へ進めます。返事には X-RateLimit-Limit（上限）と X-RateLimit-Remaining（残り）が付きます。

    数を覚えておく鍵は「名前＋誰か」を md5 で記号の並びにしたものです。

    src/vendor/laravel/framework/src/Illuminate/Routing/Middleware/ThrottleRequests.php
    'key' => self::$shouldHashKeys ? md5($limiterName.$limit->key) : $limiterName.':'.$limit->key,
    このとき動くデータ
    • 読む・書く：cache 表（.env の CACHE_STORE=database）。鍵の行に回数、:timer の行にその1分の終わりの時刻。1分たつと数え直し
    ここが大事回数制限は、Policy より前（SubstituteBindings より前）で動きます。他人の事件の番号を次々に試すような送り方は、403 になる前に回数で止まります。
  14. ブラウザ

    ニセの送信の確かめ（CSRF）①：フォームに合言葉を入れておく

    CSRF（クロスサイト・リクエスト・フォージェリ）は、悪いサイトに置いたフォームから、推理手帳へ勝手に送信させる攻撃です。ブラウザはそのサイトの Cookie を自動で付けて送るので、利用者が推理手帳にログインしたままだと、本人の操作として届いてしまいます。

    たとえると銀行の窓口で、通帳（Cookie）だけでなく、その日に窓口で渡された整理券の番号（合言葉）も一緒に出さないと受け付けない、という決まりです。悪いサイトは通帳は勝手に使わせられても、整理券の番号は知りません。

    推理手帳のフォームには、どれも @csrf が入っています。

    src/resources/views/components/ui/confirm.blade.php
    <form method="POST" action="{{ $action }}" class="mt-3">
  @csrf
  @method($method)
    src/vendor/laravel/framework/src/Illuminate/View/Compilers/Concerns/CompilesHelpers.php
    protected function compileCsrf()
{
    return '<?php echo csrf_field(); ?>';
}

    @csrf は <input type="hidden" name="_token" value="（この人の箱にある合言葉）"> に置き換わります。合言葉は、その人の預かり箱（セッション）に入っている、でたらめな40文字です。@method('DELETE') は隠し欄 _method=DELETE で、フォームでは送れない DELETE を表します。

  15. 見張り役

    ニセの送信の確かめ②：PreventRequestForgery が照らし合わせる → だめなら 419

    src/vendor/laravel/framework/src/Illuminate/Foundation/Http/Middleware/PreventRequestForgery.php
    public function handle($request, Closure $next)
{
    if (
        $this->isReading($request) ||
        $this->runningUnitTests() ||
        $this->inExceptArray($request) ||
        $this->hasValidOrigin($request) ||
        $this->tokensMatch($request)
    ) {
        return tap($next($request), function ($response) use ($request) {
            if ($this->shouldAddXsrfTokenCookie()) {
                $this->addCookieToResponse($request, $response);
            }
        });
    }

    throw new TokenMismatchException('CSRF token mismatch.');
}

    次のどれか1つに当たれば通します。

    • isReading：GET・HEAD・OPTIONS（読むだけで、記録を変えない頼み）。だから記録を変える操作は、必ず POST・PATCH・PUT・DELETE にしています（ログアウトも POST。1章）。
    • hasValidOrigin：ブラウザが付ける Sec-Fetch-Site が same-origin（同じサイトの画面から送った）なら通す。
    • tokensMatch：送られた _token（または X-CSRF-TOKEN のヘッダ）が、預かり箱の合言葉と同じか。
      src/vendor/laravel/framework/src/Illuminate/Foundation/Http/Middleware/PreventRequestForgery.php
      protected function tokensMatch($request)
{
    $token = $this->getTokenFromRequest($request);

    return is_string($request->session()->token()) &&
           is_string($token) &&
           hash_equals($request->session()->token(), $token);
}

    どれにも当たらなければ TokenMismatchException になり、例外の係が「419」に変えます（$e instanceof TokenMismatchException => new HttpException(419, …)）。手元で合言葉なしに POST /logout を送ると、419 が返りました。ログアウトや退会のあとに合言葉を作り直す（regenerateToken()）のは、古い合言葉を使えなくするためです。

    AI の窓口（POST /mcp）だけは web のひとまとまりの外にあり、この合言葉を使いません。人のブラウザではなく AI の会社のサーバーが送ってくるからです。代わりに、毎回の通行証（auth:api）と、よその画面からの呼び出しを断る見張り役 RejectForeignOrigin で守ります（13章）。

  16. 見張り役

    守りの札 SecurityHeaders：どの返事にもヘッダを足す

    この見張り役は、bootstrap/app.php の $middleware->append(SecurityHeaders::class) で、全部のお願いに付けています（0章）。多くの見張り役は先に確かめてから先へ進めますが、この見張り役は先に受付に画面を作らせ、できた返事にヘッダ（返事に付ける札）を足します。

    src/app/Http/Middleware/SecurityHeaders.php
    public function handle(Request $request, Closure $next): Response
{
    $response = $next($request);

    $headers = [
        // ファイルの種類をブラウザに推測させない
        'X-Content-Type-Options' => 'nosniff',
        // ほかのサイトの枠（iframe）の中に、この画面を表示させない（クリックをだます攻撃の対策）
        'X-Frame-Options' => 'SAMEORIGIN',
        // ほかのサイトへ移るとき、URL の詳しい部分を渡さない
        'Referrer-Policy' => 'strict-origin-when-cross-origin',
        // カメラ・マイク・位置情報などは使わない
        'Permissions-Policy' => 'camera=(), microphone=(), geolocation=(), payment=(), usb=()',
    ];

    // 「次からも必ず https で来て」と伝える。https で届いたときと本番のとき（本番は CloudFront の https からしか入れないが、
    // CloudFront からサーバーまでは http なので、アプリからは https に見えない）。ローカルの http では付けない
    if ($request->isSecure() || app()->isProduction()) {
        $headers['Strict-Transport-Security'] = 'max-age=31536000; includeSubDomains'; // 1年間覚えさせる
    }

    // 決めた札を1つずつ取り出して、応答に付ける
    foreach ($headers as $name => $value) {
        // まだ付いていない札だけ付ける。画面ごとに先に付けた値は上書きしない
        if (! $response->headers->has($name)) {
            $response->headers->set($name, $value);
        }
    }

    // ログイン中の人への応答なら、自分の記録が端末や CloudFront に残らないよう、取り置きを禁じる
    if ($request->hasSession() && $request->user() !== null) {
        $response->headers->set('Cache-Control', 'private, no-store');
    }

    return $response;
}
    • X-Content-Type-Options: nosniff：ブラウザに「中身を見てファイルの種類を推測する」ことをさせない（文字のファイルをプログラムとして動かされない）。
    • X-Frame-Options: SAMEORIGIN：ほかのサイトが推理手帳の画面を透明な枠に入れ、ボタンを押させる攻撃を防ぐ。
    • Referrer-Policy：ほかのサイトへのリンクを押したとき、/cases/12 のような住所の詳しい部分を相手に渡さない。
    • Permissions-Policy：カメラ・マイク・位置情報・支払い・USB を使わないと宣言する。
    • Strict-Transport-Security（HSTS）：「1年間は必ず https で来て」とブラウザに覚えさせる。本番だけ。
    • Cache-Control: private, no-store：ログイン中の人への返事は、ブラウザにも CloudFront にも取り置かせない。共有の端末で「戻る」を押して前の人の記録が出る、CloudFront が別の人に同じ画面を返す、を防ぐ。

    手元で /about の返事を見ると、X-Content-Type-Options: nosniff・X-Frame-Options: SAMEORIGIN・Referrer-Policy・Permissions-Policy が付いていました（ローカルの http なので HSTS はなし）。テストは src/tests/Feature/Legal/PublicPagesTest.php です。

    ログには id とエラーの種類だけを書く

    ログは、サーバーが「いつ何が起きたか」を書き残す日誌です。うまくいかなかったことを後で調べるのに使いますが、日誌に題名や本文を書くと、記録が日誌から漏れる道ができます。そこで推理手帳のログには、id・種類・件数・エラーの種類だけを書きます。

    src/app/Http/Controllers/Auth/GoogleLoginController.php

    class_basename($e) は、エラーのクラスの名前の最後の部分（たとえば ConnectionException）だけを取り出します。エラーの文（$e->getMessage()）には、Google の返事の中身やメールアドレスが入ることがあるので書きません。

    この決まりは機械でも確かめています。bin/check の決まりの表に、src/app/ の中で Log:: と本文の列（title・body・statement・memo など）や $request->all() が同じ行にあれば止める、という決まりがあります。

/** AI とつないだ許可の行（通行証・更新の札・引換券・デバイスの番号）を、その人の分だけ消す */
private function forgetAiGrants(User $user): void
{
    $tokenIds = Passport::token()->newQuery()->where('user_id', $user->id)->pluck('id');
    Passport::refreshToken()->newQuery()->whereIn('access_token_id', $tokenIds)->delete();
    Passport::token()->newQuery()->where('user_id', $user->id)->delete();
    Passport::authCode()->newQuery()->where('user_id', $user->id)->delete();
    Passport::deviceCode()->newQuery()->where('user_id', $user->id)->delete();
}

    3. 招待の行（招待制のときに名簿に入れた人。ある場合）：メールアドレスを持っているので消します（招待制のままもう一度使うなら、運営者が招待し直す）。
    4. ChatGPT・Claude とつないだ許可（forgetAiGrants）：通行証（oauth_access_tokens）・更新の札（oauth_refresh_tokens）・引換券（oauth_auth_codes）・デバイスの番号（oauth_device_codes）の、この人の行を消します。これらは Passport の表で、「親を消したら子も消える」が付いていないので、自分で消します。更新の札は user_id を持たず、通行証の番号（access_token_id）で結びついているので、先にこの人の通行証の番号を集めてから消します。AI のサービスの登録の行（oauth_clients）は利用者の記録ではないので残します（だれにも使われなければ、毎日の ai:prune-apps が消します。13章）。
    5. 利用者の行：$user->delete()。これで子の表もまとめて消えます（次のステップ）。

    2〜5は1つのトランザクションなので、途中で失敗すれば全部なかったことになり、「半分だけ消えた」状態は残りません。

  24. データベース

    子の表は cascadeOnDelete でまとめて消える（物理削除）

    利用者の記録を持つ表は、どれも user_id を users に結び、cascadeOnDelete()（親の行が消えたら、自分の行も消す）を付けています。

    src/database/migrations/2026_10_31_000009_create_tasks_table.php
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    src/database/migrations/2026_10_31_000002_create_case_files_table.php
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();

    users の1行を消すと、データベース（MySQL）が自分で、タスク・事件・手がかり・見立て・○×・見立ての状態を変えた記録・予想・屋根裏の棚・週のふりかえり・名推理カードへの推理・閉じたひとこと・カレンダー連携の行を消します。「消した印を付けて残す」のではなく、行そのものを消す物理削除です。

    ここが大事sessions と Passport の表の user_id は、Laravel の決まった形の表で users に結びついていません（sessions は $table->foreignId('user_id')->nullable()->index(); だけ）。だから cascadeOnDelete では消えず、用事 DeleteAccount が自分で消しています。テスト test_delete_removes_every_row_of_the_user が、退会のあとにこの人の行がどの表にも残っていないことを確かめています。
    このとき動くデータ
    • 消す：calendar_connections（先に。Google には revoke を送る）
    • 消す：sessions（この人の全端末）・invitations（この人のメール）・oauth_access_tokens・oauth_refresh_tokens・oauth_auth_codes・oauth_device_codes（この人の分）・users（この人）
    • 消える（cascade）：tasks・case_files・clues・hypotheses・clue_hypothesis・hypothesis_status_logs・predictions・attic_notes・weekly_reflections・scene_attempts・dismissed_hints
この章のまとめ
  1. 他人の記録：->can('write', 'case') → SubstituteBindings が行に替える（ここでは誰のものでも読める）→ Authorize → 門番 Gate が名前の決まりで CaseFilePolicy を見つける → WritesOpenCase が OwnerOnly の owns で user_id を比べ、続けて事件が捜査中かを見る → ちがえば・閉じていれば 403 で、受付まで届かない。
  2. 子の記録にも user_id を写す（CopiesOwnerFromCase）。一覧は必ず $user->tasks() などから始め、where user_id = ? が自動で付く。
  3. 回数制限は名前ごと（auth 10・writes 60・account 5・calendar 10／分、AI の窓口は mcp 120／分・oauth 60／分・oauth-register 20／時）。cache 表で数え、上限で 429。
  4. ニセの送信：@csrf の合言葉か Sec-Fetch-Site: same-origin がなければ 419。記録を変える操作は GET にしない。
  5. SecurityHeaders がどの返事にも守りの札を足し、ログイン中の返事は取り置かせない。nginx はファイルを送る形の送信と隠しファイルを止める。
  6. ログには id とエラーの種類だけ。bin/check が本文の列との組み合わせを止める。
  7. データのダウンロードは本人の記録だけ（カレンダーの鍵も AI の通行証も出さない）。退会は確認の言葉 → 先にログアウト → カレンダーの許可を取り消し → sessions・invitations・AI の通行証と更新の札・users を消し、子の表は cascadeOnDelete でまとめて物理削除。
