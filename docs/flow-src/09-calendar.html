9Google カレンダーとつなぐ・書き出す・取り込む

手帳を使う人として、期日のあるタスクや予想を確かめる日を、ふだん見ている Google カレンダーにも出したい。カレンダーの上で日をずらしたら、手帳のほうも合わせてほしい。だから、設定の画面で「カレンダーとつなぐ」を押す。

この章で追う道筋：①つなぐ：GET /calendar/connect（説明）→ POST /calendar/connect（Google へ送り出す）→ Google の同意画面 → GET /calendar/callback → 用事 ConnectCalendar（確かめる・専用カレンダーを用意する・トークンを暗号化して calendar_connections 表へ）→ 後回しの仕事 PushAllTasksToCalendar ②書き出す：TaskObserver が積んだ仕事（jobs 表）→ worker の箱の queue:work → PushTaskToCalendar・RemoveTaskFromCalendar → 窓口 CalendarApi → Google ③取り込む：routes/console.php の予定 → schedule:work → PullCalendarChanges → 用事 ApplyCalendarChanges → tasks 表 ④やめる：DELETE /calendar → 用事 DisconnectCalendar

この章は、ほかの章よりも登場人物が多くなります。ブラウザとサーバーのほかに、Google（同意の画面と、カレンダーの API）と、worker の箱（0章。後回しにした仕事と、決まった時刻の仕事を片づける係）が出てきます。下の図の A〜C の3つの流れと、最後にやめる流れを順に追います（D の「今日の予定」は 2章 で追いました。同じ読むだけの窓口 CalendarAgenda は、予想を立てるときの「確かめる日」の候補にも、これからの予定を読んで使います。6章）。

この章をつらぬく3つの決まり（.claude/rules/google.md）
  • 書くのは、アプリが作った専用カレンダー「推理手帳」にだけ。ふだんのカレンダーには書かない。
  • 送るのはタスクの題名と日時と、アプリに戻るリンクと、どのタスクの予定かを見分ける番号（suiri_task_id）だけ。番号はアプリの中の通し番号で、記録の中身ではない。メモや事件の手がかり・見立て・予想の文は送らない。
  • Google が止まっていても、タスクの保存は成功させる。Google への書き出しは後回しの仕事にして、あとで送り直す。

  2. サーバー

    住所の表：カレンダーの4つの住所

    「カレンダーとつなぐ」は、ただのリンク（<a href="/calendar/connect">）なので、ブラウザは GET /calendar/connect を送ります。住所の表 src/routes/web.php が読み込む src/routes/web/calendar.php に、カレンダーの住所が4つだけ並んでいます。

    src/routes/web/calendar.php
    Route::middleware(['auth', 'agreed', 'throttle:calendar'])->group(function () {
    Route::get('/calendar/connect', [ConnectCalendarController::class, 'show'])->name('calendar.connect');
    Route::post('/calendar/connect', [ConnectCalendarController::class, 'redirect'])->name('calendar.redirect');
    Route::get('/calendar/callback', [ConnectCalendarController::class, 'callback'])->name('calendar.callback');
    Route::delete('/calendar', DisconnectCalendarController::class)->name('calendar.disconnect');
});
    4つの住所の役目
    • GET /calendar/connect：つなぐ前の説明の画面。
    • POST /calendar/connect：「同意して Google へ進む」を押したとき。Google の画面へ送り出す。
    • GET /calendar/callback：Google で許可したあと、Google がブラウザを戻してくる先。
    • DELETE /calendar：つなぐのをやめる。
    ここが大事どの住所にも、連携の番号（{connection} のような穴）がありません。受付はいつも「ログイン中の本人の連携」だけを扱うので、住所の数字を書き換えて他人の連携をさわる、ということが最初からできない形です。
  3. 見張り役

    見張り役：ログイン・同意・回数制限

    囲みに付けた auth・agreed・throttle:calendar と、web のひとまとまりは、Laravel の並べ替え（0章）のあと、次の順に動きます（Laravel に並びを出させて確かめました）。

    1. EncryptCookies → AddQueuedCookiesToResponse → StartSession → ShareErrorsFromSession（Cookie とセッション。1章）
    2. PreventRequestForgery：POST と DELETE の合言葉を確かめる（11章）
    3. Authenticate（auth）：ログインしているか（1章）
    4. ThrottleRequests:calendar：回数が多すぎないか
    5. SubstituteBindings：住所の穴を記録に替える（この住所には穴がないので、何もしない）
    6. EnsureAgreed（agreed）：利用規約などに同意したか（1章）

    回数制限 calendar の中身は AppServiceProvider にあります。

    src/app/Providers/AppServiceProvider.php
    $by = fn (Request $request) => $request->user()?->id ?? $request->ip(); // ログイン中は人ごと、ログイン前は IP ごとに数える
// …（省略）…
RateLimiter::for('calendar', fn (Request $r) => Limit::perMinute(10)->by($by($r)));    // カレンダーとつなぐ・やめる

    つなぐ・戻る・やめるをまとめて、1人あたり1分に10回までです。Google への行き来をくり返されて、Google の側の回数の上限を使い切られないようにするためです（回数制限のしくみは 11章）。

    受付 ConnectCalendarController::redirect：「カレンダーも使わせて」と Google に頼む

    「同意して Google へ進む」を押すと POST /calendar/connect が届きます。見張り役を通ったあと、この関数が呼ばれます。

    src/app/Http/Controllers/Calendar/ConnectCalendarController.php
    public function redirect(Request $request): RedirectResponse|SymfonyRedirect
{
    // Google の鍵がまだ設定されていなければ、設定の画面へ戻して「準備中」と知らせる
    if (! GoogleTokens::configured()) {
        return redirect()->route('settings.show')->with('error', 'Google カレンダーとの連携は準備中です。');
    }

    return Socialite::driver('google')
        ->redirectUrl(route('calendar.callback'))
        ->scopes(config('suiri.calendar.scopes'))
        ->with([
            'access_type' => 'offline',
            'prompt' => 'consent',
            'include_granted_scopes' => 'true',
            'login_hint' => $request->user()->email,
        ])
        ->enablePKCE()
        ->redirect();
}

    Socialite は、Google などのアカウントで「許可をもらう手続き（OAuth）」を代わりにしてくれる Laravel の部品です。ログインでも使いました（1章）。ログインのときとの違いは、ここでカレンダーの許可を足して頼むことです。ログインのときには、名前・メール・アイコンの許可しかもらっていません。使う機能を選んだ人にだけ、あとから許可を足してもらうやり方を段階的な許可と呼びます。

    1行ずつの意味
    • redirectUrl(route('calendar.callback'))：Google で許可したあとに戻ってくる先。ログインの戻り先（/auth/google/callback）とは別の /calendar/callback にする。
    • scopes(...)：スコープ（許可の範囲）。下の2つ。
    • access_type=offline：利用者が画面の前にいないとき（worker の箱が夜中に書き出すときなど）にも使える refresh token（鍵を取り直すための鍵）をもらう。
    • prompt=consent：前に許可したことがあっても、同意の画面を必ず出してもらう。こうしないと refresh token がもう一度もらえないことがある。
    • include_granted_scopes=true：ログインのときの許可も、まとめて1つの許可にする。
    • login_hint：Google の画面で、ログイン中の人のメールのアカウントを先に選んでおく。
    • enablePKCE()：途中で許可を横取りされないための合言葉（このあと説明）。
    src/config/suiri.php
    'calendar' => [
    'name' => '推理手帳', // アプリが作る専用カレンダーの名前
    'timezone' => 'Asia/Tokyo',
    'pull_every_minutes' => 15,
    'scopes' => [
        'https://www.googleapis.com/auth/calendar.app.created',

    • calendar.events.owned.readonly：自分のカレンダーの予定を読むだけの許可。今日の画面に予定を出すのに使います（2章）。

    カレンダーのすべてを読み書きできる大きな許可（calendar）は求めません。許可は、使う分だけの最小にします。

  7. サーバー

    Socialite が合言葉をセッションにしまい、Google の住所を作る

    scopes() は、Socialite がもともと持っている Google の既定の許可（openid・profile・email）に、渡した2つを足します。

    src/vendor/laravel/socialite/src/Two/AbstractProvider.php
    public function scopes($scopes)
{
    $this->scopes = array_values(array_unique(array_merge($this->scopes, (array) $scopes)));

    return $this;
}

    最後の redirect() が、Google の同意の画面への転送を作ります。

    src/vendor/laravel/socialite/src/Two/AbstractProvider.php
    public function redirect()
{
    $state = null;

    if ($this->usesState()) {
        $this->request->session()->put('state', $state = $this->getState());
    }

    if ($this->usesPKCE()) {
        $this->request->session()->put('code_verifier', $this->getCodeVerifier());
    }

    return new RedirectResponse($this->getAuthUrl($state));
}
    1. state（でたらめな文字列）を作って、この人のセッション（サーバーの預かり箱。1章）にしまう。
    2. PKCE の code_verifier（もう1つのでたらめな文字列）もセッションにしまう。
    3. Google の住所 https://accounts.google.com/o/oauth2/auth?… を作って、そこへの転送（302）を返す。

    住所の後ろ（? から先）に付ける項目は、次の関数が集めます。

    src/vendor/laravel/socialite/src/Two/AbstractProvider.php
    if ($this->usesState()) {
    $fields['state'] = $state;
}

if ($this->usesPKCE()) {
    $fields['code_challenge'] = $this->getCodeChallenge();
    $fields['code_challenge_method'] = $this->getCodeChallengeMethod();
}

return array_merge($fields, $this->parameters);

    state はそのまま住所に付けます。code_verifier のほうは、そのままではなく、計算で元に戻せない形（code_challenge。SHA-256 という計算の結果）にして付けます。最後の $this->parameters が、さっき with([...]) で渡した access_type などです。

    たとえるとクリーニング店の引換券です。店（Google）に行く前に、半券（state と code_verifier）を自分の財布（セッション）に入れておきます。戻ってきたとき、半券と合わない人には品物（許可）を渡しません。
  8. ブラウザ

    Google の同意の画面で許可し、/calendar/callback へ戻る

    ブラウザは転送に従って Google の画面を開きます。ここから先はアプリのコードではなく、Google の画面です。利用者はアカウントを選び、カレンダーの項目にチェックを入れて「続行」を押します。

    「このアプリは Google で確認されていません」という注意が出ることがあります。少人数で使うアプリなので、Google の確認の手続きをしていないためで、説明の画面の下にもそう書いてあります（config/suiri.php の calendar.consent.warning）。

    許可すると、Google はブラウザを /calendar/callback へ戻します（Google からの転送）。

    このとき動くデータ
    • 送る：GET /calendar/callback?state=…&code=…&scope=…
    • code：認可コード。「この人は許可しました」という1回きりの引換券。これだけではまだカレンダーは使えない。
    • state：行くときに付けた合言葉が、そのまま返ってくる。

    受付 ConnectCalendarController::callback：引換券を鍵に替える

    戻りの住所にも、同じ見張り役（ログイン・同意・回数制限）が付いています。

    src/app/Http/Controllers/Calendar/ConnectCalendarController.php
    public function callback(Request $request, ConnectCalendar $connect): RedirectResponse
{
    // Google の鍵がまだ設定されていなければ、設定の画面へ戻して「準備中」と知らせる
    if (! GoogleTokens::configured()) {
        return redirect()->route('settings.show')->with('error', 'Google カレンダーとの連携は準備中です。');
    }

    // Google から許可を受け取る（送り出しと同じ戻り先と PKCE で）。やめた・時間切れなどで失敗したら、設定の画面で知らせる
    try {
        $google = Socialite::driver('google')->redirectUrl(route('calendar.callback'))->enablePKCE()->user();
    } catch (Throwable $e) {
        Log::info('カレンダーとつなぐのを中断', ['user_id' => $request->user()->id, 'error' => class_basename($e)]);

    用事 DeleteOrphanEvents：もうないタスクの予定を、専用カレンダーから消す

    連携が切れている間（broken）にタスクを消すと、予定を消す仕事 RemoveTaskFromCalendar は「切れている」ので何もせずに終わり、タスクの行も消えます。すると、予定だけが Google に残ります。つなぎ直したときに、それを片づけます。

    src/app/Actions/Calendar/DeleteOrphanEvents.php
    public function handle(CalendarConnection $connection, ?array $events = null): int
{
    $events ??= $this->api->listChangedEvents($connection, $connection->app_calendar_id, null)['events'];

    // アプリの印があって、まだ消されていない予定だけを「予定の ID => タスクの番号」にする
    $marked = collect($events)
        ->reject(fn (array $event) => ($event['status'] ?? null) === 'cancelled' || ! isset($event['id']))
        ->mapWithKeys(fn (array $event) => [$event['id'] => $event['extendedProperties']['private']['suiri_task_id'] ?? null])
        ->filter(fn ($taskId) => filled($taskId));
    // …（省略）…
    $existing = Task::where('user_id', $connection->user_id)
        ->whereIn('id', $marked->values()->unique()->all())
        ->pluck('id')->map(fn ($id) => (string) $id)->flip();
    $orphans = $marked->reject(fn ($taskId) => $existing->has((string) $taskId))->keys();

    // 本人の今あるタスクに当たらない予定を1つずつ消す（もう消えていれば窓口が何もしない）
    foreach ($orphans as $eventId) {
        $this->api->deleteEvent($connection, $connection->app_calendar_id, (string) $eventId);
    }

    return $orphans->count();
}
    • listChangedEvents(…, null)：しおりなしで、専用カレンダーの予定を全部読みます（次の手順の取り込みの窓口と同じ）。全件を読み直す取り込みのときは、もう読んだ一覧を $events で渡してもらい、読み直しません。
    • 見るのは、アプリの印 suiri_task_id（タスクの番号）がついた予定だけです。印のない予定は、利用者が専用カレンダーに手で足したものなので、消しません。
    • その番号が本人の今あるタスク（where('user_id', …)）に当たらなければ、消します。他人のタスクの番号がついた予定も、自分の専用カレンダーにあるべきではないので消します。
    ここが大事消してよいのは、専用カレンダーがアプリだけが書く場所（スコープ calendar.app.created で作ったもの）だからです。ふだんのカレンダーの予定には、そもそも触れられません。テスト src/tests/Feature/Calendar/DeleteOrphanEventsTest.php が、Google の返事を Http::fake の偽物にして、消すのが「もうないタスク・他人のタスクの番号の予定」だけで、今あるタスク・印のない予定・消された印の予定には触らないことを確かめています。

    • 外へ：GET /calendars/{専用カレンダー}/events（全件）と、消す予定ごとに DELETE /calendars/{専用カレンダー}/events/{予定の ID}
    • 読む：tasks の id（その人の分だけ）

    public function times(Task $task): array
{
    $timeZone = config('suiri.calendar.timezone');

    // 開始時刻のない（終日の）タスクは、日付だけの予定にする
    if (! $task->hasTime()) {
        $day = CarbonImmutable::parse($task->due_on, $timeZone);

        return ['start' => ['date' => $day->toDateString()], 'end' => ['date' => $day->addDay()->toDateString()]];
    }

    $start = CarbonImmutable::parse($task->due_on.' '.$task->starts_at, $timeZone);
    $end = $start->addMinutes($task->duration_minutes ?: config('suiri.calendar.default_minutes'));

    return [
        'start' => ['dateTime' => $start->format('Y-m-d\TH:i:s'), 'timeZone' => $timeZone],
        'end' => ['dateTime' => $end->format('Y-m-d\TH:i:s'), 'timeZone' => $timeZone],
    ];
}

{
    // うまくいった、または気にしなくてよい番号なら、何もしない
    if ($response->successful() || in_array($response->status(), $ok, true)) {

    private function unlinkMissing(CalendarConnection $connection, array $events, Carbon $startedAt): int
{
    // Google にある予定の ID（消された印のものは除く）を、引きやすい形にする
    $present = collect($events)->reject(fn (array $event) => ($event['status'] ?? null) === 'cancelled')->pluck('id')->filter()->flip();

    $missing = Task::where('user_id', $connection->user_id)->whereNotNull('calendar_event_id')
        ->where('calendar_synced_at', '<', $startedAt)
        ->pluck('calendar_event_id')
        ->reject(fn (string $eventId) => $present->has($eventId));

    return $missing->chunk(self::UNLINK_CHUNK)->sum(fn ($ids) => $this->unlink($connection, $ids->values()->all()));
}

    しおりが古すぎて全件を読み直したとき、その間に消された予定の「消された知らせ」は、もう受け取れていません。そこで、Google の一覧にある予定の ID と、手元のタスクの calendar_event_id を比べ、Google にないものはつながりを外します。

    • flip()：ID の一覧を「ID が見出しの表」に変えて、has() で速く引けるようにする。
    • where('calendar_synced_at', '<', $startedAt)：比べるのは、読み始める前に書き出しが済んでいたタスクだけ。まだ書き出していない・読んでいる間に書き出したタスクは、一覧になくて当たり前なので外さない。
    • chunk(500)：一度に問い合わせる ID を500ずつに分ける。
    src/app/Actions/Calendar/ApplyCalendarChanges.php
    private function unlink(CalendarConnection $connection, array $eventIds): int
{
    return Task::where('user_id', $connection->user_id)->whereIn('calendar_event_id', $eventIds)
        ->update(['calendar_event_id' => null, 'calendar_synced_at' => null]);
}

    つながりを外すのは、いつも「その人のタスク」（user_id）だけです。タスクそのものは消しません。続けて、つなぎ直したときと同じ用事 DeleteOrphanEvents に、読んだ一覧を渡して、もうないタスクの予定を消します（sweepOrphans。この章の 1 の終わり）。消すのに Google が失敗しても、取り込み（日時の写しと新しいしおりの保存）は止めず、連携の id とエラーの種類だけを記録します。消せなかった分は、つなぎ直したときや次に全件を読んだときに片づきます。差分の取り込み（しおりが生きている）では、どちらもしません。

    • 書く：calendar_connections の sync_token・last_synced_at

{
    // refresh token を取り消す（対応する access token も一緒に無効になる）。つながらないなどの失敗は false にする
    try {

この章のまとめ
  1. つなぐのは、ログインとは別の「段階的な許可」。説明の画面で送るもの・送らないものを見せてから、カレンダーの2つの小さなスコープと refresh token を Google に頼む。state と PKCE で、途中の横取りやなりすましの戻りを防ぐ。
  2. 戻りでは用事 ConnectCalendar が「同じアカウント・許可がそろった・refresh token がある」を確かめ、専用カレンダー「推理手帳」を用意し、鍵を暗号にして calendar_connections に1人1行で保存する。今までのタスクの書き出しと、切れている間に消したタスクの予定の片づけ（DeleteOrphanEvents）は後回しの仕事にする。
  3. 書き出しは、タスクを見張る係が保存の確定後に jobs 表へ積んだ仕事（タスクの id だけ）を、worker の箱が取り出して行う。送るのは題名・日時・戻るリンクと、見分けるための番号だけで、予定の ID はタスクごとに先に決めるので、何度送っても予定は1つ。
  4. Google が止まっていても、タスクの保存は成功している。書き出しは1分・5分・15分・1時間と間を空けて5回まで試し直す。許可が切れたら broken にして止め、設定の画面で「つなぎ直してください」と出す。
  5. 15分ごとの取り込みは、しおり（sync token）から先に変わった予定だけを読み、動いた日時をタスク（と予想の確かめる日）に写し、消された予定はつながりだけを外す。取り込みの保存は見張る係に知らせない形なので、Google に送り返さない。
  6. やめるときは、Google の許可を取り消し、つながりを外して、暗号にした鍵の行を消す。Google が止まっていても、手元の鍵は必ず消す。
  7. 予定を読むだけの窓口 CalendarAgenda は、今日の予定と確かめる日の候補に使う。題名と時刻だけを数分覚え、保存しない。テストでは書き出しの窓口も読む窓口も偽物に替え、本物の Google に一度もつながない。
