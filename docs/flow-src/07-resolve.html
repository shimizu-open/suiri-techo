7答え合わせ：予想が当たったか確かめる

予想を立てた人として、確かめる日が来たら、実際はどうだったかを記録して、見立てを直したい。だから、答え合わせの画面を開いて4つの大きなボタンから1つを選び、保存する。

この章で追う道筋：今日の画面の「答え合わせしよう」・事件の画面の「答え合わせをしよう」などの入口 → GET /predictions/{prediction}（can:view,prediction）→ 受付 PredictionController::show → 画面（前に書いた予想 prediction-original ＋「実際はどうだった？」のカード resolve-form）→ POST /predictions/{prediction}/result → 形の検証 ResolvePredictionRequest → 受付 ResolvePredictionController → 用事 ResolvePrediction（結果を書く ＋ 確かめるタスクを済みにする）→ 同じ画面へ転送 →「確かめた」のはんこと次の一手（resolve-result）→ 見立てを直す PATCH /hypotheses/{hypothesis}（ChangeHypothesisStatus）

入口：確かめる日が来ると、答え合わせが「いまやること」になる

  1. ブラウザ

    答え合わせの画面への入口

    答え合わせの画面（/predictions/{prediction}）へは、次のボタンやリンクから来られます。どれも同じ住所へのリンク（GET）です。

    1. 今日の画面のいちばん上のカード（部品 today/next-step。2章）：確かめる日が来た予想があると、今日の画面の「いまやること」のカードが「答え合わせしよう」になり、横いっぱいの「答え合わせする」が出る。出すのはいちばん古い1件だけで、ほかは下に「ほかにも◯件あるよ」とたたむ（部品 today/due-predictions）。
    2. 事件の画面の「答え合わせをしよう」のカード（部品 case-step/resolve-card）：その事件に確かめる日が来た予想があると、事件の画面の1枚だけのカードがこれになる。
    3. 事件の画面の「◯月◯日に確かめよう」のカード（部品 case-step/wait-card。6章）：確かめる日の前でも、下の小さなリンク「先に答え合わせをする」から来られる。
    4. タスクの一覧の確かめるタスク（部品 task/item。3章）：まだ済んでいない確かめるタスクの行に「答え合わせ」がある。
    5. Google カレンダーの予定（9章）：確かめるタスクの予定に入れたリンクが、答え合わせの画面を指している。

  2. データベース

    今日の画面のカードは、どの予想を集めるか（DuePredictionsQuery）

    今日の画面のカードに出す予想は、一覧を集める係 DuePredictionsQuery が作ります（今日の画面の全体は 2章）。カードの部品は、その1件目（いちばん古いもの）を大きく出し、2件目からをたたみます（上の $first と $rest）。

    src/app/Queries/Today/DuePredictionsQuery.php
    public function for(User $user, string $today): Collection
{
    return $user->predictions()
        ->whereNull('result')
        ->whereNull('withdrawn_at')
        ->where('check_on', '<=', $today)
        ->with('caseFile:id,title,scene')
        ->orderBy('check_on')->orderBy('check_at')->orderBy('id')
        ->get();
}
    • $user->predictions()：この人の予想だけ（user_id で絞る。他人の予想は混ざらない）。
    • whereNull('result')・whereNull('withdrawn_at')：まだ結果がなく、取り下げてもいない＝答え合わせ待ち。
    • where('check_on', '<=', $today)：確かめる日が今日まで（過ぎたものも含む）。
    • 並びは、確かめる日の古い順（過ぎているものが先）→ 時刻の早い順。だから、カードに大きく出るのは、いちばん長く待っている予想です。
    このとき動くデータ
    • 読む：predictions（この人の答え合わせ待ちで、確かめる日が来たもの）と、その事件の case_files の題名・場面
  3. サーバー

    事件の画面では、答え合わせがいちばん先（NextStep）

    事件の画面は、いまやることを1枚のカードだけで見せます。どのカードにするかは「いまの一手」を決める係 NextStep が、上から順に確かめて最初に当てはまったものを選びます（事件の画面の組み立ての全体は 5章）。閉じた事件と、相棒モードで見せ合う前（8章）を除けば、確かめる日が来た予想があるかを、手がかりや見立てより先に確かめます。

    src/app/Queries/Cases/NextStep.php
    $pending = $case->predictions->filter->isPending()->sortBy('check_on');
$due = $pending->first(fn ($p) => $p->isDue($today));
// 確かめる日が来た予想があれば、まず答え合わせ
if ($due !== null) {
    return ['key' => 'resolve', 'prediction' => $due];
}
    src/app/Models/Prediction.php
    public function isDue(string $today): bool
{
    return $this->isPending() && $this->check_on <= $today;
}
    • filter->isPending()：この事件の予想のうち、答え合わせ待ちだけを残します。sortBy('check_on') で確かめる日の早い順に並べます。
    • isDue($today)：答え合わせ待ちで、確かめる日が今日まで来ているか。最初に当てはまった1件を、答え合わせのカード（case-step/resolve-card）に渡します。
    • 確かめる日がまだ来ていなければ、ほかの段（手がかり・見立て・予想）を確かめたあと、最後に「◯月◯日に確かめよう」のカード（wait）になります。

答え合わせの画面を開く

  1. サーバー

    住所の表：見る住所は回数制限の囲みの外

    src/routes/web/cases.php
    // 答え合わせの画面
Route::get('/predictions/{prediction}', [PredictionController::class, 'show'])->can('view', 'prediction')->name('predictions.show');

    この行は auth・agreed の囲みの中ですが、書き込み用の throttle:writes の囲みの外にあります。見るだけの住所なので、書き込みの回数には数えません。Laravel に並びを出させると、動く見張り役は次の順でした。

    1. EncryptCookies → AddQueuedCookiesToResponse → StartSession → ShareErrorsFromSession → PreventRequestForgery（GET は「読むだけ」なので合言葉は要らない）
    2. Authenticate（auth）：ログインしているか
    3. SubstituteBindings：穴 {prediction} の番号を、predictions 表の行に替える（なければ 404）
    4. EnsureAgreed（agreed）：同意しているか
    5. Authorize:view,prediction（can）：この予想の持ち主か
  2. 見張り役

    can:view,prediction：他人の予想は見られない

    しくみは 6章 の can:write,hypothesis と同じです。門番（Gate）が Prediction の決まりの係 PredictionPolicy を見つけ、その view を呼びます。

    src/app/Policies/PredictionPolicy.php
    class PredictionPolicy
{
    use OwnerOnly;
}
    src/app/Policies/Concerns/OwnerOnly.php
    /** 見てよいか（持ち主だけ） */
public function view(User $user, Model $record): bool
{
    return $this->owns($user, $record);
}

    予想の行の user_id がログイン中の人と違えば「403」です。住所の番号を1つずつ変えて他人の予想をのぞこうとしても、見られません（11章）。

    受付 PredictionController::show：関係する行をまとめて読んで画面へ

    src/app/Http/Controllers/Cases/PredictionController.php

{
    $prediction->load(['hypothesis', 'caseFile', 'atticNote']);

    return view('predictions.show', ['prediction' => $prediction, 'case' => $prediction->caseFile, 'kid' => $request->user()->prefersKidWords()]);

    • load([...])：画面で使う「つながった行」を、先にまとめて読んでおきます（先読み（eager load））。この予想を導いた見立て（hypothesis）・事件（caseFile）・使った屋根裏の知識（atticNote）です。
    • kid：子ども向けの言葉を出すか。ふだんの場面を「親子」にしている人なら true で、結果のボタンが「あたり・はずれ・わからない・そもそもちがった」になります。
    • view('predictions.show', …)：画面の型紙 resources/views/predictions/show.blade.php に、予想と事件を渡して HTML を作ります。
    このとき動くデータ
    • 読む：hypotheses・case_files・attic_notes（あれば）のそれぞれ1行

結果を保存する

  1. サーバー

    住所の表と見張り役：書き込みなので回数制限つき

    src/routes/web/cases.php
    Route::post('/predictions/{prediction}/result', ResolvePredictionController::class)->can('update', 'prediction')->name('predictions.resolve');

    こちらは throttle:writes の囲みの中です。Laravel に並びを出させると、EncryptCookies → AddQueuedCookiesToResponse → StartSession → ShareErrorsFromSession → PreventRequestForgery（合言葉）→ Authenticate → ThrottleRequests:writes（1分に60回まで）→ SubstituteBindings → EnsureAgreed → Authorize:update,prediction の順でした。答え合わせは予想の行に書き込むことなので、持ち主かを update の権利で確かめます（PredictionPolicy。中身は同じ OwnerOnly）。手がかりや見立ての write（捜査中の事件だけ）とちがい、事件が閉じていても答え合わせはできます。確かめる日を待たずに事件を閉じても、待っている予想の結果を残せるように（残さないと、ノーベリ帳と確かさの集計に入らない）するためです。

  2. サーバー

    用事 ResolvePrediction：鍵をかけて読み直してから、結果を書く（文と確かさには触らない）

    src/app/Actions/Cases/ResolvePrediction.php
    public function handle(Prediction $prediction, array $data): bool
{
    $result = PredictionResult::from($data['result']);

    return DB::transaction(function () use ($prediction, $data, $result) {
        // 保存されている今の状態を、ほかの書き込みを待たせて読み直す（同時の取り下げや二重の送信と食い違わないように）
        $current = Prediction::whereKey($prediction->getKey())->lockForUpdate()->first();

        // もう答え合わせ済み・取り下げ済み（または消えた）なら、何もしない（先に書いた結果を上書きしない）
        if ($current === null || ! $current->isPending()) {
            return false;
        }

        $prediction->update([
            'result' => $result,
            'result_note' => $data['result_note'] ?? null,
            'miss_reason' => $result->isMiss() ? $data['miss_reason'] : null, // 外れのときだけ原因を残す
            'resolved_at' => now(),
        ]);
    • PredictionResult::from('miss')：送られた文字を列挙の値（PredictionResult::Miss）に変えます。
    • DB::transaction：中の書き込みを「全部するか、全部しないか」のひとまとまりにします（トランザクション）。途中で失敗したら、それまでの書き込みも取り消されます。
    • lockForUpdate()：予想の行に鍵をかけて、データベースから読み直します。検証の係（ResolvePredictionRequest）が「答え合わせ待ち」を確かめたあとに、別のタブで取り下げられたり、同じ送信が二重に届いたりしても、あとから来たほうはこの鍵が外れるのを待ち、読み直した行がもう答え合わせ待ちでなければ何もせず false を返します。先に書いた結果が残ります（取り下げの用事 WithdrawPrediction と同じ形）。
    • 書くのは、結果・メモ・見落とし・答え合わせした日時（resolved_at）だけです。
    • miss_reason は外れのときだけ残します。「どちらとも言えない」で原因が送られてきても、null にして捨てます（ノーベリ帳の数え方を食い違わせないため）。
    • 文（statement）と確かさ（confidence）には触らないので、モデルの updating の見張り（6章）を通って保存されます。

    src/app/Observers/TaskObserver.php
    /** 予定の中身に関わる列。これ以外（メモ・かかった時間など）だけが変わったときは書き出さない */

public function updated(Task $task): void
{

    public function handle(Hypothesis $hypothesis, HypothesisStatus $to): bool
{
    $from = $hypothesis->status;
    // 同じ状態を選んだだけなら、記録を増やさない
    if ($from === $to) {
        return false;
    }

    DB::transaction(function () use ($hypothesis, $from, $to) {
        $hypothesis->update(['status' => $to]);
        $hypothesis->statusLogs()->create([
            'user_id' => $hypothesis->user_id,
            'from_status' => $from,
            'to_status' => $to,
        ]);
        $hypothesis->caseFile->touch();
    });

    return true;
}

この章のまとめ
  1. 確かめる日が来ると、今日の画面のいちばん上のカード（DuePredictionsQuery のいちばん古い1件）と、事件の画面の1枚だけのカード（NextStep がいちばん先に確かめる）が「答え合わせ」になる。確かめるタスクの行・カレンダーの予定・待つカードの「先に答え合わせをする」からも来られる。
  2. GET /predictions/{prediction} は持ち主だけ（PredictionPolicy の view）。画面は、書いた日時と予想の文を「あとから変えられないよ」と大きく上に見せ、ほかは「くわしく」にたたむ。
  3. 「実際はどうだった？」は4つの大きなボタン（当たり・外れ・どちらとも言えない・前提が崩れた）。外れのときだけ「どこで見落とした？」が CSS の :has で現れ、サーバーでも required_if で必須にする。
  4. ResolvePredictionRequest は答え合わせ待ちの予想だけを受け付ける（2回目・取り下げ後は 403）。
  5. ResolvePrediction が、1つのトランザクションで結果を書き、確かめるタスクを済みにする。TaskObserver がカレンダーへの書き出しを積む。
  6. 保存すると「確かめた」のはんこが押され、結果に合わせた次の一手を1つだけ出す（当たり → 「当たり」、外れ → 「消えた」、ほか → 新しい予想）。押すと ChangeHypothesisStatus が「考えを変えた記録」を残し、事件の画面のカードが次の段に変わる。
  7. ノーベリ帳と確かさの答え合わせは、同じ予想の行を読むだけ（10章）。
