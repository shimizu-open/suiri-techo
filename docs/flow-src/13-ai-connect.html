13ChatGPT・Claude とつなぐ（読むだけの窓口）

手帳を使う人として、自分の ChatGPT や Claude に事件の記録を読ませて、ほかの見立てや確かめ方の案を出してもらいたい。ただし、書き換えられたり、仕事の場面の記録まで渡ったりするのは困る。だから、設定の画面にある窓口の住所を AI の設定に入れ、推理手帳の同意の画面で「許可する」を押す。

この章で追う道筋：①設定の画面 GET /settings の枠（窓口の住所とつなぎ方）②AI が通行証なしで POST /mcp → 401 → 案内の住所 GET /.well-known/oauth-protected-resource/mcp・GET /.well-known/oauth-authorization-server → 自己登録 POST /oauth/register ③本人のブラウザで GET /oauth/authorize（ログイン・利用規約の同意を確かめる）→ 自前の同意の画面 → POST /oauth/authorize（許可する）④AI が POST /oauth/token で引換券を通行証に引き換える ⑤通行証を見せて POST /mcp → 見張り役4つ → 窓口 SuiriServer → 読むだけの道具4つ → Queries/Ai/* ⑥やめる DELETE /settings/ai/{app}・毎日の片づけ ⑦事件の画面の写すボタン（窓口を使わない相談）

アプリの中では AI を使いません（ワトソンのひとことも入力の提案も、決まった規則です）。この章の窓口は、利用者が自分の ChatGPT・Claude から、推理手帳の記録を読むだけにするための入口です。AI の役目は「ほかの見立て・見立てを見分ける確かめ方・まだ集めていない手がかり」の候補を出すことで、どの見立てが正しいか、予想が当たったかは決めません。答え合わせは、本人が現実で確かめて手帳に書きます。

この章は、登場人物がもう1人増えます。ブラウザと推理手帳のサーバーのほかに、AI の会社のサーバー（ChatGPT なら OpenAI、Claude なら Anthropic のサーバー）です。窓口 /mcp を呼ぶのは、利用者のブラウザではなく、この AI の会社のサーバーです。ステップの札は、AI の会社のサーバーが動くところを「AI の会社のサーバー」と書きます。

この章をつらぬく決まり（.claude/rules/ai-connect.md）
  • 読むだけ：道具は読むだけの4つ。答え合わせ・○×・直す・消す・作るの道具は置かない。
  • 仕事の場面を見せない：見える事件は「本人の事件で、場面が仕事でないもの」だけ。決まりは VisibleCases の1か所。
  • 見せ合う前の相棒の見立てを隠す：相棒モードで見せ合う前の事件は、見立てと予想を出さない。
  • 戻り先は3つだけ：自己登録できるのは、許可のあとに戻る先が https://chatgpt.com・https://claude.ai・https://claude.com の AI だけ。
  • 通行証は1時間・更新の札は30日。本人は設定の画面でいつでも取り消せる。

2. AI が案内を読み、自分を登録する

  1. AI の会社のサーバー

    通行証なしで窓口を呼ぶ → 401「通行証が要ります」

    まず、窓口とは何かです。MCP（Model Context Protocol）は、役目で言うと「AI がアプリの道具を呼ぶための決まり」です。たとえると、AI という代理人のために、推理手帳の事務所に作った小窓です。中身は、決まった形の JSON（データを文字で書く形）を POST で送り合うやりとりで、ChatGPT も Claude もこの決まりに対応しているので、同じ1つの住所 /mcp で両方とつながります。推理手帳では Laravel 公式の部品 laravel/mcp で窓口を作っています。

    窓口の住所は、ふだんの住所の表（routes/web.php）ではなく、別のファイル src/routes/ai.php にあります。

    src/routes/ai.php
    // ④：よその画面からの呼び出しを断る → 通行証を確かめる → 窓口を読む範囲（mcp:use）かを確かめる → 人ごとの回数制限
Mcp::web('/mcp', SuiriServer::class)->middleware([
    RejectForeignOrigin::class,
    'auth:api',
    CheckToken::using(Registrar::OAUTH_SCOPE),
    'throttle:mcp',
]);

    このファイルは laravel/mcp が、見張り役のグループなしで読み込みます（Route::group([], $path)）。ふだんの画面の住所には web のグループ（セッション・CSRF の確かめなど。0章・11章）が付きますが、ここには付きません。AI の会社のサーバーはログインの Cookie も CSRF の合言葉も持っていないので、そのままでは POST が通らないからです。代わりに、窓口には通行証（このあとの 4）が必須です。

    src/vendor/laravel/mcp/src/Server/McpServiceProvider.php
    $path = base_path('routes/ai.php');
// …（省略）…
Route::group([], $path);

    ChatGPT は最初、通行証を持たずに POST /mcp を呼びます。見張り役 auth:api が「通行証がない」と止め、401（だれか分からない）を返します。ふつうの画面なら「ログインの画面へ送る」ところですが、相手は人ではないので、bootstrap/app.php で「この住所のエラーは JSON で返す」と決めています。

    src/bootstrap/app.php
    $exceptions->shouldRenderJsonWhen( // fetch など JSON を求める要求と、AI の窓口（/mcp）・通行証の住所のエラーは JSON で返す
    fn (Request $request) => $request->is('api/*', 'mcp', 'oauth/token', 'oauth/register') || $request->expectsJson(),
);

    さらに laravel/mcp の見張り役 AddWwwAuthenticateHeader が、401 の返事に「通行証の出し方の案内はここ」という札（WWW-Authenticate のヘッダ）を付けます。

    src/vendor/laravel/mcp/src/Server/Middleware/AddWwwAuthenticateHeader.php
    $response->header(
    'WWW-Authenticate',
    'Bearer realm="mcp", resource_metadata="'.route('mcp.oauth.protected-resource.nested', ['path' => $request->path()]).'"'
);
    返事（手元の localhost:8086 で、通行証なしで呼んで確かめたもの）
    HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="mcp", resource_metadata="http://localhost:8086/.well-known/oauth-protected-resource/mcp"
{"message":"Unauthenticated."}
    たとえると小窓で「通行証を見せてください。通行証の作り方は、あちらの案内板に書いてあります」と言われるところです。
  2. サーバー

    案内の住所：通行証の出し方を JSON で答える

    ここで使う決まりが OAuth です。役目は「パスワードを渡さずに、別のアプリに一部の権限だけを預ける」こと。たとえると、銀行で代理人に委任状を書くようなものです。推理手帳のログイン（Google）を AI に教えるのではなく、推理手帳が「この AI に、この人の記録を読ませてよい」という通行証（アクセストークン。AI が道具を呼ぶたびに見せる長い文字列）を出します。中身は、通行証を出す係に Laravel 公式の部品 Laravel Passport を使っています。

    401 の札にあった案内の住所（発見用の住所）は、routes/ai.php の1行で laravel/mcp に作らせています。

    src/routes/ai.php
    // ①〜③：IP ごとの回数制限（AI の会社のサーバーの IP は利用者みんなで同じなので、きつくしすぎない）
Route::middleware('throttle:oauth')->group(function () {
    // 案内の住所は laravel/mcp に作らせる。登録の住所は、回数制限を足すため下で自分で置く
    Mcp::oauthRoutes(registration: false);

    案内は2段です。1つ目（/.well-known/oauth-protected-resource/mcp）は「この窓口の通行証は、どこで出してもらえるか」。2つ目（/.well-known/oauth-authorization-server）は「同意の画面・通行証の引き換え・自己登録の住所と、使える方式」です。中身は laravel/mcp が組み立てます。

    src/vendor/laravel/mcp/src/Server/Registrar.php
    'authorization_endpoint' => route('passport.authorizations.authorize'),
'token_endpoint' => route('passport.token'),
'registration_endpoint' => Router::has('mcp.oauth.register') ? route('mcp.oauth.register') : null,
'response_types_supported' => ['code'],
'code_challenge_methods_supported' => ['S256'],
'scopes_supported' => [self::OAUTH_SCOPE],
    返事（手元で確かめたもの。上が1つ目、下が2つ目。読みやすいよう / の前の \ は外した）
    {"resource":"http://localhost:8086/mcp","authorization_servers":["http://localhost:8086"],"scopes_supported":["mcp:use"]}
{"issuer":"http://localhost:8086","authorization_endpoint":"http://localhost:8086/oauth/authorize","token_endpoint":"http://localhost:8086/oauth/token","registration_endpoint":"http://localhost:8086/oauth/register","response_types_supported":["code"],"code_challenge_methods_supported":["S256"],"scopes_supported":["mcp:use"],"grant_types_supported":["authorization_code","refresh_token"],...}

    中身は住所をルートの名前（passport.authorizations.authorize・passport.token）から作っています。だから推理手帳は、このあと見る同意の画面と通行証の住所を、Passport と同じ名前のまま置き直しています（名前を変えると、案内が作れなくなるため）。

    案内に出てくる言葉
    • scopes_supported: ["mcp:use"]：範囲（スコープ。通行証で何ができるか）は「窓口を読む」の1つだけ。
    • code_challenge_methods_supported: ["S256"]：引換券を守る合言葉のしくみ（PKCE。この章の 4）を使う。
    • grant_types_supported：通行証のもらい方は「引換券から」（authorization_code）と「更新の札から」（refresh_token）の2つ。
  3. サーバー

    自己登録：戻り先が3つのどれかの AI だけ登録する

    次に AI は、自分を推理手帳に登録します。OAuth の決まりでは動的クライアント登録と呼ぶしくみで、役目は「前もって運営者に申し込まなくても、AI が自分で名乗って登録の番号をもらう」こと。たとえると、受付の名簿に代理人が自分で名前と連絡先（許可のあとに戻る住所）を書くようなものです。ここではこれを「自己登録」と呼びます。

    src/routes/ai.php
    Route::post('/oauth/register', OAuthRegisterController::class)->middleware('throttle:oauth-register')->name('mcp.oauth.register');

    受付は laravel/mcp の OAuthRegisterController をそのまま使います。大事なのは、許可のあとに戻る先（redirect_uris）の確かめです。設定の redirect_domains にある住所で始まるものしか通しません。

    src/vendor/laravel/mcp/src/Server/Http/Controllers/OAuthRegisterController.php
    if (! Str::startsWith($value, $this->allowedDomains())) {
    $fail($attribute.' is not a permitted redirect domain.');
}

    laravel/mcp の初めの値は *（どこへでも戻せる）なので、推理手帳は config/mcp.php で3つに絞っています。比べるときに末尾へ / を足すので、https://chatgpt.com.evil.example のような似せた住所も通りません。

    src/config/mcp.php
    'redirect_domains' => [
    'https://chatgpt.com',
    'https://claude.ai',
    'https://claude.com',
],
    返事（手元で、よその住所を戻り先にして登録を試したもの）
    {"error":"invalid_redirect_uri","error_description":"redirect_uris.0 is not a permitted redirect domain."} 400

    通れば、Passport の表 oauth_clients に1行できて、登録の番号（client_id）が返ります。合言葉（シークレット）を持たない登録（confidential: false）なので、代わりに 4 の PKCE で守ります。

    src/vendor/laravel/mcp/src/Server/Http/Controllers/OAuthRegisterController.php
    $client = $clients->createAuthorizationCodeGrantClient(
    name: $this->resolveClientName($validated),
    redirectUris: $validated['redirect_uris'],
    confidential: false,
    enableDeviceFlow: false,
);

    だれでも呼べる住所なので、回数の上限を2重にしています（案内と通行証は IP ごとに1分60回、自己登録はさらに IP ごとに1時間20回）。AI の会社のサーバーの IP は、その会社の利用者みんなで同じなので、きつくしすぎない数にしています。

    src/app/Providers/AiConnectServiceProvider.php
    RateLimiter::for('oauth', fn (Request $r) => Limit::perMinute(60)->by($r->ip()));                    // 案内・通行証の受け渡し
RateLimiter::for('oauth-register', fn (Request $r) => Limit::perHour(20)->by($r->ip()));             // AI の自己登録
    ここが大事戻り先を絞るのは、よその人が作った偽の AI に引換券が渡らないようにするためです。戻り先を足すときは、同意の画面に出す行き先の会社（ai_connect.consent.companies）とプライバシーポリシーの文も一緒に直します。

3. 同意の画面：本人がブラウザで「許可する」を押す

  1. ブラウザ

    AI が、利用者のブラウザで同意の画面の住所を開く

    登録の番号をもらった AI は、利用者のブラウザで推理手帳の GET /oauth/authorize を開きます。住所の後ろには、登録の番号・戻り先・範囲・合言葉のしるし（code_challenge）などが付いています。テストでは、AI が開く住所を次の形で作っています。

    src/tests/Feature/Ai/Concerns/ConnectsAi.php
    return '/oauth/authorize?'.http_build_query([
    'response_type' => 'code',
    'client_id' => $appId,
    'redirect_uri' => $redirect,
    'scope' => 'mcp:use',
    'state' => 'state-123',
    'code_challenge' => $challenge,
    'code_challenge_method' => 'S256',

    この住所は、ふだんの住所の表が読み込む src/routes/web/ai.php にあります。こちらは利用者のブラウザで開く住所なので、web のグループ（セッション・CSRF）が付き、さらに auth（ログイン済みか）と agreed（利用規約に同意済みか）の見張り役で囲んでいます。

    src/routes/web/ai.php
    Route::middleware(['auth', 'agreed'])->group(function () {
    // 同意の画面「ChatGPT に、あなたの事件の記録を読ませてよいですか？」（画面は views/oauth/authorize）
    Route::get('/oauth/authorize', [AuthorizationController::class, 'authorize'])->name('passport.authorizations.authorize');

    Route::middleware('throttle:writes')->group(function () {
        // 許可する・やめる（同意の画面のボタン）
        Route::post('/oauth/authorize', [ApproveAuthorizationController::class, 'approve'])->name('passport.authorizations.approve');
        Route::delete('/oauth/authorize', [DenyAuthorizationController::class, 'deny'])->name('passport.authorizations.deny');

    受付は Passport の AuthorizationController などをそのまま使います。ただし Passport が自分で住所を作ると、推理手帳の auth・agreed の囲みが付きません。そこで、Passport が住所を作るのを止め、上のように同じ名前で置き直しています。

    src/app/Providers/AiConnectServiceProvider.php
    public function register(): void
{
    Passport::ignoreRoutes();
    Passport::$deviceCodeGrantEnabled = false;
}

    $deviceCodeGrantEnabled = false は、使わない許可のしかた（テレビなど、画面のない機械向けの方式）を切っています。

  2. 見張り役

    ログインしていなければ Google へ、利用規約がまだなら同意の画面へ

    ChatGPT から開いたブラウザでは、推理手帳にログインしていないこともあります。見張り役 auth は、ログインしていない人を redirectGuestsTo で決めた行き先へ送ります。ふだんはトップですが、この住所から来た人だけは、ボタンを1回減らすため Google のログイン（1章）へ直接送ります。

    src/bootstrap/app.php
    $middleware->redirectGuestsTo(fn (Request $request) => $request->is('oauth/authorize') ? route('auth.google') : route('home'));

    送り出すとき、Laravel は「もともと開こうとした住所」をセッションに覚えます（url.intended）。Google のログインが終わると、受付は redirect()->intended(…) で、覚えた住所＝同意の画面へ戻します。

    src/app/Http/Controllers/Auth/GoogleLoginController.php
    return redirect()->intended(Landing::url());

    ログインしていても、利用規約にまだ同意していない人は、見張り役 agreed（EnsureAgreed）が同意の画面 /agree へ送ります。こちらも redirect()->guest(…) で住所を覚えるので、同意したあとは同意の画面（AI の）へ戻ります。利用規約に同意する前の人には、AI への許可を出させません。

    src/app/Http/Middleware/EnsureAgreed.php
    if ($request->user() !== null && ! $request->user()->hasAgreed()) {
    return redirect()->guest(route('agree.show'));
}

    この3つの動き（Google へ送って住所を覚える・同意前は /agree へ・同意のあと戻る）は、テスト tests/Feature/Ai/AuthorizeTest が確かめています。

    src/tests/Feature/Ai/AuthorizeTest.php
    $this->get($url)->assertRedirect(route('auth.google'));
// …（省略）…
$this->actingAs(User::factory()->unagreed()->create())->get($url)->assertRedirect(route('agree.show'));
$this->assertDatabaseCount('oauth_auth_codes', 0);
  3. サーバー

    Passport の受付が申し込みを確かめ、同意の画面を出す

    見張り役を通ると、Passport の AuthorizationController::authorize が動きます。まず申し込みの中身を確かめます（登録の番号があるか、戻り先が登録したものと同じか、合言葉のしるしの形など）。

    src/vendor/laravel/passport/src/Http/Controllers/AuthorizationController.php
    $authRequest = $this->withErrorHandling(
    fn (): AuthorizationRequestInterface => $this->server->validateAuthorizationRequest($psrRequest),
// …（省略）…

4. 引換券を通行証に引き換える

  1. AI の会社のサーバー

    引換券＋合言葉 → 通行証（1時間）と更新の札（30日）

    引換券を受け取った AI の会社のサーバーは、推理手帳の POST /oauth/token に、引換券と合言葉を送ります。ここで守りになるのが PKCE（ピクシー）です。役目は「引換券を途中で盗まれても使えないようにする」こと。たとえると、預かり札に、あとで言う合言葉の「しるし」だけを先に書いておくやり方です。中身は、AI が最初にでたらめな合言葉（code_verifier）を作り、そのしるし（SHA-256 という計算で作った code_challenge。しるしから合言葉は逆算できない）だけを 3 の住所に付けておきます。引き換えのときに合言葉そのものを出し、Passport がしるしと合うかを確かめます。合言葉を知っているのは AI だけです。

5. 窓口 /mcp：見張り役を通って、読むだけの道具へ

  1. 見張り役

    よその画面からの呼び出しを断る（RejectForeignOrigin）

    ここからは、利用者がチャットで「体操着の事件を見て、ほかの見立てを出して」のように頼んだときの流れです。AI の会社のサーバーは、通行証を Authorization: Bearer … のヘッダに入れて POST /mcp を呼びます。routes/ai.php で付けた見張り役が、上から順に4つ動きます（laravel/mcp が付ける形の確かめの見張り役のあと）。

    1つ目の RejectForeignOrigin は、ブラウザから窓口を呼ばれたときの守りです。ブラウザは、よその画面から送るとき、どの画面から送ったかを Origin のヘッダで名乗ります。MCP の決まりでは、窓口がこれを確かめることになっています（悪いサイトが利用者のブラウザを使って窓口を呼ぶ攻撃を防ぐため）。AI の会社のサーバーからの呼び出しには Origin が付かないので、そのまま通ります。

    src/app/Http/Middleware/RejectForeignOrigin.php

    return response()->json(['error' => 'forbidden_origin'], 403);
}

この章のまとめ
  1. 窓口 POST /mcp は、利用者が自分の ChatGPT・Claude から推理手帳の記録を読むだけの入口。AI は候補を出す役で、正誤は決めない。
  2. AI の側の住所（案内・自己登録・通行証・窓口）は routes/ai.php（見張り役のグループなし）。利用者のブラウザで開く住所（同意の画面・つなぐのをやめる）は routes/web/ai.php（auth・agreed）。
  3. つなぐ流れ：通行証なしで呼ぶ → 401 と案内の住所 → 自己登録（戻り先は3つだけ）→ 本人がログイン・利用規約の同意のうえで、自前の同意の画面で「許可する」→ 引換券＋PKCE の合言葉で通行証（1時間）と更新の札（30日）。
  4. 窓口では、よその画面を断る → 通行証 → 範囲 mcp:use → 回数制限、の順に見張り役が確かめ、読むだけの道具4つが Queries/Ai/* で組み立てる。見える事件の決まりは VisibleCases の1か所（本人の・仕事の場面でない事件）で、見せ合う前の相棒の見立ては隠す。
  5. 設定の「つなぐのをやめる」は、その AI の通行証・更新の札・引換券を取り消し、次の呼び出しから 401。取り消した行・使われなかった登録は毎日片づけ、退会のときは明示して消す。
  6. 窓口を使わない道として、事件の画面の写すボタンがある。文を端末のクリップボードに写すだけで、アプリからは送らない。
