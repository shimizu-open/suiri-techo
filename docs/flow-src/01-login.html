1Google でログインする（登録から同意まで）

Google アカウントを持っている人として、推理手帳を使いはじめたい。だから、トップの「Google ではじめる」を押し、Google でアカウントを選び、はじめる前の2つの確認にチェックを入れる。

この章で追う道筋：GET /（HomeController）→ 「Google ではじめる」→ GET /auth/google（見張り役 StartSession・throttle:auth・guest → GoogleLoginController::redirect → Socialite が合言葉 state と PKCE を預かり箱に入れて Google へ転送）→ Google の画面 → GET /auth/google/callback（GoogleLoginController::callback → Socialite が合言葉を確かめて利用者の情報をもらう → 用事 LoginWithGoogle：users を探す／新しく登録（招待制のときだけ invitations で招待を確かめる）→ Auth::login → セッションを作り直す）→ GET /agree → POST /agree（AcceptTermsRequest → AcceptTerms：agreed_at）→ /today。おまけに POST /logout。

  1. ブラウザ

    トップ / を開く

    アドレスバーに https://suiri.agi-japan.com/（手元では http://localhost:8086/）と入れると、ブラウザは GET / を送ります。住所の表では、トップは routes/web/auth.php のいちばん上にあります。

    src/routes/web/auth.php
    // トップ（ログイン前）。ログイン済みなら最初の画面へ送る
Route::get('/', HomeController::class)->name('home');

    受付の書き方が [HomeController::class, 'index'] ではなく HomeController::class だけになっています。これは1つの用事だけの受付（シングルアクションコントローラー）で、Laravel はそのクラスの __invoke という関数を呼びます。トップには auth も guest も付いていないので、ログインしていてもいなくても届きます（通る見張り役は、どの住所にも付く web のひとまとまりだけ。0章）。

  2. サーバー

    受付 HomeController：ログイン前ならトップ、ログイン済みならきょうの画面へ

    src/app/Http/Controllers/HomeController.php
    /** トップを返す。ログイン済みなら最初の画面（いつも今日の画面。行き先は App\Support\Landing が決める）へ送る */
public function __invoke(Request $request): View|RedirectResponse
{
    // ログイン済みなら、トップは見せずに今日の画面へ送る
    if ($request->user() !== null) {
        return redirect(Landing::url());
    }

    return view('home', ['googleReady' => GoogleLoginController::enabled()]);
}

    $request->user() は「いまログインしている人」を返します（していなければ null）。ログイン済みの人にトップを見せても意味がないので、Landing::url()（最初の画面の住所を決める小さな係）へ転送します。

    src/app/Support/Landing.php
    /** 最初の画面の URL を返す */
public static function url(): string
{
    return route('today');
}

    まだログインしていない人には、画面 home（src/resources/views/home.blade.php）を返します。そのとき googleReady という値を1つ渡します。中身は GoogleLoginController::enabled() の答えで、「Google の鍵が設定してあるか」です。

    src/app/Http/Controllers/Auth/GoogleLoginController.php
    /** Google でのログインが使えるか（クライアント ID とシークレットが両方設定されているか）を返す */
public static function enabled(): bool
{
    return filled(config('services.google.client_id')) && filled(config('services.google.client_secret'));
}

    config('services.google.client_id') は設定ファイル src/config/services.php の値で、元は .env の GOOGLE_CLIENT_ID です。Google に「このアプリです」と名乗るための番号と合言葉で、Google Cloud で作ります（作り方は解体新書の 11章）。filled は「空でない」かを返す関数です。

  3. ブラウザ

    トップの画面と「Google ではじめる」のボタン

    トップの画面は、題字・ひとことの説明・親子で手帳を使う絵・できることの3行・ログインのボタンを上から並べ、その下に手帳の使い方（4つの手順）とお約束を置きます。スマホでもスクロールせずにボタンを押せる高さに収めています。文は画面に直書きせず、config('suiri.home') から引きます。

    src/resources/views/home.blade.php
    @php($h = config('suiri.home'))
{{-- …（省略）… --}}
    <ul class="mt-4 space-y-2.5">
      {{-- できることの3行を1つずつ取り出し、段の絵つきで並べる --}}
      @foreach ($h['points'] as $point)
        <x-auth.intro-line :icon="$point['icon']" :tone="$point['tone']">{{ $point['text'] }}</x-auth.intro-line>
      @endforeach
    </ul>

    <div class="mt-5 space-y-2">
      <x-auth.google-button :ready="$googleReady" :label="$h['button']" />
      <p class="text-xs text-muted">{{ config('suiri.invite_only') ? $h['invite'] : $h['open'] }}</p>
    </div>

    <x-auth.intro-line> は、段の色の丸に段の絵（目・はてな・チェック）を描き、その横に1行の文を置く部品です。3行は「気になったことを『事件』にして、」「『どうしてかな？』の答えを考え、」「決めた日に、本当か確かめよう。」で、手帳の流れをひと目で伝えます。ボタンは部品 <x-auth.google-button> に任せています。ボタンの下の一文は、招待制（config('suiri.invite_only') が true）なら「招待制です。はじめると、…」（invite）、既定の一般公開なら「はじめると、利用規約とプライバシーポリシーを確かめる画面に進むよ。」（open）を出し分けます（? : は「左が正しければ前、そうでなければ後ろ」の書き方）。

    src/resources/views/components/auth/google-button.blade.php
    @props(['ready' => false, 'label' => 'Google でログイン'])
{{-- 鍵が設定されていればログインのボタン、なければ「準備中」の札を出す --}}
@if ($ready)
  <a href="{{ route('auth.google') }}" class="flex min-h-14 w-full items-center justify-center gap-3 rounded-full border border-[#747775] bg-white px-5 text-lg font-medium text-[#1f1f1f] no-underline hover:bg-[#f8f9fa]">
{{-- …（省略）… --}}
    {{ $label }}
  </a>
@else
  <p class="flex min-h-14 w-full items-center justify-center rounded-full border border-dashed border-rule px-5 text-base font-semibold text-muted">
    Google でのログインは準備中です
  </p>
@endif

    :ready="$googleReady" の : は「文字ではなく PHP の値として渡す」という印です。部品の側では @props で受け取り、鍵があれば <a href="/auth/google"> のリンクを、なければ押せない「準備中」の札を出します。ボタンの文字は label で受け取り、トップでは「Google ではじめる」です。高さは 56px（min-h-14）で、子どもの指でも押しやすい大きさです。ボタンの見た目（白い面に色つきの G）は Google の決まりどおりで、変えていません。

    ここで大事なのは、ボタンがフォームではなくただのリンクだということです。押すと、ブラウザは GET /auth/google を送ります。

  4. サーバー

    住所の表：/auth/google には guest と throttle:auth が付く

    src/routes/web/auth.php
    // Google へ送り出す・Google から戻る（ログイン前だけ。回数制限つき）
Route::middleware(['guest', 'throttle:auth'])->group(function () {
    Route::get('/auth/google', [GoogleLoginController::class, 'redirect'])->name('auth.google');
    Route::get('/auth/google/callback', [GoogleLoginController::class, 'callback'])->name('auth.google.callback');
});

    送り出す住所と戻ってくる住所の2つを、同じ囲みに入れています。囲みに付けた見張り役は2つです。

    • guest：ログインしていない人だけ通す。
    • throttle:auth：1分あたりの回数を数え、多すぎたら止める。

    web のひとまとまりと合わせて、Laravel に並べ替えさせた実際の順番を出すと、次のとおりでした（0章 の並べ替えの表のとおり）。

    1. EncryptCookies：Cookie を暗号から元に戻す
    2. AddQueuedCookiesToResponse：あとで渡すと決めた Cookie を返事に付ける
    3. StartSession：番号札から預かり箱（セッション）を開く（次のステップ）
    4. ShareErrorsFromSession：前の入力の間違いを画面で使えるようにする
    5. PreventRequestForgery：ニセの送信でないか（GET は読むだけなので素通り。11章）
    6. ThrottleRequests:auth：回数を数える
    7. SubstituteBindings：住所の穴を表の行に替える（この住所には穴がないので何もしない）
    8. RedirectIfAuthenticated（guest）：ログイン済みなら追い返す
  5. 見張り役

    StartSession：番号札（Cookie）から、その人の預かり箱（セッション）を開く

    ログインのしくみの土台はセッションです。サーバーは、お願いが来るたびに「前のお願いと同じ人か」を覚えていません。そこで、初めて来たブラウザに番号札（セッション ID を入れた Cookie）を渡し、サーバーの側にはその番号の預かり箱を用意します。ブラウザは次から毎回その番号札を見せるので、サーバーは同じ箱を開けて「この人はさっきの人だ」と分かります。

    たとえるとコインロッカーです。鍵（番号札）は客が持ち、荷物（ログイン中の人の番号・途中の合言葉・お知らせの文）はロッカー（サーバー）の中にあります。鍵だけ見ても中身は分かりません。
    src/vendor/laravel/framework/src/Illuminate/Session/Middleware/StartSession.php
    public function getSession(Request $request)
{
    return tap($this->manager->driver(), function ($session) use ($request) {
        $session->setId($request->cookies->get($session->getName()));
    });
}

    お願いに付いてきた Cookie から番号を取り出し、その番号の箱を用意します。番号札がない・知らない番号なら、新しい番号の空の箱になります。

    src/vendor/laravel/framework/src/Illuminate/Session/Middleware/StartSession.php
    protected function handleStatefulRequest(Request $request, $session, Closure $next)
{
    // …（省略）…
    $request->setLaravelSession(
        $this->startSession($request, $session)
    );

    $this->collectGarbage($session);

    $response = $next($request);

    $this->storeCurrentUrl($request, $session);

    $this->addCookieToResponse($response, $session);

    // …（省略）…
    $this->saveSession($request);

    return $response;
}
    1. startSession：箱の中身を読み込み、お願い（$request）に持たせる。これで受付や見張り役が $request->session() で箱を使える。
    2. $next($request)：次の見張り役 → 受付へ進む。返事ができるまで待つ。
    3. addCookieToResponse：返事に番号札（Set-Cookie）を付ける。
    4. saveSession：箱の中身を保存する。
    このとき動くデータ
    • 箱の置き場所は sessions 表（.env の SESSION_DRIVER=database）。1つの箱が1行で、列は id（番号）・user_id（ログイン中の人。まだなら空）・ip_address・user_agent・payload（中身）・last_activity。
    • 番号札の Cookie の名前は設定 session.cookie で、元は APP_NAME を英数字にしたものです。手元の環境で確かめると -session でした（アプリ名が日本語の「推理手帳」で、英数字にすると空になるため）。中身の番号は、見張り役 EncryptCookies が暗号にしてから渡します。
    • 箱は SESSION_LIFETIME=120（分）使われないと期限切れになります。
  6. 見張り役

    throttle:auth：1つの IP から1分に10回まで

    回数制限（throttle）は、同じ相手から短い間にたくさん来たお願いを止める見張り役です。auth は数え方の名前で、中身は AppServiceProvider に書いてあります。

    src/app/Providers/AppServiceProvider.php
    RateLimiter::for('auth', fn (Request $r) => Limit::perMinute(10)->by($r->ip()));       // Google へのログイン・戻り

    ログイン前はまだ「誰か」が分からないので、IP アドレスごとに数えます。送り出し（/auth/google）と戻り（/auth/google/callback）は同じ auth の数え方なので、1回のログインで2回と数えます。11回目からは「429（多すぎる）」の画面になります。数え方のしくみは 11章 でくわしく追います。

  7. 見張り役

    guest：ログイン済みの人はきょうの画面へ追い返す

    src/vendor/laravel/framework/src/Illuminate/Auth/Middleware/RedirectIfAuthenticated.php
    public function handle(Request $request, Closure $next, string ...$guards): Response
{
    $guards = empty($guards) ? [null] : $guards;

    foreach ($guards as $guard) {
        if (Auth::guard($guard)->check()) {
            return redirect($this->redirectTo($request));
        }
    }

    return $next($request);
}

    Auth::guard()->check() は「ログインしているか」です。していれば受付まで進ませず、redirectTo の行き先へ転送します。行き先は bootstrap/app.php で決めてあります。

    src/bootstrap/app.php
    // ログインが必要な画面に、ログインしていない人が来たときの行き先（トップ）。
// AI（ChatGPT・Claude）の同意の画面から来た人だけは、トップのボタンを1回減らすため Google のログインへ直接送る（ログイン後にここへ戻る）
$middleware->redirectGuestsTo(fn (Request $request) => $request->is('oauth/authorize') ? route('auth.google') : route('home'));
// ログイン前だけの画面（Google へ送り出すなど）に、ログイン済みの人が来たときの行き先（最初の画面）
$middleware->redirectUsersTo(fn () => Landing::url());

    まだログインしていない今回は、そのまま受付へ進みます。上の redirectGuestsTo は逆向きの決まりで、ログインが要る画面にログインしていない人が来たときの行き先です。ふだんはトップへ送りますが、ChatGPT・Claude とつなぐ同意の画面（/oauth/authorize）から来た人だけは、トップを飛ばして Google のログインへ直接送ります。ログインが済むと、下の intended の仕組みで同意の画面へ戻ります（13章）。

  8. サーバー

    受付 GoogleLoginController::redirect：Google の画面へ送り出す

    src/app/Http/Controllers/Auth/GoogleLoginController.php
    /** Google の画面へ送り出す（GET /auth/google）。鍵が未設定なら「準備中」と知らせてトップへ戻す */
public function redirect(): RedirectResponse|SymfonyRedirect
{
    // Google の鍵がまだ設定されていなければ、トップへ戻して「準備中」と知らせる
    if (! self::enabled()) {
        return redirect()->route('home')->with('error', 'Google でのログインは準備中です。');
    }

    return Socialite::driver('google')
        ->enablePKCE() // 戻りでも enablePKCE() を呼ぶ（呼ばないと確かめの合言葉が Google に送られない）
        ->with(['prompt' => 'select_account']) // 家族で同じ端末を使うことがあるので、毎回アカウントを選ばせる
        ->redirect();
}

    Socialite は、Google や GitHub でのログインを引き受ける Laravel の公式の道具です（src/vendor/laravel/socialite）。Google とのやりとりの細かい決まり（OAuth：アプリが本人の許しを得て、Google から情報を受け取る手順）を代わりにこなします。

    • driver('google')：Google 用の係（GoogleProvider）を使う。
    • enablePKCE()：PKCE という確かめを付ける（次のステップ）。
    • with(['prompt' => 'select_account'])：Google の画面で、毎回アカウントを選ばせる。家族で1台の端末を使うと、前の人のアカウントのまま入ってしまうことがあるからです。
    • redirect()：Google の画面への転送を作る。

    ->with('error', '…') は、転送先の画面で1回だけ出すお知らせを預かり箱に入れる書き方です（鍵が未設定のときだけ）。

  9. サーバー

    Socialite が合言葉（state）と PKCE の種を預かり箱に入れ、Google の住所を作る

    src/vendor/laravel/socialite/src/Two/AbstractProvider.php
    public function redirect()
{
    $state = null;

    if ($this->usesState()) {
        $this->request->session()->put('state', $state = $this->getState());
    }

    if ($this->usesPKCE()) {
        $this->request->session()->put('code_verifier', $this->getCodeVerifier());
    }

    return new RedirectResponse($this->getAuthUrl($state));
}

    Google へ送り出す前に、2つの「あとで照らし合わせる種」を作り、この人の預かり箱に入れます。

    • state：でたらめな40文字の合言葉。Google から戻ってきたとき、同じ合言葉を持っているかを確かめます。別の人が作った戻りの住所を踏まされても、合言葉が合わないので止まります。
    • PKCE（ピクシー）の code_verifier：でたらめな96文字。Google にはこれを sha256 で混ぜた形（code_challenge）だけを渡し、元の96文字は戻りのときに初めて Google に見せます。途中で受け渡しの番号（code）を盗まれても、元の96文字を知らない人は使えません。
    src/vendor/laravel/socialite/src/Two/AbstractProvider.php
    protected function getCodeFields($state = null)
{
    $fields = [
        'client_id' => $this->clientId,
        'redirect_uri' => $this->redirectUrl,
        'scope' => $this->formatScopes($this->getScopes(), $this->scopeSeparator),
        'response_type' => 'code',
    ];

    if ($this->usesState()) {
        $fields['state'] = $state;
    }

    if ($this->usesPKCE()) {
        $fields['code_challenge'] = $this->getCodeChallenge();
        $fields['code_challenge_method'] = $this->getCodeChallengeMethod();
    }

    return array_merge($fields, $this->parameters);
}
    src/vendor/laravel/socialite/src/Two/GoogleProvider.php
    protected $scopes = [
    'openid',
    'profile',
    'email',
];
// …（省略）…
protected function getAuthUrl($state)
{
    return $this->buildAuthUrlFromBase('https://accounts.google.com/o/oauth2/auth', $state);
}

    Google の住所 https://accounts.google.com/o/oauth2/auth のうしろに、?client_id=…&redirect_uri=…/auth/google/callback&scope=openid profile email&response_type=code&state=…&code_challenge=…&code_challenge_method=S256&prompt=select_account を付けます。scope（もらいたい情報の範囲）は openid・profile・email の3つだけ、つまり名前・メールアドレス・アイコン・Google の利用者番号だけです。カレンダーの許しはここでは求めません（つなぐのは別の手順。9章）。

    このとき動くデータ
    • 書く：預かり箱（sessions 表の payload）に state と code_verifier
    • 返す：302 の転送。行き先（Location）は上の Google の住所
  10. ブラウザ

    Google の画面でアカウントを選ぶ → 推理手帳へ戻される

    ブラウザは転送に従って Google の画面を開きます。ここから先は Google のサーバーとのやりとりで、推理手帳のプログラムは動いていません。利用者がアカウントを選び、（初めてなら）「推理手帳に名前・メールアドレス・プロフィール写真を見せてよいか」に同意すると、Google はブラウザを redirect_uri へ転送し直します。

    このとき動くデータ
    • 送る：GET /auth/google/callback?state=（行きと同じ合言葉）&code=（受け渡しの番号）&scope=…
    • 送る：番号札の Cookie（行きと同じ預かり箱を開けるため）
    たとえると役所の窓口（Google）で本人確認をしてもらい、「この人は本人です」という引換券（code）をもらって、元の店（推理手帳）に戻ってくるようなものです。店は引換券を役所に持っていき、本物の証明書（利用者の情報）と取り換えます。
  11. サーバー

    受付 GoogleLoginController::callback：戻ってきた人を受け取る

    見張り役は行きと同じ（StartSession → throttle:auth → guest）です。受付の前半は、Google からの情報の受け取りです。

    src/app/Http/Controllers/Auth/GoogleLoginController.php
    public function callback(Request $request, LoginWithGoogle $login): RedirectResponse
{
    // Google の鍵がまだ設定されていなければ、トップへ戻して「準備中」と知らせる
    if (! self::enabled()) {
        return redirect()->route('home')->with('error', 'Google でのログインは準備中です。');
    }

    // Google から利用者の情報を受け取る。キャンセルや時間切れ・合言葉の食い違いで失敗したら、トップへ戻して知らせる
    try {
        $google = Socialite::driver('google')->enablePKCE()->user();
    } catch (Throwable $e) {
        Log::info('Google ログインを中断', ['error' => class_basename($e)]); // メールアドレスなどはログに書かない

        return redirect()->route('home')->with('error', 'Google でのログインを完了できませんでした。もう一度お試しください。');
    }

    引数の LoginWithGoogle $login は、Laravel がその場で作って渡してくれる用事の係です（0章）。

    try { … } catch (Throwable $e) { … } は「試してみて、どんな失敗が起きても受け止める」書き方です。Google の画面で「キャンセル」を押した・時間がたって合言葉が消えた・Google につながらない、などのとき、エラーの画面を出さずにトップへ戻して「もう一度お試しください」と知らせます。ログには失敗の種類（class_basename($e)：たとえば InvalidStateException）だけを書き、メールアドレスなどは書きません（11章）。

  12. サーバー

    Socialite が合言葉を照らし合わせ、引換券を利用者の情報に換える

    src/vendor/laravel/socialite/src/Two/AbstractProvider.php
    public function user()
{
    if ($this->user) {
        return $this->user;
    }

    if ($this->hasInvalidState()) {
        throw new InvalidStateException;
    }

    $response = $this->getAccessTokenResponse($this->getCode());

    if (User::where('email', $email)->exists()) {

    }

    1. メールアドレスを小文字にそろえる（Invitation::normalize）：Irene@Example.com と irene@example.com を同じものとして扱うため。招待を足すときも、探すときも、必ずこれを通します。
      src/app/Models/Invitation.php

{

}

/** このメールアドレスが招待されているか（その招待を返す。なければ null） */
public static function findFor(string $email): ?self
{

}
    2. Google がそのメールアドレスを確認済みか（verified）：確認されていないアドレスなら、他人のアドレスを名乗っているかもしれないので、登録しません。一般公開でも招待制でも同じです。

    • 書く：users に1行（google_id・name・email・avatar_url。agreed_at はまだ空）
    • 書く（招待の行があるとき）：invitations のその行の used_at

    1. ログインの印を箱に書く：put($this->getName(), $id)。名前は login_web_ に続く記号の並び、値は users の id です。次のお願いからは、この印を見て「ログイン中の人」を見分けます。

    • 書く：sessions（新しい番号の行。user_id にこの人の id が入る）。古い番号の行は消える
    • 書く：users.remember_token（まだ空なら）
    • 返す：番号札の Cookie（新しい番号）と、remember_web_… の Cookie

    受付は薄く、用事を呼んで転送するだけです。用事は、まだ同意していなければ agreed_at に今の日時を入れます。2回送られても、最初に同意した日時は変えません。そのあと、行きたかった所（なければきょうの画面）へ「ようこそ、推理手帳へ。」の緑のお知らせつきで転送します。

    このとき動くデータ
    • 書く：users のこの人の行の agreed_at
  22. 見張り役

    ほかの画面には agreed：同意の前の人を同意の画面へ回す

    きょうの画面・タスク・事件・手引き・ふりかえり・設定・カレンダー・ChatGPT とつなぐ同意の画面の住所には、どれも ['auth', 'agreed'] が付いています（0章）。agreed は、このアプリが自分で足した見張り役 EnsureAgreed の呼び名です（bootstrap/app.php の alias）。

    src/app/Http/Middleware/EnsureAgreed.php
    /** 同意済みならそのまま進め、まだなら同意の画面へ送る */
public function handle(Request $request, Closure $next): Response
{
    // ログイン中で、まだ同意していなければ、同意の画面へ送る（同意したあとは元の画面へ戻れるよう覚えておく）
    if ($request->user() !== null && ! $request->user()->hasAgreed()) {
        return redirect()->guest(route('agree.show'));
    }

    return $next($request);
}

    redirect()->guest(…) は、ただの転送ではなく「いま開こうとした住所を url.intended に覚えてから転送する」書き方です。だから、同意の前に /settings を開こうとした人は、同意のあと /settings に戻れます（テスト AgreementTest の test_both_checks_are_required_to_agree で確かめています）。

    同意が済めば、ふだんは /today（2章）に着きます。ChatGPT・Claude とつなぐ途中で初めてログインした人は、覚えておいた同意の画面（/oauth/authorize）へ戻ります（13章）。

  23. サーバー

    おまけ：ログアウト（POST /logout）

    設定の画面の下のほう、ログインしているアカウントの横の「ログアウト」（部品 <x-settings.account>）は、@csrf 入りのフォームで POST /logout を送ります。リンク（GET）にしないのは、ほかのサイトに置かれたリンクや画像で勝手にログアウトさせられないようにするためです。

    src/app/Http/Controllers/Auth/LogoutController.php
    /** ログアウトして、セッションを作り直し、トップへ戻す */
public function __invoke(Request $request): RedirectResponse
{
    Auth::logout();
    $request->session()->invalidate(); // セッションの中身を捨てる
    $request->session()->regenerateToken(); // フォームの合言葉（CSRF トークン）も作り直す

    return redirect()->route('home')->with('status', 'ログアウトしました。');
}
    1. Auth::logout()：預かり箱からログインの印を消し、「ログインしたまま」の Cookie も消します。users.remember_token も新しい文字に替えるので、ほかの端末に残っていた「ログインしたまま」の札も使えなくなります。
    2. invalidate()：箱の中身を全部捨て、番号も作り直します。
    3. regenerateToken()：フォームの合言葉も新しくします。
    このとき動くデータ
    • 書く：users.remember_token（新しい文字に）
    • 書く：sessions（古い番号の行を消し、新しい空の箱）
この章のまとめ
  1. ログインの土台はセッション。ブラウザは番号札（Cookie）を持ち、中身は sessions 表の預かり箱にある。
  2. 「Google ではじめる」はただのリンク。GoogleLoginController::redirect → Socialite が合言葉 state と PKCE の種を箱に入れ、Google へ転送する。もらう情報は名前・メール・アイコン・Google の番号（sub）だけ。
  3. 戻り（callback）で Socialite が合言葉を照らし合わせ、引換券（code）を利用者の情報に換える。失敗はトップへ戻し、ログには失敗の種類だけを書く。
  4. 用事 LoginWithGoogle は、google_id（sub）で前からの人を探し、初めての人は「確認済みのメール・（招待制のときだけ）招待あり・同じメールの別人なし」を確かめてから users に登録し、招待の行があれば used_at を入れる。既定は一般公開で、SUIRI_INVITE_ONLY=true で招待制に切り替わる。だめなら LoginRefused の文をトップに出す。
  5. Auth::login が箱にログインの印を書き、番号を作り直す（セッション固定攻撃の対策）。「ログインしたまま」の札も渡す。
  6. 初めての人は /agree で2つのチェック（AcceptTermsRequest）→ AcceptTerms が agreed_at を入れる。ほかの画面の見張り役 agreed が、同意の前の人を同意の画面へ回し、済んだら元の画面（なければ /today）へ戻す。
