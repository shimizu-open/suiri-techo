3タスクを足す・済ませる

手帳を使う人として、思いついたやることをすぐ書きとめ、済んだら印を付けたい。だから、「何をする？」の欄に題名を入れて「書く」を押し、済んだら行の左の丸を1回押す。

この章で追う道筋：POST /tasks → 見張り役（auth → throttle:writes → agreed）→ 形の検証 StoreTaskRequest → 受付 TaskController::store → 用事 CreateTask → tasks に1行 → 見張る係 TaskObserver がカレンダーへの書き出しの仕事を jobs に予約 → 今日の画面へ転送。続けて「日にちや時間も決める」（POST /tasks/draft）・一覧（GET /tasks?view=）・済ませる（POST /tasks/{task}/done：権限 TaskPolicy → CompleteTaskRequest → CompleteTask）・戻す・直す・消す

3-1　タスクを足す

  3. 見張り役

    見張り役を通る：回数制限 throttle:writes は1人1分に60回まで

    POST /tasks で実際に動く見張り役は、並べ替えたあと次の順です。

    EncryptCookies → AddQueuedCookiesToResponse → StartSession → ShareErrorsFromSession → PreventRequestForgery（合言葉 _token を確かめる）→ Authenticate（auth）→ ThrottleRequests:writes → SubstituteBindings → EnsureAgreed（agreed）

    回数制限（throttle）は、ボタンの連打や、機械で大量に送られることを防ぐ見張り役です。writes は数え方の名前で、中身は AppServiceProvider にあります。

// …（省略）…

    題名の似た過去のタスクの実績（SimilarTasksQuery）

    予想時間の欄のすぐ下に、題名の似た、前に済ませたタスクの「予想 → 実際」を出します。見積もりが楽観しすぎないように、前回の実績を見せるためです。

    src/app/Queries/Tasks/SimilarTasksQuery.php
    return $user->tasks()->done()->whereNotNull('actual_minutes')
    ->when($exceptId, fn ($query) => $query->whereKeyNot($exceptId))
    ->latest('done_at')->latest('id')->limit(config('suiri.tasks.similar.pool'))
    ->get(['id', 'title', 'duration_minutes', 'actual_minutes', 'done_at'])
    ->map(fn (Task $task) => ['task' => $task, 'score' => self::score($key, self::normalize($task->title))])
    ->filter(fn (array $pair) => $pair['score'] >= $minScore)
    ->sortByDesc('score')
    ->take(config('suiri.tasks.similar.limit'))
    • 相手は、この人の済んだタスクのうち、かかった時間が入っているもの。新しい順に 200 件（similar.pool）まで。
    • 似ている度合いは 0〜1。空白と記号を取ってから比べ、同じ題名なら 1、片方がもう片方を含むなら 0.8、ほかは「2文字ずつの組」がどれだけ重なるか（ダイス係数）で計ります。日本語は単語の区切りがないので、2文字ずつに切って比べます（「買い物」と「買い物に行く」は似ている、「牛乳を買う」とは似ていない）。
    • 0.5（similar.min_score）以上のものを、似ている順に 3 件（similar.limit）まで。見せるときは新しい順で、先頭を「前回」と呼びます。

    出すのは部品 <x-task.similar-history> で、「何分かかりそう？」のすぐ下に、「前の『買い物』は 30分の予定で、45分かかったよ（15分長かった）」のような一言で出します。

    • どちらも任意で、何もしなくてかまいません。お知らせは一度きりなので、次に画面を開いたときには枠は消えています。
  8. サーバー

    未完了に戻す（DELETE /tasks/{task}/done）

    済んだタスクの丸をもう一度押すと、_method=DELETE 付きで送られます。見張り役はステップ3と同じ（回数制限・持ち主の確認）、形の検証 ReopenTaskRequest も「確かめるタスクは戻せない」を確かめます。

    src/app/Actions/Tasks/ReopenTask.php
    /** 済んだ印を外して保存し、そのタスクを返す */
public function handle(Task $task): Task
{
    $task->done_at = null;
    $task->save();

    return $task;
}

    済んだ日時を空に戻すだけで、かかった時間は残します（まちがえて戻したときに入れ直さなくてよいように）。done_at が変わるので、TaskObserver::updated が書き出しの仕事を出し、予定の題名の「✓ 」が外れます。受付は元の画面へ戻し、「「…」を、まだに戻したよ。」とお知らせします（config('suiri.tasks.flash.reopened')）。

3-4　直す・消す

  1. サーバー

    直す（GET /tasks/{task}/edit → PATCH /tasks/{task}）

    行の題名を押すと直す画面です。直す画面も「何をする？」を大きく出し、日にち・時間・何分・メモは「くわしく決める」の中です。予想から作った確かめるタスクなら、題名は文字で見せるだけ（「予想の文から作ったので、直せないよ。」）にし、上に答え合わせへのボタンを出します。住所に can:update,task が付いているので、他人のタスクは画面さえ開けません。送るときは @method('PATCH') で PATCH になります。形の検証は UpdateTaskRequest で、作るときの決まりを受け継ぎ、確かめるタスクのときだけ決まりを変えます。

    src/app/Http/Requests/Tasks/UpdateTaskRequest.php
    $rules = parent::rules() + [
    'actual_minutes' => ['nullable', 'integer', 'min:1', 'max:'.config('suiri.tasks.max_minutes')],
];
$task = $this->route('task');

// 予想から作った確かめるタスクなら、題名の決まりを外す（送られても受け取らず、題名は予想の文の写しのまま）
if ($task->answeredByPrediction()) {
    unset($rules['title']);
}
// 答え合わせ待ちの予想を確かめるタスクなら、期日を必須にする（予想の確かめる日を空にしない）
if ($task->checksPendingPrediction()) {
    $rules['due_on'] = ['required', 'date_format:Y-m-d'];
}

    決まりから外した項目は validated() に入らないので、確かめるタスクの題名（予想の文の写し）は送られても書き換わりません。用事 UpdateTask は、タスクの保存と予想の確かめる日の書き写しを1つのトランザクションで行います。

    src/app/Actions/Tasks/UpdateTask.php
    return DB::transaction(function () use ($task, $data) {
    $task->fill($data);
    // 期日がなくなったら、開始時刻も消す
    if ($task->due_on === null) {
        $task->starts_at = null;
    }
    $task->save();
    $this->syncPredictionCheck->handle($task);

    return $task;
});
    • 期日を消して「いつか」にしたら、開始時刻も消します（時刻だけ残っても使い道がない）。
    • SyncPredictionCheck：答え合わせ待ちの予想を確かめるタスクなら、期日・開始時刻を予想の確かめる日・時刻にも写します。写すのは日時だけで、予想の文と確かさには触りません（6章）。
    • トランザクションの中で保存しているので、TaskObserver::updated が出す仕事（afterCommit）は、タスクと予想の両方の保存が確定してから jobs 表に入ります（3-1 のステップ10 の addCallback）。途中で失敗して取り消されたら、仕事も出ません。
  2. サーバー

    消す（DELETE /tasks/{task}）：答え合わせ待ちの確かめるタスクは消せない

    直す画面の下の「このやることを消す」は、押すと確認の文が開く部品 <x-ui.confirm>（JavaScript なしの <details>）です。確認の「消す」で DELETE を送ります。住所には can:delete,task が付いています。

    src/app/Http/Requests/Tasks/DeleteTaskRequest.php
    /** 答え合わせ待ちの予想を確かめるタスクでなければ、消してよい */
public function authorize(): bool
{
    return ! $this->route('task')->checksPendingPrediction();
}

/** 消せないときは 403 にし、予想の取り下げを使うよう案内する */
protected function failedAuthorization(): void
{
    throw new AuthorizationException('このタスクは予想を確かめるためのものなので、消せません。確かめるのをやめるときは、予想を取り下げてください。');
}

    答え合わせ待ちの予想を確かめるタスクを消すと、確かめる手立てのない予想だけが残ってしまいます。なので、そういうタスクの直す画面では消すボタンの代わりに「予想を取り下げる」を出し、受付でも断ります。用事 DeleteTask も念のため同じことを確かめてから、モデルの delete() で消します。

    src/app/Actions/Tasks/DeleteTask.php
    public function handle(Task $task): void
{
    // 答え合わせ待ちの予想を確かめるタスクなら止める（答え合わせ待ちの予想だけが残ってしまうため）
    if ($task->checksPendingPrediction()) {
        throw new LogicException('答え合わせ待ちの予想を確かめるタスクは、予想の取り下げで消します。');
    }

    $task->delete();
}

    モデルの delete() で消すので、deleted（消しました）の知らせが出て、見張る係が予定を消す仕事を出します。

    src/app/Observers/TaskObserver.php
    public function deleted(Task $task): void
{
    // まだ予定にしていない・つないでいない人なら、何もしない
    if (blank($task->calendar_event_id) || ! $this->connected($task)) {
        return;
    }

    $this->safely($task, fn () => RemoveTaskFromCalendar::dispatch($task->user_id, $task->calendar_event_id)->afterCommit());
}

    タスクの行はもう消えているので、仕事には「持ち主の番号」と「予定の ID」を渡します（ID は保存の直前に決めておいたもの。3-1 のステップ7）。仕事の中身は 9章。受付は、そのタスクがいた一覧へ戻して「「…」を消したよ。」とお知らせします。

    このとき動くデータ
    • 消す：tasks のこの行
    • 書く：jobs 表に RemoveTaskFromCalendar の1行（つないでいて、予定にしていた場合だけ）
この章のまとめ
  1. タスクの住所は Route::resource の6つと、「日にちや時間も決める」・済ませる・戻すの3つ。書く住所には回数制限 throttle:writes（1人1分60回）、{task} のある住所には持ち主の確認 can が付く。
  2. 送られた中身は FormRequest が先に確かめ、受付は用事（CreateTask・CompleteTask …）に頼んで転送するだけ。持ち主の user_id はいつもログイン中の人から決まる。
  3. すばやく書く欄は「何をする？」の1つだけ。「日にちや時間も決める」は題名を住所に載せず、POST とセッションの「前の入力」で、くわしく書く画面へ持っていく。分の欄は、よく使う分のボタンを押すと欄に入る（minute-chips.js。保存は本人が押したとき）。
  4. 済ませると done_at に日時が入り、お知らせ task_done で元の画面に「できたね！」の枠（1回押すだけの分のボタン・気になる）が出る。確かめるタスクは答え合わせで済む（丸では済ませられない・消せない）。
  5. タスクの担当は Google を知らない。保存のたびに TaskObserver が、つないでいる人のタスクだけ、書き出し・消す仕事を jobs 表に予約する（確定してから・同じタスクは1つにまとめて）。その先は 9章。
