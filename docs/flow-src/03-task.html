3タスクを足す・済ませる・直す

手帳を使う人として、思いついたやることをすぐ書きとめ、済んだら印を付けたい。だから、きょうの画面の「何をする？」の欄に題名を入れて「今日」「明日」「いつか」のどれかを押し、済んだら行の左の丸を1回押す。直したいときは、その行を押して開く。

この章で追う道筋：POST /tasks（押したボタンの due_on つき）→ 見張り役（auth → throttle:writes → agreed）→ 形の検証 StoreTaskRequest → 受付 TaskController::store → 用事 CreateTask → tasks に1行 → 見張る係 TaskObserver がカレンダーへの書き出しの仕事を jobs に予約 → きょうの画面のそのタスクが見える枠へ転送（TaskListQuery::openOf → /today?open=…）。続けて「くわしく」（POST /tasks/draft）・前の一覧の住所（GET /tasks?view= → /today?open=）・済ませる（POST /tasks/{task}/done：権限 TaskPolicy → CompleteTaskRequest → CompleteTask）・戻す・行を開いて直す・消す・気になる

    $this->safely($task, fn () => PushTaskToCalendar::dispatch($task->id)->afterCommit());
}

/** そのタスクの持ち主が、いまカレンダーとつながっているかを返す */
private function connected(Task $task): bool
{
    return CalendarConnection::where('user_id', $task->user_id)->where('status', CalendarStatus::Active)->exists();
}
    • 期日のない「いつか」のタスクは、カレンダーに置く日がないので書き出しません。
    • 持ち主が Google カレンダーとつないでいて、状態が「つながっています」のときだけ、仕事 PushTaskToCalendar を出します。
    • dispatch($task->id)：仕事に渡すのはタスクの番号だけです。題名などの中身は、仕事が動くときに表から読み直します。

この章のまとめ
  1. タスクの住所は Route::resource の6つと、「くわしく」・済ませる・戻すの3つ。書く住所には回数制限 throttle:writes（1人1分60回）、{task} のある住所には持ち主の確認 can が付く。前の一覧の住所 GET /tasks?view=… は画面を返さず、/today?open=… へ移すだけ。
  2. 1行で書く欄は、題名と「今日」「明日」「いつか」の3つの送信ボタン。押したボタンの name="due_on" の値（今日の日付・明日の日付・空）で期日が決まり、Enter は「今日」。「くわしく」は formaction で /tasks/draft へ送り、題名を住所に載せずに、セッションの「前の入力」でくわしく書く画面へ持っていく。分の欄は、よく使う分のボタンを押すと欄に入る（minute-chips.js。保存は本人が押したとき）。
  3. 送られた中身は FormRequest が先に確かめ、受付は用事（CreateTask・CompleteTask …）に頼んで転送するだけ。持ち主の user_id はいつもログイン中の人から決まる。作る・直す・消すのあとは、openOf が決めた、きょうの画面のそのタスクが見える枠へ戻る（今日までなら /today、明日より先なら ?open=upcoming、期日なしなら ?open=someday）。
  4. 済ませると done_at に日時が入り、back(fallback: route('today')) で元の画面（開いていた枠ごと）へ戻り、お知らせ task_done で「できたね！」の枠（1回押すだけの分のボタン・気になる）が出る。確かめるタスクは答え合わせで済む（丸では済ませられない・消せない）。
  5. 行の題名を押すと、その場で開いて「直す」「気になる」「消す」が出る。消すのは確かめの文が開いてから（<x-ui.confirm>）。
  6. タスクの担当は Google を知らない。保存のたびに TaskObserver が、つないでいる人のタスクだけ、書き出し・消す仕事を jobs 表に予約する（確定してから・同じタスクは1つにまとめて）。その先は 9章。
