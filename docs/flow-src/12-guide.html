12手引き：名推理カードで推理して裏返す

ホームズのものの見方を学びたい人として、物語の場面の手がかりだけを読んで、自分ならどう考えるかを考えてから、ホームズの推理と比べたい。だから、手引きの入口で「このカードで遊ぶ」を押し、カードの表を読んで「裏返す」を押す（考えをメモしておきたいときは「メモして裏返す」）。

この章で追う道筋：GET /guide → 受付 GuideController::index → 教材の係 GuideLibrary（database/data/guide/*.json を読んでキャッシュ。nextScene で次に遊ぶカードを選ぶ）→ GET /guide/scenes（一覧）→ GET /guide/scenes/{key}（表。ホームズの推理は渡さない）→ POST /guide/scenes/{key}/attempt → 形の検証 StoreSceneAttemptRequest → 用事 SaveSceneAttempt（メモがあれば scene_attempts に上書き）→ 転送 → GET /guide/scenes/{key}?side=back（裏：自分の考えとホームズの推理を上下に並べる）→ 「次のカードへ」

教材を開く

  1. サーバー

    手引きの住所は、1つの囲みに名前の頭と住所の頭をまとめて付ける

    src/routes/web/guide.php
    Route::middleware(['auth', 'agreed'])->prefix('guide')->name('guide.')->group(function () {
    Route::get('/', [GuideController::class, 'index'])->name('index');
    Route::get('/reasoning', [GuideController::class, 'reasoning'])->name('reasoning');
    Route::get('/skills/{key}', [SkillController::class, 'show'])->name('skills.show');
    Route::get('/scenes', [SceneController::class, 'index'])->name('scenes.index');
    Route::get('/scenes/{key}', [SceneController::class, 'show'])->name('scenes.show');
    Route::post('/scenes/{key}/attempt', SaveSceneAttemptController::class)->middleware('throttle:writes')->name('scenes.attempt');
    Route::get('/practices', [PracticeController::class, 'index'])->name('practices.index');
});
    • ->prefix('guide')：囲みの中の住所の頭に /guide を付けます。'/' は /guide、'/scenes/{key}' は /guide/scenes/{key} になります。
    • ->name('guide.')：囲みの中のルート名の頭に guide. を付けます。'index' は guide.index、'scenes.show' は guide.scenes.show です。
    • 見張り役は、ほかの画面と同じ auth・agreed（ログインして同意した人だけ。1章）。記録を書くのはカードのメモの保存だけなので、そこにだけ throttle:writes（1分に60回まで。11章）を足しています。
    • 穴 {key} には scarlet-watson のような教材のキーが入ります。教材はデータベースの行ではないので、行に取り換える見張り役（0章）は働かず、文字のまま受付に渡ります。
  2. ブラウザ

    ナビの「手引き」を押す

    ログインしたあとの画面には、スマホなら下、パソコンなら左にナビ（今日・タスク・事件・手引き・ふりかえり）があります。「手引き」はただのリンクなので、押すとブラウザは GET /guide を送ります。

  3. サーバー

    受付 GuideController::index：次に遊ぶカードと、ほかの行き先を集める

    src/app/Http/Controllers/Guide/GuideController.php
    public function index(Request $request, GuideLibrary $library, SceneAttemptReader $attempts, DailyPractice $daily): View
{
    $doneKeys = $attempts->keys($request->user());
    $nextScene = $library->nextScene($doneKeys);

    return view('guide.index', [
        'overview' => $library->overview(),
        'skills' => array_column($library->skills(), null, 'key'),
        'scenes' => array_column($library->scenes(), null, 'key'),
        'reasoningNames' => array_column($library->reasoning()['items'], 'name', 'key'),
        'nextScene' => $nextScene,
        'nextNumber' => $nextScene ? $library->position('scenes', $nextScene['key']) : null,
        'nextFresh' => $nextScene && ! in_array($nextScene['key'], $doneKeys, true), // まだ書いていないカードか（全部書いたら最初に戻る）
        'practice' => $daily->for($request->user()),
        'kid' => $request->user()->prefersKidWords(),
    ]);
}

    引数の GuideLibrary $library などは、Laravel がその場で作って渡す係です（0章 の「依存性の注入」）。受付がしていることは、上から次の4つです。

    1. $attempts->keys(…)：この人がメモを書いたカードのキーの一覧を読みます（中身は下の一覧の歩で見ます）。
    2. $library->nextScene($doneKeys)：次に遊ぶカードを1枚選びます。position は、そのカードが並びの何枚目か（カードに出す「No.02」）です。
    3. nextFresh：選んだカードが「まだ書いていないカード」か。全部書き終えて最初のカードに戻ったときは偽になり、見本の右上の札が「次のカード」から「はじめのカード」に変わります。
    4. $daily->for(…)：今日の練習を1つ選びます。今日の画面と同じ係で、日付と利用者で決まるので、同じ日に何度開いても同じものが出ます（2章）。

    array_column($list, null, 'key') は「並びを、キーで引ける形に並べ替える」PHP の関数で、画面の中で $skills['S1'] のように技能をキーで取り出せるようにしています。

  4. サーバー

    教材はデータベースではなくファイル：GuideLibrary::load

    手引きの中身（10の技能・名推理カード・練習メニュー・3つの考え方の説明・入口の案内）は、利用者の記録ではなく、だれが見ても同じ「本の中身」です。なので表ではなく、src/database/data/guide/ の5つの JSON ファイル（overview.json・skills.json・scenes.json・practices.json・reasoning.json）に置き、プログラムと一緒に変えます。

    src/app/Support/Guide/GuideLibrary.php
    /** JSON を読んで配列にする。ファイルが変わったら読み直すよう、更新日時をキャッシュのキーに入れる */
private function load(string $name): array
{
    $path = database_path("data/guide/{$name}.json");

    return Cache::rememberForever(
        "guide:{$name}:".filemtime($path),
        fn () => json_decode(file_get_contents($path), true, flags: JSON_THROW_ON_ERROR),
    );
}
    • json_decode(…, true)：JSON の文字を、PHP の配列にします。形が壊れていれば JSON_THROW_ON_ERROR で失敗として止めます。
    • Cache::rememberForever(鍵, 作り方)：キャッシュ（一度作ったものを覚えておく置き場）に鍵があればそれを返し、なければ作り方を動かして結果を覚えます。推理手帳のキャッシュの置き場はデータベースの cache 表です。
    • 鍵に filemtime($path)（ファイルを最後に変えた時刻）を入れているので、教材のファイルを直すと鍵が変わり、次に開いたときに読み直されます。
    たとえると図書館の本です。利用者のノート（事件やタスク）は一人ずつ別の棚にしまいますが、本（教材）は全員が同じものを読むので、1冊を書庫に置き、よく読まれるページはコピーをカウンターに置いておきます。本が改訂されたら、コピーの日付が合わなくなるので取り替えます。
    このとき動くデータ
    • 読む：src/database/data/guide/*.json（キャッシュがないときだけ）
    • 読む・書く：cache 表（guide:scenes:更新時刻 などの鍵）
  5. サーバー

    次に遊ぶカードを選ぶ：GuideLibrary::nextScene

    src/app/Support/Guide/GuideLibrary.php
    public function nextScene(array $doneKeys): ?array
{
    $scenes = $this->scenes();

    return collect($scenes)->first(fn (array $scene) => ! in_array($scene['key'], $doneKeys, true)) ?? ($scenes[0] ?? null);
}
    • collect($scenes)->first(条件)：カードを並びの順に見て、条件に合う最初の1枚を返します。条件は「書いたカードの一覧（$doneKeys）に入っていない」です。
    • ?? ($scenes[0] ?? null)：?? は「左が空なら右を使う」という書き方です。全部のカードに書き終えていたら最初の1枚に戻り、カードが1枚もなければ空（null）になります。

    選ぶ順をデータベースに覚えさせず、「書いたカードの一覧」と「並び」から毎回計算しているので、新しいカードを教材に足しても、そのまま「まだのカード」として選ばれます。

  7. サーバー

    名推理カードの一覧 GET /guide/scenes：書いたカードにはんこを押す

    入口の「ほかのカードを選ぶ」や、手引きのタブの「名推理カード」からは、カードの一覧へ来ます。

    src/app/Http/Controllers/Guide/SceneController.php
    public function index(Request $request, GuideLibrary $library, SceneAttemptReader $attempts): View
{
    $doneKeys = $attempts->keys($request->user());

    return view('guide.scenes.index', [
        'scenes' => $library->scenes(),
        'skillNames' => $library->skillNames(),
        'doneKeys' => $doneKeys,
        'nextScene' => $library->nextScene($doneKeys), // 「まだのカードで遊ぶ」の行き先
    ]);
}
    src/app/Support/Guide/SceneAttemptReader.php
    /** その人が推理を書いたカードのキーの一覧を返す（一覧の画面で「書いた」の印を付けるため） */
public function keys(User $user): array
{
    return $user->sceneAttempts()->pluck('scene_key')->all();
}

    $user->sceneAttempts() は「この人の推理」という関係（User モデルの hasMany(SceneAttempt::class)）なので、問い合わせには必ず where user_id = この人 が付きます。他人の推理が混ざることはありません。pluck('scene_key') は、行の中の scene_key の欄だけを集めます。

    src/resources/views/guide/scenes/index.blade.php

@if ($nextScene)
  <x-ui.big-button :href="route('guide.scenes.show', $nextScene['key'])" tone="answer" icon="sparkle" class="mt-4">

  </x-ui.big-button>
@endif

    一覧でも、いちばん大きいのは「まだのカードで遊ぶ」のボタンです（全部書き終えていれば「最初のカードから遊ぶ」）。その下に「23枚のうち、2枚に考えを書いたよ」のような書いた枚数と、カードの行が並びます。

    src/resources/views/components/guide/scene-item.blade.php

    このとき動くデータ
    • 読む：scene_attempts のこの人の行の scene_key

カードの表を開いて、裏返す

  1. サーバー

    カードの表 GET /guide/scenes/{key}：ホームズの推理は HTML に入れない

    src/app/Http/Controllers/Guide/SceneController.php
    /** 裏返す前の表に渡さない欄（ホームズの推理・確かめ方・答えに近い引用） */
private const BACK_ONLY = ['reasoning', 'verification', 'quote_en'];
// …（省略）…
public function show(Request $request, GuideLibrary $library, SceneAttemptReader $attempts, string $key): View
{
    $scene = $library->scene($key) ?? abort(404);
    $back = $request->query('side') === 'back';

    return view('guide.scenes.show', [
        'scene' => $back ? $scene : Arr::except($scene, self::BACK_ONLY),
        'back' => $back,
        'steps' => $back ? ReasoningSteps::split($scene['reasoning']) : [],
        'attempt' => $attempts->find($request->user(), $key),
        'skillNames' => $library->skillNames(),
        'neighbors' => $library->neighbors('scenes', $key),
        'position' => $library->position('scenes', $key), // 何枚目か（No.07・「7 / 23 枚目」）
        'total' => count($library->scenes()),
        'mistakeNote' => $library->overview()['mistake_note'],
        'kid' => $request->user()->prefersKidWords(), // 子ども向けのヒントを開いておくか（ふだんの場面が親子の人）
    ]);
}
    1. $library->scene($key) で、scenes.json の中からキーの合うカードを1枚探します。なければ abort(404)（そのカードはない）。
    2. 住所の後ろに ?side=back が付いていれば裏、なければ表です（$request->query('side') は住所の ? のあとの値を読む）。
    3. 表のときは Arr::except($scene, self::BACK_ONLY) で、ホームズの推理（reasoning）・どう確かめたか（verification）・英語の引用（quote_en）の欄を取り除いてから画面に渡します。
    4. $attempts->find(…) で、前にこのカードに書いた自分のメモがあれば探します（ここでも自分の行だけ）。
    5. neighbors（並びの1つ前と1つ後ろのカード）・position（何枚目か）・total（全部で何枚か）は、カードの「No.02 / 23」と、裏の「次のカードへ」や下の「前へ・次へ」に使います。
    ここが大事見た目で隠す（CSS で見えなくする）のではなく、表の HTML にはホームズの推理を最初から入れていません。ブラウザの「ページのソースを表示」で見ても、答えは書かれていません。自分で考える前に答えが目に入らないようにするためです。
    このとき動くデータ
    • 読む：scenes.json（キャッシュから）の1枚
    • 読む：scene_attempts の「この人・このカード」の1行（あれば）

    • 「裏返す」（<x-ui.big-button>。:href がないので送信のボタン）も、メモの欄の下の「メモして裏返す」も、同じフォームを POST /guide/scenes/{key}/attempt に送ります。メモの欄は <details>（押すと開く、たたんだ囲み）の中にありますが、たたんでいてもフォームの一部なので、書いてあれば一緒に送られ、書いていなければ空で送られます。

    • :maxlength：書ける長さの上限を config/suiri.php の limits.scene_answer（500字）から入れます。ブラウザも長すぎる入力を止めますが、本当の確かめはサーバー側でします（あとの歩）。

    このとき動くデータ
    • 送る：POST /guide/scenes/scarlet-watson/attempt（「初対面のワトソン」のカードのとき）
    • 送る：answer（メモ。書いていなければ空）と _token（合言葉）
  3. 見張り役

    見張り役：ログイン・回数・同意（持ち主の確かめは要らない）

    この住所の見張り役を Laravel の優先順位で並べると、web のひとまとまり（セッション・合言葉の確かめ）→ auth → throttle:writes → SubstituteBindings → agreed の順です（並べ替えのしくみは 0章）。

    事件やタスクの住所と違って ->can() がありません。住所の {key} は教材のキーで、だれかの記録の番号ではないからです。保存する行は、いつも「ログイン中の本人の推理」です（あとの歩の用事が $request->user() の関係を通して書く）。他人の推理を書き換える道は、はじめからありません。

  4. サーバー

    形の検証 StoreSceneAttemptRequest：書かなくてもよい、書くなら500字まで

    src/app/Http/Requests/Guide/StoreSceneAttemptRequest.php
    /** 確かめる前に、前後の空白を取る（空白だけの推理は「書かなかった」として扱う） */
protected function prepareForValidation(): void
{
    $this->merge(['answer' => trim((string) $this->input('answer'))]);
}

/** 項目ごとの決まり（長さの上限は config/suiri.php の limits.scene_answer） */
public function rules(): array
{
    return [
        'answer' => ['nullable', 'string', 'max:'.config('suiri.limits.scene_answer')],
    ];
}
    • prepareForValidation：確かめる前に値を整える関数。前後の空白を取ります。
    • nullable：空でもよい（メモを書かずに「裏返す」を押してもよい）。max:500：500字まで。超えていれば、受付まで届かずに表の画面へ戻り、「自分の推理は 500 文字以内にしてください。」という誤りが出ます（項目の名前「自分の推理」は attributes() で決めている）。このときメモの欄は開いた状態で出るので（前の歩の open）、誤りが目に入ります。

  6. データベース

    用事 SaveSceneAttempt：1人1カードに1行、書き直すと上書き

    src/app/Actions/Guide/SaveSceneAttempt.php
    /** 推理を保存して返す。何も書いていなければ保存せずに null を返す（前に書いた推理はそのまま残る） */
public function handle(User $user, string $sceneKey, ?string $answer): ?SceneAttempt
{
    // 空のまま送られたとき（書かずに裏返したとき）は、何も書き換えない
    if (blank($answer)) {
        return null;
    }

    return $user->sceneAttempts()->updateOrCreate(['scene_key' => $sceneKey], ['answer' => $answer]);
}
    • blank($answer)：空なら何もしません。前に書いたメモを、空で消してしまわないためです。
    • updateOrCreate(探す条件, 書く値)：「この人の推理」の中から scene_key が同じ行を探し、あれば answer を書き換え、なければ新しい行を作ります。$user->sceneAttempts() を通しているので、新しい行の user_id には自動でこの人の番号が入ります。

    • 読む：scene_attempts（user_id と scene_key が同じ行）
    • 書く：その行の answer と updated_at（なければ新しい1行）。メモが空なら書かない

この章のまとめ
  1. 手引きの住所は prefix('guide')・name('guide.') の1つの囲みにまとめ、見張り役は auth・agreed。書き込みのメモの保存にだけ throttle:writes。
  2. 教材は利用者の記録ではないので、表ではなく JSON のファイル。GuideLibrary が読んで、ファイルの更新時刻つきの鍵でキャッシュする。
  3. 入口と一覧でいちばん大きいのは「このカードで遊ぶ」「まだのカードで遊ぶ」。行き先は nextScene が「書いたカードの一覧」と「並び」から毎回選ぶ（全部書いたら最初に戻る）。
  4. カードの表の HTML には、ホームズの推理・確かめ方・引用を入れない（Arr::except）。裏は ?side=back の別の画面。
  5. 「裏返す」も「メモして裏返す」も同じフォーム。メモが書いてあれば scene_attempts に1人1カード1行で上書き保存し、空なら保存せずに裏へ進む。いつも本人の関係（$user->sceneAttempts()）を通して読み書きするので、他人の推理は見えず、書き換えられない。
  6. 裏では、ホームズの推理を段に分けて「見えたこと・考えたこと・だから」の見出しを付け、自分の考えと上下に並べて比べる。いちばん下の「次のカードへ」で、そのまま次のカードへ進める。
