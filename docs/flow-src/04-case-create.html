4事件を作る

気になる出来事に出会った人として、それを「なぞ」にして考え始めたい。だから、事件を作る画面で、1問ずつ「何が気になった？」「見たこと・聞いたことを1つ」「どうしてだと思う？」に答えて「事件を作る」を押す。

この章で追う道筋：入口（事件の一覧の「新しい事件を作る」／練習メニューの「この練習を始める」GET /cases/create?origin=practice&practice=…／予定・タスクの「気になる」POST /cases/draft → 転送）→ GET /cases/create → 受付 CaseController::create → 組み立て係 NewCaseDraft::for → 画面 cases/create-steps.blade.php（4つの段を1つのフォームに。stepper.js が1問ずつ見せる・提案のチップ）→ POST /cases → 見張り役（throttle:writes）→ 形の検証 StoreCaseRequest → 受付 CaseController::store → 用事 CreateCase（case_files・clues・hypotheses に書く）→ 転送 /cases/{case} → {case} を事件の行に替える → 権限 CaseFilePolicy::view → 組み立て係 CaseBoardQuery（いまの一手 NextStep・ワトソン・提案）→ 画面 cases/board.blade.php（机の部品 desk が「いまやること」のカードを1枚だけ選ぶ）。終わりに、なぞを直す PATCH・事件を消す DELETE・一覧 GET /cases も見ます。

  1. ブラウザ

    入口は3つある

    事件は、このアプリの記録の単位です。「気になる出来事」と、その「なぜ？」（なぞ）を1つの束にしたもので、表では case_files、コードでは CaseFile と呼びます（case は PHP の予約語＝プログラムの文法で使う言葉なので、モデルの名前に使えません）。

    事件を作る画面へは、3つの道から来ます。

    3つの入口
    • 事件の一覧の「新しい事件を作る」：ふつうのリンク。GET /cases/create へ。
    • 練習メニューの「この練習を始める」：手引きの練習メニュー（GET /guide/practices）から。住所に練習のキーを付けて GET /cases/create?origin=practice&practice=seventeen-steps のように来ます（今日の画面の「きょうの練習」の「やってみる」も同じ住所です。2章）。
    • 予定・タスクの行の「気になる」：今日の画面（2章）やタスクを済ませたあと（3章）から。いったん POST /cases/draft に送り、そこから GET /cases/create へ転送されます。

    1つ目のリンクは、事件の一覧のいちばん上にある横いっぱいの大きなボタンです。事件がまだ1つもない人には、代わりに絵と一言と「最初の事件を作ってみよう」のボタンだけの画面を出します。

    入口3：予定・タスクの「気になる」は、題名を住所に載せない

    「気になる」ボタンは、予定やタスクの題名（たとえば「歯医者（10:00）」）を、事件のきっかけとして作る画面へ持っていきます。ここで練習メニューと同じように ?label=歯医者 と住所に書くと、題名が住所に入ってしまいます。住所は、ブラウザの履歴やサーバーのアクセスの記録（だれがどの住所を開いたかの帳面）に残ります。そこで、題名は住所ではなくフォームの中身として POST で送ります。

    • 送る：POST /cases/draft、中身は _token・origin=event・label=歯医者（10:00）
  4. サーバー

    POST /cases/draft：まだ作らずに、入力を預けて転送する

    住所の表 src/routes/web/cases.php では、事件の住所は全部 auth（ログインした人だけ）と agreed（同意した人だけ）の囲みの中にあります（1章）。

    src/routes/web/cases.php
    Route::middleware(['auth', 'agreed'])->group(function () {
    // 事件：一覧・作る・詳細・なぞと場面を直す・消す
    Route::get('/cases', [CaseController::class, 'index'])->name('cases.index');
    Route::get('/cases/create', [CaseController::class, 'create'])->name('cases.create');
    // 予定・タスクの「気になる」：題名を URL に載せずに、作る画面へ持っていく（まだ作らない）
    Route::post('/cases/draft', DraftCaseController::class)->name('cases.draft');
    Route::get('/cases/{case}', [CaseController::class, 'show'])->can('view', 'case')->name('cases.show');

    /cases/draft の行き先は DraftCaseController というクラスそのものです。関数名を書かずにクラスだけを書くと、Laravel はそのクラスの __invoke という関数を呼びます（仕事が1つだけの受付の書き方）。

    src/app/Http/Controllers/Cases/DraftCaseController.php
    /** 入力を持って、事件を作る画面へ移る（長さや種類を確かめるのは、画面の組み立て NewCaseDraft と、作るときの StoreCaseRequest） */
public function __invoke(Request $request): RedirectResponse
{
    return redirect()->route('cases.create')->withInput($request->only(['origin', 'label']));
}

    この受付は何も保存しません。$request->only(['origin', 'label']) で送られた中から2つの欄だけを取り出し、withInput でセッション（サーバーがこの人のために持つ預かり箱。1章）に「一度きりの入力」として預け、/cases/create へ転送します。

    src/vendor/laravel/framework/src/Illuminate/Http/RedirectResponse.php
    public function withInput(?array $input = null)
{
    $this->session->flashInput($this->removeFilesFromInput(
        ! is_null($input) ? $input : $this->request->input()
    ));

    return $this;
}

    flashInput の フラッシュは「次のお願い1回だけ取り出せて、そのあと消える」預け方です。転送されたブラウザが次に開く /cases/create で1回だけ読めて、その次には消えます。

    たとえると受付で「このメモを、隣の窓口に1回だけ渡しておきます」と預かってもらうことです。隣の窓口で読んだら、メモは捨てられます。住所（封筒の表書き）には何も書かないので、通りがかった人に見られません。
    このとき動くデータ
    • 書く：セッション（sessions 表のこの人の行）に一度きりの入力 origin・label
    • 返す：302、行き先 /cases/create
    ここが大事この住所には回数制限（throttle:writes）を付けていません。記録を書かず、セッションに預けるだけだからです。
  5. 見張り役

    GET /cases/create の見張り役

    どの入口から来ても、ここからは同じ GET /cases/create です。Laravel が並べ替えたあとの見張り役の順は次のとおりです（並べ替えのしくみは 0章）。

    1. EncryptCookies・AddQueuedCookiesToResponse：Cookie を元に戻す・返事に付ける
    2. StartSession：セッションを開く（ここで、さっき預けた一度きりの入力が読めるようになる）
    3. ShareErrorsFromSession：前の入力の誤りを画面で使えるようにする
    4. PreventRequestForgery：合言葉の確認（GET は読むだけなので通る）
    5. Authenticate（auth）：ログインしているか（1章）
    6. SubstituteBindings：住所の穴を行に替える（この住所には穴がないので何もしない）
    7. EnsureAgreed（agreed）：同意したか（1章）
  6. サーバー

    受付 CaseController::create：材料を集めて組み立て係に渡す

    src/app/Http/Controllers/Cases/CaseController.php
    /**
 * 事件を作る画面を返す。きっかけを初めの値にする：練習メニューは ?origin=practice&practice=、
 * 予定・タスクの「気になる」は POST /cases/draft から一度きりの入力（origin・label）で届く。
 * 題名の写し（label）は URL からは受け取らない（題名を URL とアクセスの記録に残さないため）
 */
public function create(Request $request, NewCaseDraft $draft): View
{
    return view('cases.create-steps', ['draft' => $draft->for($request->user(), $request->old() + Arr::only($request->query(), ['origin', 'practice']))]);
}

    1行の中で、3つのことをしています。

    1. $request->old()：セッションに預けた一度きりの入力を、配列で取り出す。「気になる」から来たなら ['origin' => 'event', 'label' => '歯医者（10:00）']、ほかの入口なら空。
    2. Arr::only($request->query(), ['origin', 'practice'])：住所の ? のあとから、origin と practice だけを取り出す。label は取り出さないので、だれかが ?label=… と住所に書いても無視されます（テスト test_a_label_in_the_url_is_ignored で確かめています）。
    3. 2つを + でつなぐ。PHP の配列の + は「左にある名前を優先し、左にない名前だけ右から足す」つなぎ方です。
    src/vendor/laravel/framework/src/Illuminate/Http/Concerns/InteractsWithFlashData.php
    public function old($key = null, $default = null)
{
    $default = $default instanceof Model ? $default->getAttribute($key) : $default;

    return $this->hasSession() ? $this->session()->getOldInput($key, $default) : $default;
}

    引数の NewCaseDraft $draft は、Laravel がその場で作って渡します（依存性の注入：受付が「この係が要る」と型で書くだけで、Laravel が用意してくれるしくみ）。返す画面は cases.create-steps、つまり src/resources/views/cases/create-steps.blade.php です（1問ずつ進む形の作る画面）。

  7. サーバー

    組み立て係 NewCaseDraft::for：用紙の書き出しを決める

    Query（組み立て係）は、画面に出すものを読み集めて形を整える係です。書き込みはしません。

    src/app/Queries/Cases/NewCaseDraft.php
    public function for(User $user, array $query): array
{
    $origin = OriginKind::tryFrom((string) ($query['origin'] ?? ''));
    $practice = $origin === OriginKind::Practice ? $this->library->practice((string) ($query['practice'] ?? '')) : null;
    // 練習メニューから来たのにメニューが見つからなければ、きっかけなしにする
    if ($origin === OriginKind::Practice && $practice === null) {
        $origin = null;
    }
    $label = $practice['name'] ?? trim((string) ($query['label'] ?? ''));

    return [
        'origin_kind' => $origin?->value,
        'origin_label' => $origin && $label !== '' ? mb_substr($label, 0, config('suiri.limits.origin_label')) : null,
        'practice' => $practice,
        'title' => $practice['prompts']['title'] ?? null,
        'scene' => $user->default_scene ?? Scene::Daily,
        'firstWork' => ! $user->caseFiles()->where('scene', Scene::Work)->exists(),
        'partner' => $user->hasPartner() ? $user->partner_name : null,
        'kid' => $user->prefersKidWords(), // ふだんの場面が親子の人には、子ども向けの言葉で問いかける
    ];
}
    • OriginKind::tryFrom(…)：OriginKind は「きっかけの種類」の列挙（決まった値だけを持つ型。task・event・practice の3つ）。tryFrom は、知らない値なら null を返します。なので ?origin=abc のような値は「きっかけなし」になります。
    • 練習メニューから来たら、GuideLibrary::practice でキーのメニューを探します。見つからなければ（?practice=nope）、きっかけなしに戻します。
    • $label：練習ならメニューの名前、「気になる」なら預けた題名。
    • title：練習ならメニューの問いかけ（例：「いつもの階段は何段？」）を、なぞの初めの値にします。
    • scene：設定の「ふだんの場面」を初めの値にします（設定がなければ日常）。
    • firstWork：仕事の場面の事件がまだ1つもないか。初めてなら、仕事の場面を選んだときに約束の全文を出すために使います。
    • partner：設定に相棒の名前があれば、その名前（「相棒といっしょに考える？」の切り替えを出すため。8章）。
    • kid：ふだんの場面が「親子」の人なら true。問いかけや札の言葉を子ども向けの言い方にします（見立ては「かも」など）。

    練習メニューを探す GuideLibrary は、JSON のファイルを読んで配列にし、キャッシュ（一度読んだものを覚えておく置き場）にしまいます。

    src/app/Support/Guide/GuideLibrary.php
    private function load(string $name): array
{
    $path = database_path("data/guide/{$name}.json");

    return Cache::rememberForever(
        "guide:{$name}:".filemtime($path),
        fn () => json_decode(file_get_contents($path), true, flags: JSON_THROW_ON_ERROR),
    );
}

    覚えておく名前に filemtime($path)（ファイルを最後に直した時刻）を入れているので、教材のファイルを直すと名前が変わり、新しい中身が読まれます。

    このとき動くデータ
    • 読む：cache 表（練習メニューの中身）、なければ practices.json
    • 読む：case_files 表（この人の、仕事の場面の事件があるか）
  8. ブラウザ

    画面 cases/create-steps.blade.php：1つのフォームに4つの問い

    作る画面は、1画面に1問だけを見せて「つぎへ」で進む形です。①何が気になった？（なぞ・場面・相棒モード）→ ②見たこと・聞いたことを1つ（最初の手がかり）→ ③どうしてだと思う？（最初の見立て）→ ④これで事件を作るよ（確かめて送る）。ただし HTML としては、4つの問いが1つのフォームの中に全部入っています。

    src/resources/views/cases/create-steps.blade.php
    <x-layouts.app :title="config('suiri.case_new.page_title')">

    <input type="hidden" name="origin_label" value="{{ old('origin_label', $draft['origin_label']) }}">

    <x-case-new.mystery :draft="$draft" :kid="$draft['kid'] ?? false" />
    <x-case-new.clue :draft="$draft" :kid="$draft['kid'] ?? false" />

    • きっかけ（origin_kind・origin_label）と練習のキー（practice_key）は、隠し欄で送信に乗せます。old('origin_kind', 初めの値) は、「入力の誤りで戻ってきたなら、さっき送った値。そうでなければ初めの値」という意味です。
    • <x-case-new.mystery> などはBlade の部品（何度も使う見た目のかたまり。src/resources/views/components/ にあり、x-case-new.mystery なら components/case-new/mystery.blade.php）。1問が1つの部品です。
    • data-stepper は、画面のプログラム stepper.js への目印です（あとのステップ）。class="group/new" は、中の欄の状態で見た目を切り替えるための目印です（次のステップ）。

    1つのフォームにしているのは、送るのを最後の1回だけにするためです。途中の問いで何もサーバーに送らないので、途中でやめても半端な事件は残りません。JavaScript が動かないブラウザでは4つの問いが縦に並び、いちばん下の「事件を作る」でそのまま送れます。

    たとえると4枚つづりの申込用紙です。窓口の人が1枚ずつめくって「次はこれを書いてね」と見せますが、出すのは最後に4枚まとめて1回です。めくる人がいなくても（JavaScript がなくても）、4枚を並べて書けば出せます。

    • withCounts：1件ごとに、手がかり・見立て・答え合わせ待ち・確かめる日が来た・答え合わせ済みの予想の数を、SQL の数える命令でまとめて数えます（今日の画面でも使う）。

    画面では、状態ごとの件数つきのつまみ（<x-case.list-filter>。捜査ファイルの引き出しの形）の下に、1件ずつ <x-case.summary> を並べます。1件には「事件 No.12」・なぞと、段ごとの進み具合の小さな丸（なぞ → 見たこと → どうして？ → もしそうなら → 答え合わせ）、「次は『どうして？』」の一言が出ます。丸は、さっき数えた数から決めます。

この章のまとめ
  1. 事件を作る画面への入口は3つ。練習メニューはキーを住所に付けて、予定・タスクの「気になる」は題名を住所に載せないよう POST /cases/draft でセッションに一度きりで預けてから来る。
  2. NewCaseDraft が、きっかけ・練習の問いかけ・ふだんの場面・子ども向けの言葉を使うかから、用紙の書き出しを決める。住所の label は受け取らない。
  3. 作る画面 cases/create-steps は、4つの問いを1つのフォームに入れ、stepper.js が1問ずつ見せる。手がかりと見立ては「あとで書く」で飛ばせ、提案のチップは欄に書き出しを入れるだけ。送るのは最後の1回だけ。
  4. POST /cases は、回数制限 → 形の検証 StoreCaseRequest（下ごしらえ → 送ってよいか → 決まり）→ 受付 → 用事 CreateCase（トランザクションで事件・手がかり・見立て）の順。持ち主は事件から写る。
  5. 保存のあとは backToCase で事件の画面へ。ほかの人がわかる情報らしきものがあれば警告を預ける（保存は止めない）。
  6. GET /cases/{case} は、Route::model で番号を事件の行に替え、CaseFilePolicy で持ち主かを確かめ、CaseBoardQuery がいまの一手・ワトソン・提案を組み立てる。画面では机の部品が「いまやること」のカードを1枚だけ選ぶ。
  7. なぞを直す・事件を消すは「ほかにできること」から。消すときは、確かめるタスクを1件ずつ消してカレンダーの後始末も動かす。
