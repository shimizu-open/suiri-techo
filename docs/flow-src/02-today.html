2きょうの画面ができるまで

手帳を使う人として、開いたらすぐに「いまやること」が1つだけわかり、そのまま今日の予定とやることを片づけたい。明日から先のこと・日にちを決めていないこと・済んだことも、別の画面へ行かずに同じ所で見たい。だから、ログインしたあとの最初の画面（きょう）を開く。

この章で追う道筋：GET /today（?open=upcoming|someday|done が付くこともある）→ 見張り役（web のひとまとまり → auth → agreed）→ 受付 TodayController → 係が5つ（DuePredictionsQuery・AgendaQuery（中で今日の予定の窓口 CalendarAgenda）・TaskListQuery（forToday・justDone）・OpenCasesQuery・DailyPractice）→ 表を読む（predictions・tasks・case_files ほか、cache）→ 画面 today/index.blade.php と部品（いまやることのカード <x-today.next-step>・きょうの予定とやること <x-today.agenda>（中に1行で書く欄 <x-task.quick-add> と、たたんだ枠 <x-today.later-tasks>・<x-today.fold>）・開ける行 <x-task.item> ほか）→ 守りの札を付けて返事

  1. ブラウザ

    「きょう」を開く（ログインのあとに自動で来る）

    この画面に来る道は3つあります。1つは、ログインや同意を済ませた直後に自動で送られてくる道（1章）。2つめは、画面の下（パソコンでは左）のナビの「きょう」を押す道。3つめは、タスクを作る・直す・消したあとに送り返されてくる道です（3章）。行き先はどれも /today で、最初の画面を決めているのは係 Landing です。

  3. 見張り役

    見張り役を順に通る（auth → agreed）

    Laravel が優先順位で並べ替えたあと、この住所で実際に動く見張り役は次の順です（php artisan tinker で Laravel に並びを出させて確かめたもの）。

    1. EncryptCookies → AddQueuedCookiesToResponse → StartSession → ShareErrorsFromSession：Cookie を元に戻し、番号札からその人の預かり箱（セッション）を開く（1章）。
    2. PreventRequestForgery：ニセの送信でないか。GET は「読むだけ」なので素通りです（11章）。
    3. Authenticate（auth）：ログインしているか。していなければトップ（/）へ送られます（1章）。
    4. SubstituteBindings：住所の中の {…} をデータベースの行に取り換える係。/today には {…} がないので、何もせずに通します。
    5. EnsureAgreed（agreed）：同意したか。まだなら同意の画面（/agree）へ送られます（1章）。

    このほかに、どのお願いも通る全体の見張り役（TrustProxies・TrimStrings・このアプリが足した SecurityHeaders など）が外側にいます（0章）。SecurityHeaders は、画面ができたあとの帰り道で働きます（最後のステップ）。

    このとき動くデータ
    • 読む：sessions 表（セッションの中身）と、users 表のこの人の1行（ログインと同意の確かめ）

    受付 TodayController：係を5人呼んで、集めたものを画面に渡すだけ

    src/app/Http/Controllers/Today/TodayController.php

public function __invoke(
    Request $request,
    DuePredictionsQuery $duePredictions,
    AgendaQuery $agenda,
    OpenCasesQuery $openCases,
    DailyPractice $dailyPractice,
    TaskListQuery $tasks,
): View {
    $user = $request->user();

    $shown = $predictions->pluck('id')->all(); // 答え合わせ待ちに出す予想（その確かめるタスクは、きょうの並びに二重に出さない）

        'user' => $user,
        'today' => $today,
        'predictions' => $predictions,

    引数に、係のクラスが5つ並んでいます。受付は自分で new DuePredictionsQuery() のように係を作っていません。関数の引数に「この型のものが欲しい」と書くだけで、Laravel が作って渡してくれます。この仕組みを依存性の注入（DI）と呼び、作って渡す係をサービスコンテナと呼びます。

    たとえると窓口の人が「答え合わせ係・予定係・事件係・練習係・タスク係を呼んで」と頼むと、事務所の総務（サービスコンテナ）が担当者を連れてきてくれるようなものです。窓口の人は、担当者がどこにいて、どうやって呼ぶのかを知らなくてかまいません。
    • today()->toDateString()：今日の日付を '2026-10-31' のような文字にします。アプリの時刻の基準は Asia/Tokyo（日本時間）です。
    • $shown：上の答え合わせのカードに出す予想の番号（id）の一覧。下の「きょうの予定とやること」に、同じ予想を確かめるタスクを二重に出さないために使います（ステップ7。期日を過ぎたやることのほうは、画面の部品が同じように外します。ステップ17）。
    • ...$tasks->forToday($user, $today)：先頭の ... は配列を広げる書き方（スプレッド）です。forToday は overdue・upcoming・someday・done・counts・dates の6つの名前つきの値を入れた配列を返し（ステップ10）、... はその6つを、ここに1つずつ書いたのと同じように画面へ渡す配列に並べます。たとえると、袋ごと渡さずに、袋を開けて中身を机の上に並べるようなものです。
    • 'open'：住所の ?open= の値。どのたたんだ枠を最初から開いておくかに使います（ステップ18）。
    • 受付は数えたり並べたりしません。そうした決まりは全部、係（Query・Service）の中にあります。受付を薄くする決まり（.claude/rules/architecture.md）のとおりです。

    ?open= の値は、だれでも住所を書き換えて好きな文字を入れられます。そこで、知っている枠の名前だけを通す normalizeOpen にそろえてもらいます。

    src/app/Queries/Tasks/TaskListQuery.php
    /** きょうの画面のたたんだ枠の名前（?open= で開ける値。前の一覧の ?view= の値と同じ名前） */
public const OPENS = ['upcoming', 'someday', 'done'];

/** 送られた ?open=（前の一覧なら ?view=）の値を、たたんだ枠の名前にそろえる（知らない値・「today」・空なら null＝どれも開かない） */
public static function normalizeOpen(mixed $open): ?string
{
    return in_array($open, self::OPENS, true) ? $open : null;
}
    • OPENS：たたんだ枠の名前の一覧（これから・いつか・済み）。const は書き換えられない決まった値です。
    • in_array(…, true)：一覧の中に同じ値があるかを、型までそろえて比べます。あれば値をそのまま、なければ null（どの枠も開かない）を返します。
    • static の関数なので、係を作らずに TaskListQuery::normalizeOpen(…) とクラスの名前から呼べます。前のタスクの一覧の住所 /tasks?view=… を移すときも、この同じ関数を使います（3章）。

{
    return $user->predictions()
        ->whereNull('result')
        ->whereNull('withdrawn_at')
        ->where('check_on', '<=', $today)
        ->with('caseFile:id,title,scene')

    予定とタスクを1つの並びに混ぜる（AgendaQuery::for）

    src/app/Queries/Today/AgendaQuery.php
    public function for(User $user, string $date, array $skipPredictionIds = []): Collection
{
    $events = collect($this->calendar->eventsOn($user, $date))->map(fn (array $event) => [
        'type' => 'event',
        'title' => $event['title'],
        'starts_at' => $event['all_day'] ? null : $event['starts_at'],
        'ends_at' => $event['all_day'] ? null : ($event['ends_at'] ?? null),
        'all_day' => (bool) $event['all_day'] || blank($event['starts_at']),
        'task' => null,
    ])->map(fn (array $item) => $item + ['just_ended' => self::justEnded($date, $item)]);

    $tasks = $user->tasks()->where('due_on', $date)
        ->where(fn ($query) => $query->whereNull('prediction_id')->orWhereNotIn('prediction_id', $skipPredictionIds))
        ->orderBy('id')->get()
        ->map(fn (Task $task) => [
            'type' => 'task',
            'title' => $task->title,
            'starts_at' => $task->starts_at,
            'ends_at' => self::endOf($task),
            'all_day' => ! $task->hasTime(),
            'task' => $task,
            'just_ended' => false,
        ]);

    return $events->concat($tasks)
        ->sortBy(fn (array $item) => ($item['all_day'] ? '0' : '1').'|'.($item['starts_at'] ?? '').'|'.($item['type'] === 'event' ? '0' : '1'))
        ->values();
}

    4つのことをしています。

    1. 予定：窓口の eventsOn に今日の Google カレンダーの予定をもらい、画面で使う形（type・title・starts_at・ends_at・all_day・task）にそろえます。つないでいない人は空です（次のステップ）。
    2. さっき終わった予定の印：予定の1件ずつに just_ended（終わってから少しのあいだか）を足します。画面ではこの印のある予定に「気になったことは？」と一言そえます（ステップ17）。
    3. タスク：この人のタスク（$user->tasks() で user_id に絞る）のうち、期日 due_on が今日のもの。済んだタスクも入ります（線を引いて見せ、今日やったことが分かるように）。ただし prediction_id（もとの予想）が上の答え合わせのカードに出す予想の確かめるタスクは外します。同じものを2か所に出さないためです。期日を過ぎたもの・明日から先のもの・期日のないものは、ここでは集めません（ステップ10 の forToday が別に集める）。
    4. 並べる：sortBy に「並べるときの名札」の文字を渡しています。たとえば終日のタスクは 0||1、17:30 の予定は 1|17:30|0、17:30 のタスクは 1|17:30|1。文字の順に並べると、終日が上 → 時刻の早い順 → 同じ時刻なら予定が先になります。

    「さっき終わった予定」かどうかは justEnded が決めます。

    src/app/Queries/Today/AgendaQuery.php
    private static function justEnded(string $date, array $item): bool
{
    // 終日の予定・終わりの時刻がない予定は、いつ終わったかわからないので印を付けない
    if ($item['all_day'] || blank($item['ends_at'])) {
        return false;
    }
    $timeZone = config('suiri.calendar.timezone');
    $end = Carbon::parse("{$date} {$item['ends_at']}", $timeZone);
    $now = now($timeZone);

    return $now->gte($end) && $now->lt($end->copy()->addHours((int) config('suiri.suggest.just_ended_hours')));
}

    終わりの時刻を過ぎていて（gte）、そこから config('suiri.suggest.just_ended_hours') の 3 時間たつ前（lt）なら true です。タスクには付けません（タスクは済ませたときに別の枠でさそうため。3章）。

    タスクの終わりの時刻は、開始時刻と予想時間の両方があるときだけ計算します。

    src/app/Queries/Today/AgendaQuery.php
    private static function endOf(Task $task): ?string
{
    // 開始時刻と予想時間の両方があるときだけ、終わりの時刻を出せる
    if (! $task->hasTime() || ! $task->duration_minutes) {
        return null;
    }

    return Carbon::createFromFormat('H:i', $task->starts_at)->addMinutes($task->duration_minutes)->format('H:i');
}
    このとき動くデータ
    • 読む：tasks 表（この人の、期日が今日の行）
    • 返す：予定とタスクを混ぜた並び（1件は ['type' => 'event'|'task', 'title', 'starts_at', 'ends_at', 'all_day', 'task', 'just_ended']。just_ended は終わってから3時間以内の予定の印。タスクはいつも false）

    今日のほかのタスクを枠ごとに集める（TaskListQuery::forToday）

    ステップ7 で集めたのは、期日が今日のタスクだけでした。残りのタスクを、この画面の4つの置き場に振り分けて集めるのが forToday です。たとえると、手帳の「今日のページ」の上に、前からのやり残しの付せんを貼り、ページの下に「これから」「いつか」「済み」の3つのポケットを付けるようなものです。

    src/app/Queries/Tasks/TaskListQuery.php
    public function forToday(User $user, string $today): array
{
    $day = Carbon::parse($today);
    $tomorrow = $day->copy()->addDay()->toDateString();
    $doneFrom = $day->copy()->subDays((int) config('suiri.today_tasks.done_days') - 1)->startOfDay();

    $overdue = $this->byDate($user->tasks()->open()->where('due_on', '<', $today))->get();
    $upcoming = $this->byDate($user->tasks()->open()->where('due_on', '>=', $tomorrow))->get();
    $someday = $user->tasks()->open()->whereNull('due_on')->orderBy('id')->get();
    $done = $user->tasks()->done()->where('done_at', '>=', $doneFrom)
        ->latest('done_at')->latest('id')->limit((int) config('suiri.today_tasks.done_limit'))->get();

    return [
        'overdue' => $overdue,
        'upcoming' => $upcoming->groupBy('due_on'),
        'someday' => $someday,
        'done' => $done,
        'counts' => [
            'upcoming' => $upcoming->count(),
            'someday' => $someday->count(),
            'done' => $done->count(),
            'overdue' => $overdue->count(),
        ],
        'dates' => ['today' => $today, 'tomorrow' => $tomorrow],
    ];
}

    今日が 2026-10-31 なら、$tomorrow は 2026-11-01、$doneFrom は 2026-10-25 00:00:00（今日を入れて7日前の日の始まり）です。問い合わせは4つで、どれも $user->tasks()（この人のタスク）から始めます。

    1. 期日を過ぎた（overdue）：期日が今日より前で、まだ済んでいないもの。古い順。予想に結びついた確かめるタスクも入れます（上の答え合わせのカードに出ている予想の分は、画面の部品が外す。ステップ17）。行そのものを「きょうの予定とやること」の上に並べるので、数ではなく Task の並びで返します。
    2. これから（upcoming）：期日が明日以降の、まだ済んでいないもの全部。先の日付のものが見えなくならないよう、「14日先まで」のような日数の区切りは付けません。groupBy('due_on') で日付ごとの組にまとめ、['2026-11-01' => [Task, …], '2026-11-03' => [Task, …]] の形にします（画面で日付の小見出しを付けやすいように）。
    3. いつか（someday）：期日のない、まだ済んでいないもの。作った順（id の小さい順）。
    4. 済み（done）：今日を入れて config('suiri.today_tasks.done_days') の 7日のあいだに済んだもの。新しい順に done_limit の 30件まで。済んだものは増え続けるので、期間と件数で区切ります。
    • counts：枠の名前の横に出す件数。upcoming は日付ごとにまとめる前に数えるので、日数ではなくタスクの数です。
    • dates：1行で書く欄の「今日」「明日」のボタンが送る日付（3章）。
    • 日付だけの due_on は 'Y-m-d' の文字として比べます。この形なら、文字の大小と日付の前後が同じになるからです。

    並べ方は、期日を過ぎたものとこれからのもので共通の byDate にまとめてあります。

    src/app/Queries/Tasks/TaskListQuery.php
    /** 期日の古い順 → 同じ日なら終日を先に、時刻の早い順 → 作った順、に並べる */
private function byDate(HasMany|Builder $query): HasMany|Builder
{
    return $query->orderBy('due_on')->orderBy('starts_at')->orderBy('id');
}

    きょうの画面が出る

    ブラウザは HTML を受け取り、@vite が書き出した CSS と JavaScript を読み込んで画面を描きます。JavaScript のファイルは読み込みますが、この画面で動かすものはありません。丸を押す・「今日」「明日」「いつか」・「気になる」はふつうのフォームの送信、「答え合わせする」「直す」はリンク、たたんだ枠・行を開く・「消す」の確かめ・「ほかにも◯件あるよ」はどれも <details> です。なので、JavaScript が動かない端末でも同じように使えます。?open= の付いた住所で来たときは、その枠だけが開いた形で出ます。

この章のまとめ
  1. /today はログインした人の最初の画面（Landing::url()）で、ナビの4つ（きょう・事件・手引き・ふりかえり）の先頭。前の「今日」と「タスク」をこの1つにまとめた。見張り役 auth と agreed を通った人だけが来られる。
  2. 受付 TodayController は、5人の係（Query・Service）をサービスコンテナに作ってもらい、集めた値を画面に渡すだけ。...$tasks->forToday(…) で枠ごとのタスクを広げて渡し、?open= は normalizeOpen で知っている枠の名前だけにそろえる。
  3. TaskListQuery::forToday は、期日を過ぎた未完了（古い順）・明日以降の未完了全部（日付ごと）・期日なし（作った順）・この7日に済んだもの（30件まで）と、その件数・ボタンの日付を返す。
  4. どの係も $user->predictions()・$user->tasks()・$user->caseFiles() から始めるので、読むのはいつもその人の記録だけ。
  5. 今日の予定は窓口 CalendarAgenda から。準備の係が「いつも空」を本物 GoogleCalendarAgenda に差し替える。本物は題名と日時だけを受け取り、5分だけキャッシュに覚え、失敗しても画面を止めない。
  6. 画面は骨組み <x-layouts.app> の中に、いまやることのカード（<x-today.next-step>）を1枚だけ大きく置く。答え合わせの日が来た予想があれば「答え合わせしよう」（いちばん古い1件。ほかはたたむ）、なければ記録のきっかけと「気になったことを書こう」。
  7. その下の「きょうの予定とやること」（<x-today.agenda>）に、やることを全部まとめる：いつも開いた1行で書く欄 → 赤い帯と左にもとの期日を付けたやり残し → 時刻順の予定とやること → これから・いつか・済みのたたんだ枠（<x-today.fold>。?open= の枠だけ開く）。やることの行（<x-task.item>）は丸で済ませ、題名を押すとその場で開く。
  8. 下に小さく練習と捜査中の事件。帰り道で SecurityHeaders が「取り置かないで」の札を付ける。
