10週のふりかえり・事件を閉じる・ノーベリ帳と屋根裏の棚

手帳を続けている人として、この1週間で何を記録し、どれだけ考えを変え、確かさの付け方が現実と合っていたかを知りたい。だから、週に1回「ふりかえり」を開き、週の問いに1問ずつ答える。事件が片づいたら閉じて、わかった決まりを屋根裏の棚にしまう。

この章で追う道筋：GET /review/{week?} → ReviewController::show → ReviewWeek（週を決める）→ WeekReviewQuery → WeeklyStats（＋EstimateCheck）・Calibration・WeekCasesQuery → 画面 review/show.blade.php（week-summary・reflection-steps・calibration-chart など）／ PUT /review/{week} → UpdateWeeklyReflectionRequest → SaveWeeklyReflection → weekly_reflections → 次の問い ／ 事件の画面のカード case-step/close-card → POST /cases/{case}/close → CloseCase → case-step/closed-card（「つまり、何がわかった？」）→ POST /attic ／ DELETE /cases/{case}/close → ReopenCase ／ GET /norbury → NorburyQuery ／ /attic → AtticNoteController → SaveAtticNote

週のふりかえりを開く

  1. ブラウザ

    下のナビの「ふりかえり」を押す

    どの画面にもある下のナビ（パソコンでは横のナビ）の項目は、設定ファイルに並べてあります。

    src/config/suiri.php
    ['route' => 'review.show', 'match' => ['review.*', 'norbury.*', 'attic.*'], 'label' => 'ふりかえり', 'icon' => 'loop'],

    route はリンク先のルート名、match は「いまの画面」に印を付けるかの判定に使うルート名です。ふりかえり・ノーベリ帳・屋根裏の棚の3つの画面のどれにいても「ふりかえり」が光ります。route('review.show') は、住所の {week?} を省いた /review になります。

    このとき動くデータ
    • 送る：GET /review（クッキーの番号札だけ）
  2. 見張り役

    住所の表：{week?} は省いてよい穴、形は where で決める

    src/routes/web/review.php
    Route::middleware(['auth', 'agreed'])->group(function () {
    // 週のふりかえり。{week} は週の月曜日の 'Y-m-d'（省略は今週）
    Route::get('/review/{week?}', [ReviewController::class, 'show'])->where('week', '\d{4}-\d{2}-\d{2}')->name('review.show');
    Route::put('/review/{week}', [ReviewController::class, 'update'])->where('week', '\d{4}-\d{2}-\d{2}')
        ->middleware('throttle:writes')->name('review.update');
    • {week?}：? の付いた穴は省略できるルートパラメータです。/review でも /review/2026-10-19 でもこの行に当たります。省いたときは、受付係の引数 ?string $week = null に null が入ります。
    • ->where('week', '\d{4}-\d{2}-\d{2}')：穴の中身の形の決まり（正規表現：文字の並びの型）です。「数字4つ - 数字2つ - 数字2つ」。/review/26-10-26 のように形が違えば、この行には当たらず、ほかに当たる行もないので 404（見つからない）になります。

    見張り役の順は EncryptCookies → AddQueuedCookiesToResponse → StartSession → ShareErrorsFromSession → PreventRequestForgery → Authenticate → SubstituteBindings → EnsureAgreed。見るだけの GET なので回数制限はなく、穴の {week} はモデルではないので、SubstituteBindings は文字のまま受付係へ渡します。->can() もありません。ふりかえりは、いつも「ログイン中の本人の記録」だけを数えるからです（あとで見る $user->caseFiles() のような、本人から始める読み方で守ります）。

  3. サーバー

    受付係 ReviewController::show：週を決め、月曜日でなければ住所をそろえ直す

    src/app/Http/Controllers/Review/ReviewController.php
    /** 週のふりかえりの画面を返す。月曜日でない日付は、その週の月曜日の住所へ送り直す。ない日付・未来の週は 404 */
public function show(Request $request, WeekReviewQuery $query, ?string $week = null): View|RedirectResponse
{
    $current = ReviewWeek::fromParam($week) ?? abort(404);
    // 住所の日付が月曜日でなければ、その週の月曜日の住所にそろえる（確かさの期間の選択は引き継ぐ）
    if ($week !== null && $week !== $current->param()) {
        return redirect()->route('review.show', ['week' => $current->param()] + $request->only('range'));
    }
    $range = $request->query('range') === 'week' ? 'week' : 'all';

    return view('review.show', $query->for($request->user(), $current, $range));
}
    1. ReviewWeek::fromParam($week) で「週」を作ります。作れなければ（ない日付・未来の週）?? abort(404) で 404 にします。?? は「左が null なら右を使う」という書き方です。
    2. 住所の日付が月曜日でなければ（例 /review/2026-10-29）、その週の月曜日の住所 /review/2026-10-26 へ転送します。住所を1つの形にそろえておくと、同じ週が別々の住所で開かれません。?range=week が付いていれば引き継ぎます。
    3. range：確かさの答え合わせを「これまで全部」（all）で数えるか「この週」（week）で数えるか。決まった2つ以外の値は全部 all にします。
  4. サーバー

    「週」の係 ReviewWeek：月曜日の 0 時から、次の月曜日の 0 時の手前まで

    src/app/Services/Review/ReviewWeek.php
    public static function fromParam(?string $param): ?self
{
    // 省略されたら今週
    if ($param === null) {
        return self::current();
    }
    // 'Y-m-d' の形でない、または 2月31日のようなない日付なら、週を作らない
    if (! preg_match('/^(\d{4})-(\d{2})-(\d{2})$/', $param, $m) || ! checkdate((int) $m[2], (int) $m[3], (int) $m[1])) {
        return null;
    }
    $week = new self(CarbonImmutable::parse($param)->startOfWeek(CarbonInterface::MONDAY));

    return $week->start->greaterThan(self::current()->start) ? null : $week;
}
    • 住所の where は形しか見ないので、2026-02-31 も通ってきます。checkdate(月, 日, 年) が「本当にある日付か」を確かめ、なければ null（→ 404）。
    • CarbonImmutable は日付と時刻を扱う道具（Carbon）の「書き換えられない版」です。startOfWeek(MONDAY) でその日を含む週の月曜日の 0 時にします。
    • その週が今週より先（未来）なら null。まだ来ていない週はふりかえれません。

    手元で確かめると、fromParam('2026-10-29') の週は 2026-10-26、fromParam('2026-11-02')（今日 2026-10-31 から見て来週）と fromParam('2026-02-31') は null でした。

    src/app/Services/Review/ReviewWeek.php
    /** 住所に使う形（月曜日の 'Y-m-d'）を返す。weekly_reflections.week_start と同じ形 */
public function param(): string
{
    return $this->start->toDateString();
}
// …（省略）…
/** 問い合わせで「この週の中」に絞る：列の値が週の始まり以上、次の月曜日の 0 時より前 */
public function scope($query, string $column)
{
    return $query->where($column, '>=', $this->start)->where($column, '<', $this->end());
}

    scope は、このあとの集計で何度も使う「この週の中だけに絞る」部品です。終わりを「日曜日の 23:59:59 まで」ではなく「次の月曜日の 0 時より前（<）」にしているので、秒の端数で取りこぼしません。

    たとえるとカレンダーの1週間の枠です。どんな日付を言われても、まずその日が入っている枠（月曜始まり）を指さし、その枠の中に書かれた記録だけを数えます。

  7. データベース

    見積もりの答え合わせ EstimateCheck：予想した時間とかかった時間のずれ

    src/app/Services/Review/EstimateCheck.php
    public function for(User $user, ReviewWeek $week): array
{
    $tasks = $week->scope($user->tasks(), 'done_at')
        ->whereNotNull('duration_minutes')->whereNotNull('actual_minutes')
        ->get(['duration_minutes', 'actual_minutes']);

    $count = $tasks->count();
    $longer = $tasks->filter(fn ($task) => $task->actual_minutes > $task->duration_minutes)->count();
    $diffs = $tasks->map(fn ($task) => $task->actual_minutes - $task->duration_minutes);

    return [
        'count' => $count,
        'longer' => $longer,
        'longer_rate' => WeeklyStats::percent($longer, $count),
        'average_diff' => $count > 0 ? (int) round($diffs->avg()) : null,
    ];
}

    タスクを作るときに入れた予想時間（duration_minutes）と、済ませたときに入れたかかった時間（actual_minutes。3章）の両方があり、この週に済ませた（done_at）タスクだけを数えます。「予想より長かった割合」と「平均のずれ（かかった − 予想。長ければプラス）」を出します。見積もりも「予想して、確かめる」練習の1つだからです。

    このとき動くデータ
    • 読む：tasks（この人・この週に済ませ、2つの時間が入っているもの）
  8. サーバー

    確かさの答え合わせ Calibration：確かさ 70％ と付けた予想は、本当に 7 割当たったか

    キャリブレーション（確かさの答え合わせ）は、「自分が付けた確かさ」と「実際に当たった割合」がどのくらい合っているかを見ることです。予想を立てるとき、確かさを 50〜95％ から選びました（6章）。確かさ 70％ の予想を10個立てて7個当たっていれば、確かさの付け方が現実と合っています。

    src/app/Services/Review/Calibration.php
    $query = $user->predictions()
    ->whereIn('result', [PredictionResult::Hit->value, PredictionResult::Miss->value])
    ->whereNull('withdrawn_at');
// 週が渡されたら、その週に答え合わせした予想に絞る
if ($week !== null) {
    $week->scope($query, 'resolved_at');
}

$rows = $query->get(['confidence', 'result'])
    ->map(fn ($p) => ['confidence' => (int) $p->confidence, 'hit' => $p->result === PredictionResult::Hit])
    ->all();

return $this->summarize($rows);

    数えるのは「当たり」か「外れ」になった予想だけです。「どちらとも言えない」「前提が崩れた」は、当たったとも外れたとも言えないので入れません。取り下げた予想（withdrawn_at がある）も入れません。データベースから取るのは確かさと結果の2つの列だけで、組にしてから summarize で区間に分けます。

    src/app/Services/Review/Calibration.php
    foreach (config('suiri.review.calibration_buckets') as [$from, $to]) {
    $inside = array_values(array_filter($rows, fn ($r) => $r['confidence'] >= $from && $r['confidence'] <= $to));
    $count = count($inside);
    $hits = count(array_filter($inside, fn ($r) => $r['hit']));
    $buckets[] = [
        'label' => "{$from}〜{$to}％",
        'from' => $from,
        'to' => $to,
        'count' => $count,
        'hits' => $hits,
        'enough' => $count >= $min,
        // 件数が足りれば当たった割合（％）、足りなければ「まだ判断できない」の印として null
        'rate' => $count >= $min ? (int) round($hits / $count * 100) : null,
        // 図の横の位置に使う確かさの平均（1件もなければ区間のまん中）
        'mean' => $count > 0 ? array_sum(array_column($inside, 'confidence')) / $count : ($from + $to) / 2,
    ];
}

    週の問いの選択肢 WeekCasesQuery：この週に動いた自分の事件

    src/app/Queries/Review/WeekCasesQuery.php
    return $user->caseFiles()
    ->where(function ($query) use ($week, $selectedId) {
        $week->scope($query, 'created_at')
            ->orWhereHas('hypotheses.statusLogs', fn ($logs) => $week->scope($logs, 'hypothesis_status_logs.created_at'))
            ->orWhereHas('predictions', fn ($predictions) => $week->scope($predictions, 'resolved_at'));
        // 保存済みの事件があれば、それも選択肢に入れる
        if ($selectedId !== null) {
            $query->orWhere('id', $selectedId);
        }
    })
    ->latest('updated_at')->latest('id')
    ->limit(config('suiri.review.case_options'))
    ->pluck('title', 'id')
    ->all();

    「今週いちばん考えが変わった事件は？」の選択肢です。この人の事件のうち、この週に「作った」か「見立ての状態を変えた」（orWhereHas：つながった表にこの条件の行があるもの）か「予想の答え合わせをした」ものを、新しい順に30件まで。前に選んで保存した事件は、条件に合わなくなっても残します。全体を where(function …) で囲んでいるのは、「この人の事件で、かつ（A または B または C）」の形にするためです。囲まないと「この人の事件で A、または B、または C」になり、他人の事件が混ざってしまいます。

    pluck('title', 'id') で「事件の id => なぞ」の配列にして、選択の部品にそのまま渡します。

  1. ブラウザ

    週の問いのカード reflection-steps：いまの問いだけを出し、答えて「次へ」を押す（PUT）

    });

    用事 CloseCase：閉じるのと棚に入れるのを、1つのトランザクションで

    src/app/Actions/Cases/CloseCase.php
    public function handle(CaseFile $case, array $data): void
{
    DB::transaction(function () use ($case, $data) {
        $case->update([
            'status' => $data['status'],
            'conclusion' => $data['conclusion'] ?? null,
            'closed_at' => now(),
        ]);

        // 「つまり？」が書いてあれば、屋根裏の棚に入れる
        if (filled($data['rule'] ?? null)) {
            $case->user->atticNotes()->create([
                'case_file_id' => $case->id,
                'rule' => $data['rule'],
                'examples' => $data['examples'] ?? null,
            ]);
        }
    });
}

    トランザクションは「いくつかの書き込みを、全部するか、全部しないかのどちらかにする」しくみです。DB::transaction(function () { … }) の中で途中に失敗が起きると、それまでの書き込みも取り消されます。「事件は閉じたのに、棚の知識だけ入らなかった」という半端な状態を残しません。

    • 「つまり？」が送られていれば、事件の持ち主の atticNotes() から棚の知識を作ります（user_id は自動で入り、case_file_id で「どの事件からわかったか」も結ぶ）。今の閉じるカードからは「つまり？」が来ないので、この分かれ道は通らず、事件を閉じるだけになります。

  1. サーバー

    ノーベリ帳 GET /norbury：外れた予想の一覧と、見落としの種類ごとの数

    ふりかえりの画面の上の切り替え（x-review.tabs）から開きます。ノーベリ帳は、外れた予想を集めたページです（ホームズが自分の見込み違いを忘れないように「ノーベリ」とささやいてくれと頼んだ話から）。

    /** 外れた予想の一覧を返す（事件のなぞも一緒に読む）。1ページの件数は config('suiri.review.norbury_per_page') */
public function misses(User $user): LengthAwarePaginator
{
    return $user->predictions()
        ->where('result', PredictionResult::Miss->value)
        ->with('caseFile:id,user_id,title,scene')
        ->latest('resolved_at')->latest('id')
        ->paginate(config('suiri.review.norbury_per_page'));

  2. 見張り役

    屋根裏の棚の住所：Route::resource で4つをまとめて作る

    src/routes/web/review.php
    // 屋根裏の棚。{note} は AtticNote に結びつく。直す・消すは持ち主だけ（AtticNotePolicy）
Route::resource('attic', AtticNoteController::class)
    ->only(['index', 'store', 'update', 'destroy'])
    ->parameters(['attic' => 'note'])
    ->middlewareFor('store', 'throttle:writes')
    ->middlewareFor('update', ['throttle:writes', 'can:update,note'])
    ->middlewareFor('destroy', ['throttle:writes', 'can:delete,note']);

    Route::resource は、一覧・作る・直す・消すといった決まった形の住所をまとめて作る書き方です（リソースルート）。only で4つだけにし、次の住所ができます。

    住所受付係の関数付く見張り役（web・auth・agreed のほか）
    GET /atticindex（一覧）なし
    POST /atticstore（足す）throttle:writes
    PUT|PATCH /attic/{note}update（直す）throttle:writes・can:update,note
    DELETE /attic/{note}destroy（消す）throttle:writes・can:delete,note
    • parameters(['attic' => 'note'])：穴の名前をふつうの {attic} から {note} に変えます。受付係の引数 AtticNote $note と名前をそろえ、attic_notes の行に取り換えてもらうためです。
    • middlewareFor('動作', 見張り役)：その動作の住所だけに見張り役を付けます。同じ動作に2回書くと後の指定で上書きされるので、動作ごとに1回でまとめて書いています。
    • can:update,note は ->can('update', 'note') と同じで、AtticNotePolicy（中身は OwnerOnly）が「知識の user_id がログイン中の人か」を確かめます。他人の知識の番号を送ると 403 です。

@if ($writing)

@elseif ($notes->isEmpty())

    'rule' => ['required', 'string', 'max:'.config('suiri.limits.attic_rule')],
    'examples' => ['nullable', 'string', 'max:'.config('suiri.limits.attic_examples')],

    「つまり？」は必須、「たとえば？」と「どの事件から？」は任意。事件は、週の問いと同じく Rule::exists(...)->where('user_id', …) で自分の事件だけに限ります。直すときの UpdateAtticNoteRequest も同じ決まりを使います。

    src/app/Actions/Attic/SaveAtticNote.php
    /** 検証済みの値で知識を保存して返す。空のたとえば？・事件は null にする */
public function handle(User $user, array $data, ?AtticNote $note = null): AtticNote
{
    $note ??= $user->atticNotes()->make();
    $note->fill([
        'rule' => $data['rule'],
        'examples' => filled($data['examples'] ?? null) ? $data['examples'] : null,
        'case_file_id' => $data['case_file_id'] ?? null,
    ])->save();

    return $note;
}

    知識を渡されなければ（足すとき）、$user->atticNotes()->make() で「この人の、まだ保存していない新しい知識」を用意します。??= は「左が null のときだけ右を入れる」書き方です。渡されれば（直すとき）、その知識に値を入れて保存します。足すのも直すのも、同じ1つの用事で済みます。保存したら、受付係 AtticNoteController が棚の画面へ戻し、「棚に置いたよ。」（直したときは「決まりを直したよ。」）のお知らせを出します。文は config('suiri.review.attic.flash') にあります。

この章のまとめ
  1. GET /review/{week?} の {week?} は省略できる穴（省略は今週）。where が形を、ReviewWeek::fromParam が「ある日付か・未来でないか」を確かめ、月曜日でない日付は月曜日の住所へ転送する。
  2. 週は「月曜日の 0 時から、次の月曜日の 0 時の手前まで」。ReviewWeek::scope がどの集計にもこの絞り込みを付ける。
  3. WeekReviewQuery が、WeeklyStats（事件・見立て2つ以上・答え合わせ・考えを変えた・外れ・棚・見積もり）、Calibration（当たり・外れだけを確かさの区間ごとに。5件未満は「まだ判断できない」）、WeekCasesQuery（週の問いの選択肢）を集める。どれも本人の記録から始めて数える。
  4. 確かさの図は外の部品を使わず、Blade が SVG を組み立てる。点線が「確かさ＝当たった割合」。
  5. 画面は「今週のまとめ（大きな一言と3つの数。内訳はたたむ）→ 週の問い → 確かさの答え合わせ」。いまやることは週の問いなので、問いのカードを最初の画面に入れる。
  6. 週の問いは reflection-steps が1問ずつ出し、PUT /review/{week} で1問ずつ保存する。いま答えない問いの値は hidden で送り直して消さない。事件は Rule::exists(...)->where('user_id') で自分のものだけ。updateOrCreate と表のユニーク制約で「1人1週に1行」。
  7. 事件を閉じるのは、事件の画面のいまやることのカード「事件を閉じる？」（当たりの見立てがあれば勧められる）。POST /cases/{case}/close は捜査中の事件だけで、CloseCase がトランザクションの中で閉じる。閉じたあとのカードが「つまり、何がわかった？」を1問ずつ聞き、POST /attic で棚にしまう。開き直す（DELETE）は状態を戻すだけで、結論は残す。
  8. ノーベリ帳は外れた予想の一覧と見落としの種類ごとの数。屋根裏の棚は Route::resource の4つの住所で、直す・消すは AtticNotePolicy が持ち主だけに許す。自分で書くときは ?add=1 で書くカードを1枚だけ出す。
