5手がかりを足し、見立てを立てて ○× を付ける

事件を調べている人として、見たこと・聞いたことを手がかりとして集め、説明の案（見立て）を2つ以上並べて、どの手がかりがどの見立てに合うかを確かめたい。だから、事件の画面に1枚ずつ出る「いまやること」のカードに答えて、手がかりと見立てを書き足し、見立てごとに ○× を付ける。

この章で追う道筋：GET /cases/{case} → CaseBoardQuery（いまの一手 NextStep）→ 机の部品 case-step/desk がカードを1枚選ぶ → 「見たことを1つ教えて」のカード（提案のチップつき）→ POST /cases/{case}/clues → 見張り役（throttle:writes・can:write,case）→ StoreClueRequest → ClueController::store → 用事 AddClue → backToCase（ほかの人がわかる情報の確認・back_open）→ 次のカード → WatsonNotes::forCase（吹き出し1つ）→ ひとことを閉じる POST /cases/{case}/hints/{rule} → 「どうしてだと思う？」のカード → POST /cases/{case}/hypotheses（AddHypothesis）→ 「この見立てに合う？」のカード → ○× PUT /hypotheses/{hypothesis}/clues/{clue}（can 2つ・UpdateFitRequest・SetFit）→ 見立てを見直す PATCH /hypotheses/{hypothesis}（ChangeHypothesisStatus・考えを変えた記録）→ 直す・消す

    src/app/Services/Watson/WatsonNotes.php
    public function forCase(CaseFile $case, ?string $alert = null, array $skip = []): ?array
{
    // 保存した直後の警告があれば、閉じたかどうかに関係なく、それを出す
    if ($alert !== null && config("watson.rules.{$alert}") !== null) {
        return $this->note($alert, null, true);
    }
    $dismissed = [...$case->dismissedHints->pluck('rule')->all(), ...$skip];

    // 規則を優先度の高い順に1つずつ確かめ、閉じていなくて当てはまる最初の1つを返す
    foreach (array_keys(config('watson.rules', [])) as $rule) {
        // 閉じた規則と、飛ばすように頼まれた規則は飛ばす
        if (in_array($rule, $dismissed, true)) {
            continue;
        }
        $quote = $this->match($rule, $case);
        // 当てはまったら（引用がなくても空文字が返る）、その規則のひとことを返す
        if ($quote !== null) {
            return $this->note($rule, $quote !== '' ? $quote : null);
        }
    }

    return null;
}
    1. 保存した直後の警告（$alert）があれば、それを最優先で返す。
    2. この事件で閉じた規則（dismissed_hints の行）と、飛ばすよう頼まれた規則（$skip）を集める。
    3. 設定の規則を上から順に確かめ、閉じていなくて当てはまる最初の1つだけを返す。1つも当てはまらなければ null（ひとことは出ない）。

    見立てを2つ以上に：止めずに勧める

    このアプリは「見立てを2つ以上立てる」ことを大事にしていますが、1つしかないと保存できない、という止め方はしません。代わりに、見立てがちょうど1つで捜査中のとき、W-3 が当てはまります（'single_hypothesis' => $case->isOpen() && $case->hypotheses->count() === 1）。見立てが1つできると、いまの一手は「予想を立てる」に進みますが、カードの吹き出しに「ほかの説明は？」が出て、カードの下の「ほかにできること」の「見立てをもう1つ書く」（?open=add-hypothesis）から2つ目を書けます。2つ目を足すと W-3 は当てはまらなくなり、ひとことは次の規則に移るか、言葉の説明に戻ります。

    public function handle(Hypothesis $hypothesis, HypothesisStatus $to): bool
{
    $from = $hypothesis->status;
    // 同じ状態を選んだだけなら、記録を増やさない
    if ($from === $to) {
        return false;
    }

    DB::transaction(function () use ($hypothesis, $from, $to) {
        $hypothesis->update(['status' => $to]);
        $hypothesis->statusLogs()->create([
            'user_id' => $hypothesis->user_id,
            'from_status' => $from,
            'to_status' => $to,
        ]);
        $hypothesis->caseFile->touch();
    });

    return true;
}

    状態を変えると、hypothesis_status_logs に「前の状態 → 新しい状態」を1行残します。この表は書いたあと直さないので、updated_at を持ちません（モデルの UPDATED_AT = null）。週のふりかえりで「考えを変えた件数」として数えます（10章）。考えを変えたことは、失敗ではなく練習の成果として数える、という設計です。

public function update(UpdateClueRequest $request, Clue $clue): RedirectResponse
{
    $clue->update($request->validated());

/** 手がかりを消して、事件の詳細へ戻す（付けていた ○× も一緒に消える） */
public function destroy(Clue $clue): RedirectResponse
{
    $case = $clue->caseFile;
    $clue->delete();

    return $this->backToCase($case, '手がかりを消しました。', [], 'clues');
}

この章のまとめ
  1. 事件の画面は「いまやること」のカード1枚。NextStep がいまの一手を決め、机の部品 case-step/desk が ?open= の頼みと合わせてカードを選ぶ。答えるたびに次の問いが1つ出る。
  2. 手がかりは事実（見た・聞いた・なかった）だけ。POST /cases/{case}/clues は、事件の持ち主で捜査中か（can:write,case）→ 形の検証 → AddClue（持ち主を写して1行・事件の touch）の順。
  3. 提案のチップは、押すと欄に書き出しが入るだけ（AI なし・保存は本人）。手がかりの問いかけ・ほかの説明の型・屋根裏の棚の候補。
  4. 戻すときの backToCase は、ほかの人がわかる情報らしきもの（メール・電話番号・「〇〇さん」）があれば W-5 の警告をカードの上に出し（保存は止めない）、back_open が決まった候補なら同じカードへ戻す。
  5. ワトソンのひとことは config/watson.php の規則を上から確かめ、閉じていなくて当てはまる1つだけを、主なボタンの下の吹き出しに出す。閉じると dismissed_hints に残り、その事件ではもう出ない。知らない規則のキーは住所の制約で 404。
  6. 見立ては止めずに2つ以上を勧める（W-3）。○× は見立てと手がかりの組ごとに1行（updateOrCreate）。両方の持ち主かを2つの can で、同じ事件かを UpdateFitRequest で確かめる。
  7. × の付いた見立ては「ちがった にする」を勧める。状態を変えると hypothesis_status_logs に「考えを変えた記録」が残る。消すより「消えた」にするほうが、記録が残る。
