8相棒とスマホを渡し合い、見立てを隠して書いて見せ合う

子どもと一緒に考える親として、相手の考えに引っぱられずに、それぞれの見立てを出し合いたい。だから、相棒モードの事件で1台のスマホを渡し合い、相棒 → 自分の順に見立てを隠して書いて、最後に「いっしょに見せ合おう！」を押す。

この章で追う道筋：設定で相棒の名前を入れる（PATCH /settings → UpdateSettingsRequest → UpdateSettings → users.partner_name）→ 事件を作る1問目で「長男といっしょに考える？」を入れる（partner-toggle → StoreCaseRequest → CreateCase）→ 事件の画面のいまやることが渡し合いになる（CaseBoardQuery → desk → case-partner.flow → case-partner.turn）→ 渡す付箋 → 書く（POST /cases/{case}/hypotheses → StoreHypothesisRequest → AddHypothesis → 書いた人の番の画面へ）→ ○ を付ける（PUT /hypotheses/{hypothesis}/clues/{clue}）→ 自分の番へ渡す（?turn=self）→ 見せ合う（POST /cases/{case}/reveal → RevealHypotheses → case_files.revealed_at）→ 並べて見る（RevealBoard → case-partner.reveal）

はじめに：相棒は「別のアカウント」ではない要件定義書（docs/design/requirements.md）では、子ども（相棒）は「保護者の端末で『相棒の見立て』を先に書く」使い方を想定しています（13歳未満なら自分のアカウントは持たない）。だから相棒モードは、1つのアカウント・1台のスマホを渡し合って、順番に書くしくみです。相棒の見立ても、表の上では親のアカウント（user_id）の記録で、「書いた人」の列（author）が partner になっているだけです。2つのアカウントで同じ事件を見る共有（C-13）は「次」に回していて、まだ作っていません。

事件の画面が「渡し合い」になる

  1. サーバー

    「隠すか」はモデルの1つの関数で決める：CaseFile::hidesHypotheses

    src/app/Models/CaseFile.php
    /** 相棒モードで、まだ見せ合っていない（互いの見立てを隠す）かを返す */
public function hidesHypotheses(): bool
{
    return $this->partner_mode && $this->revealed_at === null;
}

    このあと出てくる「隠す・予想を止める・番の画面へ戻す・AI の窓口に見せない」は、どれもこの関数に聞きます。決まりを1か所にしておくと、見せ合ったあとに隠したままになる、といった食い違いが起きません。

  2. サーバー

    事件の画面を組み立てる：CaseBoardQuery が「いまの番」を決め、見立てを絞る

    事件を作ると、事件の画面 GET /cases/{case}（CaseController::show）へ転送されます。受付係は組み立てを Query（画面に出すものを読み集める係）に任せ、画面 cases.board（いまやることのカード1枚の形）に渡します。

    src/app/Http/Controllers/Cases/CaseController.php

    1. 隠す事件なら、住所の ?turn= が self のときだけ「自分の番」、それ以外（何もない・ほかの文字）はいつも「相棒の番」にします。先に相棒が書く決まりなので、事件を作った直後は相棒の番から始まります。
    2. 隠さない事件（相棒モードでない・見せ合った）なら、番はありません（null）。
    3. 番があるときは、見立てを「書いた人がいまの番の人」のものだけに絞ります（filter）。
    4. partnerName（相棒の呼び名）と selfName（設定の表示名）は、画面で「長男さんの番だよ」「父さんは見ないでね」と2人を呼ぶのに使います。
    たとえるとクイズ番組で、2人が別々のフリップに答えを書いて「せーの」で見せるのと同じです。ここではフリップの代わりにスマホそのものを手渡しし、画面に出すのは「いまスマホを持っている人」の分だけにします。データベースには両方の答えがあります。
    ここが大事番は住所の ?turn= で切り替えるだけなので、これは秘密を守るしくみではなく「先に相手の見立てを見てしまわないための目隠し」です。1つのアカウントを同じスマホで順番に使う前提（この章のはじめ）だから、これで足ります。他人の記録を見られないようにするしくみ（->can() と Policy）は別にあり、11章で説明します。

  5. サーバー

    RevealBoard::build：手がかりごとに、どちらがどの見立てで ○× を付けたか

    src/app/Queries/Cases/RevealBoard.php
    $partner = $case->hypotheses->filter->isByPartner()->values();
$self = $case->hypotheses->reject->isByPartner()->values();

$rows = [];
// 手がかりを1つずつ取り出し、両方の側の印を集めて比べる
foreach ($case->clues as $clue) {
    $p = $this->marks($partner, $clue->id);
    $s = $this->marks($self, $clue->id);
    $rows[] = [
        'clue' => $clue,
        'partner' => $p,
        'self' => $s,
        'differs' => (bool) $p['fits'] !== (bool) $s['fits'] || (bool) $p['contradicts'] !== (bool) $s['contradicts'],
    ];
}
    1. 見立てを「相棒が書いたもの」と「自分が書いたもの」に分けます。filter->isByPartner() は「isByPartner() が本当のものだけ残す」、reject->isByPartner() は「本当のものを外す」という Laravel の短い書き方です。
    2. 手がかりを1つずつ見て、それぞれの側で「この手がかりに ○（合う）を付けた見立ての番号」と「×（合わない）を付けた見立ての番号」を集めます（marks）。
    3. differs（違いがあるか）：片方は ○ を付けたのにもう片方は1つも付けていない、のように、○ があるか・× があるかが両方でそろっていないとき本当にします。(bool) は「空の一覧なら false、1つでもあれば true」に変える書き方です。
    src/app/Queries/Cases/RevealBoard.php
    /** 片方の側の見立てのうち、その手がかりに ○ を付けた番号と × を付けた番号を返す（番号は並びの1から） */
private function marks(Collection $hypotheses, int $clueId): array
{
    $marks = ['fits' => [], 'contradicts' => []];
    // 見立てを1つずつ取り出し、その手がかりへの印があれば番号を控える
    foreach ($hypotheses as $i => $hypothesis) {
        $fit = $this->fitOf($hypothesis, $clueId);
        // 印があれば、合う・合わないの側に番号を入れる
        if ($fit !== null) {
            $marks[$fit->value][] = $i + 1;
        }
    }

    return $marks;
}

    ○× の印（clue_hypothesis 表の fit。fits か contradicts）は、CaseBoardQuery が最初に hypotheses.fits として読み込んであるので、ここでデータベースへ取りに行くことはありません。2人がそれぞれの番で付けた ○ が、ここで初めて並びます。

    例（テスト test_reveal_lines_up_both_sides_and_marks_the_split_clue と同じ形）
    • 1つ目の手がかり：父も長男も、自分の見立てに ○ → differs は false
    • 2つ目の手がかり：長男だけ ○、父は印なし → differs は true（「見方が分かれたよ」が出る）
    たとえると2人の答案を横に並べて、問題ごとに「2人とも同じ所に丸を付けたか」を見比べる表です。ただし勝ち負けを決めるためではなく、「どの手がかりで見方が分かれたか」を話すきっかけにするための表です。

この章のまとめ
  1. 相棒は別のアカウントではなく、同じアカウント・同じスマホを渡し合って順番に書く人。相棒の見立ても持ち主（user_id）は親で、hypotheses.author が partner になるだけ。
  2. 相棒モードは、設定の users.partner_name がある人だけ。事件を作る1問目の「長男といっしょに考える？」で選び、入れると3問目の入力欄が CSS だけで説明に替わる。StoreCaseRequest が名前のない人の partner_mode を外し、CreateCase は相棒モードの最初の見立てを保存しない。
  3. 「隠すか」は CaseFile::hidesHypotheses()（partner_mode が本当で revealed_at が空）の1か所で決める。CaseBoardQuery が住所の ?turn= でいまの番を決め（相棒の番から始まる）、机の上のカードは渡し合い（case-partner.flow → turn）になる。もう片方の見立ての文は HTML にも入れない。
  4. 番ごとに「渡す付箋 →（:target で開く）書くカード → ○ を付けるカード → 渡す」。書くカードは隠し欄 author に番を入れ、AddHypothesis は相棒モードのときだけそれを残す。書いたあと・○× を付けたあとは、書いた人の番の画面へ戻す。
  5. 見せ合う前は、予想を画面でもサーバー（StorePredictionRequest::authorize）でも止め、AI に見せる文にも見立てを出さない。
  6. 「いっしょに見せ合おう！」（POST /cases/{case}/reveal）は revealed_at に日時を入れるだけ。すると RevealBoard が手がかりごとの ○× を2人分並べ、分かれた荷札に「見方が分かれたよ」を出す。カードはふつうのいまの一手に戻る。
