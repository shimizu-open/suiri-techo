# 画面の見た目と動き

元は `docs/design/basic-design.md` の 3・4 と `requirements.md` の 6（使いやすさ）。部品の見本と色の表は `docs/design/ui-kit.md`、部品の一覧の正本は `docs/design/components.md`。

使う人は、保護者と中高生の子ども（相棒）が**1台のスマホで一緒に**使う。ほかに少数の施術者。画面を開いたら「ああ、今はこれを書けばいいんだ」とすぐわかることを、見た目のいちばんの目的にする。

## 3つの原則

1. **いまやることは1画面に1つ**：その画面でいちばんすべきことを、いまやることのカード1枚（`<x-ui.step-card>`：問いの見出し・例・入力欄・主なボタン）で出す。済んだことは `<x-ui.done-summary>` で小さくたたむ。まだ先のことは出さない（「あとでできること」はカードの下に小さく1行）。あれもこれも入力欄を同時に並べない。スマホ 390×844 で、いまやることのカードと主なボタンが**最初の画面の中に**見えること。
2. **やわらかい話し言葉**：「〜しよう」「〜を教えて」「どのくらい自信ある？」のように話しかける。1文は短く（25字くらいまで）、例文を添える。設計書の言葉（手がかり・見立て・もしそうなら・確かさ・答え合わせ・屋根裏の棚・ノーベリ帳）は使ってよいが、**初めて出る所で一言の説明**を添える（「見立て＝『どうしてだろう？』の答えの案」。`<x-ui.hint>` の吹き出しで）。「〜を足す」「〜を記録」「〜の状態」「入力してください」のような事務的な言い方はしない。ボタンは動きの言葉（「これでOK」）、押したあとは「保存したよ」。エラーは何がまずくてどう直すかを書く。ダッシュ（――）のはさみ込み、「AではなくB」の言い回し、思わせぶりな言い方はしない。
3. **子どもと一緒に使える**：主なボタンは高さ 48px 以上で横いっぱい（`<x-ui.big-button>` は 56px）、押せるものはどれも 48px 以上。文字は本文 16px 以上。漢字の多い硬い熟語を減らす。ふだんの場面が親子の人には子ども向けの言葉を出す（下の「子ども向けの言葉を出す条件」）。

## 見た目：捜査の手帳（AI が作りがちな見た目から抜け出す）

- **避ける見た目**：「温かいクリーム色の背景＋明朝体の見出し＋赤茶の差し色」「何でも同じ角丸のカードで囲む」「カードの左に色の帯（アクセントのレール）」「絵文字を見出しの印にする」「何でも中央ぞろえ」。どれも AI が作ると似たり寄ったりになる形。引用の文の左の細い線（`border-l-2`）は引用の印なのでよいが、カードの左に太い色の帯は付けない。
- **題材の形を中身として使う**：段ごとの色のつまみ（捜査ファイルのタブ）、証拠品の荷札（手がかり1つ＝1枚の札。`<x-ui.evidence-tag>`）、答え合わせの「確かめた」の丸いはんこ（`<x-ui.stamp>`）、事件の番号（「事件 No.12」）、相棒の番の付箋（`<x-ui.handoff>`）。子どもが見て楽しいが、幼すぎない。
- **紙と灰色**：背景はうすい青みの紙（`paper`）、いまやることのカードと入力欄は白（`sheet`）、文字は紺のインク（`ink`）、差し色は深い赤（`accent`）。灰色（`muted`・`rule`・`mark`）はただの灰色にせず、すべて紺に寄せた灰色。
- **書体は端末の書体だけ**：本文も見出しも、子どもにも読みやすい UD 書体を先頭に `"BIZ UDPGothic", "Hiragino Sans", "Noto Sans JP", sans-serif`（`font-sans`）。見出しは同じ書体の太字。**明朝体（`font-mincho`）は事件のなぞの1か所だけ**。数字は桁がそろう形（`tabular-nums`。body に指定ずみ）。外部の書体・CDN は読み込まない（Vite の書体の道具 `laravel-vite-plugin/fonts` と `@fonts` も使わない。`bin/check` が止める）。
- **文字の大きさの段**：`text-xs` 13px・`text-sm` 15px・`text-base` 16px（本文）・`text-lg` 18px・`text-xl` 22px・`text-2xl` 28px。この段の外の大きさを作らない。補足の小さな文字も 13px より小さくしない。
- **段ごとの色と絵**で「いまどこにいるか」を見せる（色の名前は `@theme`、絵は `<x-ui.step-icon>` の手で描いた inline SVG。外の画像やアイコンの道具は使わない）：

  | 段 | tone・色の名前 | 絵 |
  |---|---|---|
  | 見たこと（手がかり） | `clue`・`clue-soft`（紺） | `eye`（目） |
  | どうして？（見立て） | `hypothesis`・`hypothesis-soft`（からし色） | `question`（はてな） |
  | もしそうなら（予想） | `prediction`・`prediction-soft`（深い緑） | `arrow`（矢印） |
  | 確かめる日 | `check`（色は `prediction` と同じ緑） | `calendar`（カレンダー） |
  | 答え合わせ | `answer`・`answer-soft`（深い赤） | `check`（チェック） |

  `-soft` はその段の淡い面。段の色で塗った面の上の文字は `on-ink`。進み具合は `<x-ui.progress>`（済み＝塗った丸、いま＝大きな枠、まだ＝うすい丸）と「ステップ 2 / 5」。
- **カードは役割のあるものだけ**：枠・塗り・角丸は「これは別のもの」という印。囲むのは、いまやることのカード（`step-card`。角丸 `rounded-step`）と、題材の形（荷札・はんこ・付箋）だけ。済んだこと・空のとき・一覧の1件は囲まず、細い線と余白で区切る。
- **状態は形でも見せる**：数字や文字だけでなく、つまみの色・荷札・はんこの線の形（二重の輪・点線）で、ひと目でわかるように。押せるものは押せる見た目にする。
- **空のとき**は、絵と一言と主なボタン1つ（`<x-ui.empty-state>`。「最初の事件を作ってみよう」）。
- **番号は本当に順番があるものだけ**に付ける（手順の段・事件の番号・荷札の番号はよい）。
- **平らな紙**：影・つや・グラデーション・浮き上がり（hover の translate・scale）・ずっと続く動き（spin・pulse など）は付けない（`bin/check` が止める）。区切りは細い線と余白で。角丸はやや大きめ、余白はたっぷり。
- **ダークモード（夜の書斎）**：濃い紺の背景（`paper` #0f1524・`sheet` #172036）に、少し青みの白い文字（`ink` #e7ebf4）。反転するだけにせず、段の色も夜に読める明るさで選び直してある（紺 → 明るい青 #a9c1ee、からし色 → #e6c065、緑 → #8fd1ad、赤 → #ef9aa1。`-soft` はそれぞれの色を混ぜた濃い面）。塗った面の上の文字 `on-ink` は昼は白・夜は濃い紺。切り替えは `app.css` の `@media (prefers-color-scheme: dark)` の中で `:root` の変数を入れ替えるだけ。部品に `dark:` を書かない（`bin/check` が止める）。昼も夜も、文字と背景の明るさの差（コントラスト比）は 4.5 以上（数値は `ui-kit.md`）。

## 見た目の書き方：Tailwind のクラスで書く

- 見た目は **Blade の中の Tailwind CSS v4 のクラス**で書く（`class="rounded-step bg-clue-soft px-5 py-4 text-lg text-clue"`）。
- `resources/css/app.css` に置くのは、`@theme` の色・書体・大きさの名前（`--color-clue` を足すと `bg-clue`・`text-clue`・`border-clue/40` が使える）、`:root` の昼と夜の色の値、`@layer base` の要素（`body`・`a`・`h1` など）の基本の見た目だけ。**独自のクラス（`@layer components` の `.tone-clue { … }` や、トップレベルの `.card { … }`）を足さない**（`bin/check` が止める）。Blade に `<style>` も書かない。
- 同じ組み合わせを何度も使うときは、CSS のクラスではなく **Blade の部品**にまとめる。段の種類ごとのクラスの組み合わせは、部品の中の PHP の配列で選ぶ（`['clue' => 'bg-clue-soft text-clue', 'hypothesis' => 'bg-hypothesis-soft text-hypothesis', …]`）。Tailwind はクラスの名前を文字のまま探すので、`"bg-{$tone}"` のように組み立てない。
- どうしても Tailwind のクラスで書けないもの（`:has()` を使う切り替えなど）は、`@custom-variant` か `@utility` で Tailwind の仕組みとして足す。
- 新しいクラスを使ったら `npm run build`（並行作業中は `flock /tmp/suiri-build.lock docker compose exec -T app npm run build`）。

## 置き方（各部品を置く理由を先に決める）

- 部品を置く前に「この画面で利用者が何をするか」と「その部品がそのために何をするか」を一言で決める。理由が言えない部品は置かない。
- 関係する情報は1つにまとめる。ばらばらの大きさの札を浮かせない。スクロールを無駄に増やさない。
- 文字と部品は左にそろえる（中央ぞろえは、空のときの絵などの限られた所だけ）。
- **スマホ（幅 390px）で片手で使える**。パソコン（1280px）でも崩れない。
- 骨組み：スマホは下に固定のナビ（今日・タスク・事件・手引き・ふりかえり。高さ 64px、絵 24px）、パソコンは左に縦のナビ。上の帯（高さ 48px）に画面の名前（事件の画面は「事件 No.12」）と右に設定。画面の名前は控えめにして、いまやることのカードを目立たせる。
- 今日の画面は上から：いまやることのカード1枚（答え合わせの日が来た予想があれば答え合わせ、なければ次の一歩）→ 今日の予定とタスク（時刻順）→ 今日の練習の提案 → 捜査中の事件（最近の3件）。
- 事件の画面は段ごとに1問ずつ：上に進み具合、済んだ段はたたんだ要約、いまの段のカード1枚。1件の記録は1分以内で書ける。一番軽い記録（手がかり1つと見立て1つ）で保存できる。
- 提案のチップ（`<x-case.suggest-chips>`：手がかりの問いかけ・別の説明の型・予想の穴埋め・確かめる日の候補）は、押すと入力欄に書き出しが入るだけ。保存は本人がする（AI なし。`docs/design/words.md` の「提案・書き出し」）。

## 子ども向けの言葉を出す条件（1つにそろえる）

- 子ども向けの言葉（まちがいノート・ぼくの図鑑・「かも」・見に行く日・どのくらい自信がある？・練習の `kid_description`・わざの `kid_name` など）は、**ふだんの場面（設定）が「親子」の人に出す**。判断は `User::prefersKidWords()` の1か所。受付・Query で `kid` を作って部品に `:kid` で渡す（部品の中で場面を見て決めない）。
- 事件ごとの場面（`$case->scene`）で子ども向けに切り替えない。事件の場面が変えるのは仕事の場面の出し分けだけ。
- 手引き（技能・演繹・帰納・アブダクション）は、何も選んでいなければ上の条件で決め、「大人向け・子ども向け」のボタン（`<x-guide.audience-toggle>`、`?kid=0`・`?kid=1`）で選んだ向きを先にする。
- 画面ごとの対応（手引きの入口のわざの名前・練習メニューの説明・名推理カードの「まずは声に出して言ってみよう」など）は `docs/design/words.md` の 2-2。新しく子ども向けの言葉を出すときは、そこと `.claude/rules/domain.md` に足す。

## 注意書きの部品

- 入力欄の下には、個人情報の注意書き `<x-ui.privacy-note>` を**常に**小さく出す（文は `config/legal.php` か `config/suiri.php` から。`rules/privacy.md`）。
- 仕事の場面の振り返りでは、入力欄の上にも施術者向けの注意（お客さまの記録には使えない）を出す。
- フッター：このアプリについて・プライバシーポリシー・利用規約、「医療機器ではありません」の一文。
- ワトソンのひとこと `<x-case-step.bubble>`（見た目は `<x-ui.hint>` の吹き出し）は一度に1つ、閉じられる。保存は止めない。

## 部品（Blade コンポーネント）

| 分類 | 置き場所 | 例 |
|---|---|---|
| 共通（作り直しの部品） | `components/ui/` | いまやることのカード `step-card`・進み具合 `progress`・主なボタン `big-button`・段の絵 `step-icon`・吹き出し `hint`・済んだことの要約 `done-summary`・空のとき `empty-state`・荷札 `evidence-tag`・はんこ `stamp`・渡す付箋 `handoff` |
| 共通（前からの部品） | `components/ui/` | `button`・`field`・`textarea`・`select`・`choices`・`badge`・`flash`・`privacy-note`・`confirm`・`icon` |
| 骨組み | `components/layouts/` | `app`・`guest`・`nav`・`footer` |
| 機能ごと | `components/{task,case,case-new,case-step,case-partner,today,guide,review,settings,auth,legal}/` | `case/suggest-chips`・`review/calibration-chart`（SVG・件数つき） |

- 作り直しの部品の役目・props・使い方の見本と、段ごとの色の表は **`docs/design/ui-kit.md`**。新しい画面はまずこの部品で組む。
- 部品の役目・受け取る値・使っている画面は `docs/design/components.md` に書き足す。部品は `@props` で受け取るものを宣言し、データを取りに行かない。部品は文言を持たず画面から受け取る（決まった言葉だけ `config('suiri.ui')`）。

## 動き（JS）

- `resources/js/app.js` は読み込むだけ。動きは `resources/js/parts/{部品}.js`（1ファイル 200 行まで）。
- JS がなくても送信できる形（ふつうのフォーム）を先に作り、JS は使いやすくするために足す。

## 確かめ方

画面を変えたら `docker compose exec -T app npm run build` し、headless Chrome でスクリーンショットを撮って**自分の目で**3つの原則を満たすか確かめる（スマホ 390×844 の最初の画面と全体・パソコン 1280・ダークモード）。撮り方：一時の Feature テストで `actingAs` して HTML を書き出し、`/build/` を `file://` にして headless Chrome で開く（書き出しは scratchpad、一時のテストは消す）。`public/build` は git に入れない。
