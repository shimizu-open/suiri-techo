# コードのコメント（手前に書く）

Baker Street English と同じ決まり。読み手はプログラミングの初心者。コードを読む前に、**すぐ上のコメントだけで「何をするか・どう分かれるか」が分かる**ようにする。エンジニアの基本の作法として、宣言と分岐の**手前**に必ず書く（行末の短いコメントだけで済ませない）。`bin/code_comments.py` が抜けを探し、`bin/check` が止める。

## 必ず書く所（すぐ上の行に）

| 所 | 書くこと | 形 |
|---|---|---|
| クラス（移行の `return new class` も） | 何の係か・主な仕事 | PHP / JS とも `/** … */` |
| 関数・メソッド（JS の `const f = () =>`・クラスやオブジェクトの `name() {` も） | 何をするか（「〜する」）。必要なら、受け取るもの・返すもの・いつ呼ばれるか・DB に書く等の副作用 | `/** … */`。すでにある `@param` `@return` の型は残す |
| `if`（早期 return の1行も） | 何を確かめるか、そのときどうするか。`else` / `elseif` があれば、それぞれの行き先も | `// …` |
| `foreach` `for` `while` `do` | 何を1つずつ取り出して、何をするか（いつ終わるか） | `// …` |
| `switch` `match` | 何で分けるか、主な行き先 | `// …` |
| `try` | 何を試すか、失敗（`catch`）したらどうするか（`finally` があればそれも） | `// …` |
| Blade の `@if` `@unless` `@foreach` `@forelse` `@for` `@while` `@switch` `@isset` `@auth` `@guest` | 何を確かめて何を出すか（`@else` の行き先も） | `{{-- … --}}` |

テストのメソッドは「何を確かめるテストか」を書く。

## 書き方

- 平易な日本語で、**何のためか**を書く。コードの言い換え（`// $i を1増やす`）にしない。1〜3行が目安。
- 例：
  ```php
  // Google が確認済みのメールでなければ、既存のアカウントには結びつけない（乗っ取りを防ぐ）。ログインの画面へ戻す
  if ($existing && ! $verified) {
  ```
  ```php
  // Google から利用者の情報を受け取る。キャンセルや時間切れで失敗したら、ログインの画面へ戻して知らせる
  try {
  ```
- その文（`if` など）の**行末にあったコメントは、手前のコメントに移す**（同じことを2回書かない）。ほかの行の行末コメントはそのまま残してよい。
- `else` `catch` の中が分かりにくいときは、ブロックの最初の行にも一言書く。
- コメントを足すとき、**コードは1文字も変えない**（空行とコメントだけ）。
